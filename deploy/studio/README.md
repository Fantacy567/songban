# 创作与管理服务本机启动

使用已有 Python 环境以及仓库依赖。`scripts/run_studio_platform.py` 启动统一应用，不新建用户、不发学习权益、不发布课程、不发送验证邮件或测试模型。真实账号、已有比赛与私密作品保留原数据库。

1. 将 `admin.example.json` 放到仓库外的受控目录，配置经用户确认的管理员邮箱和私密密钥目录；空名单拒绝所有管理访问。不要把供应商密钥填进该JSON。
2. 按实际运营条件准备学习配置。`learning.example.json` 不包含已审核同意文本、教研签署、关系审核人员或课程权益，不能冒充正式教学上线配置。已部署学习数据库必须沿用其有效的设置与同意版本。
3. 先执行 `python scripts/run_studio_platform.py --learning-config <绝对路径> --admin-config <绝对路径> --database <绝对数据库路径> --origin http://127.0.0.1:8894 --check`。检查不会打开数据库或发网络请求。
4. 启动去掉 `--check`，给已有数据库增加 `--backup-directory <仓库外已存在目录>`。要沿用QQ邮件及原模块配置，显式传 `--legacy-env <私密配置完整路径>`；此文件不会成为新工作台模型额度授权。
5. 管理员访问 `/server-admin`，用已有邮箱登录；邮箱未注册时先通过原站注册或绑定。只有服务器记录的验证邮箱在白名单中才获得管理入口。

后台文字配置供新 Harness 创作运行层读取。已保存密钥永不回显；额度0或停用阻止新调用，修改配置不重置累计调用。原比赛、旧邀请卡模型和既有图片服务保持原配置，不能把新后台描述为这些模块已经热切换。

目前豆包后台字段可保存准备信息，但启用被服务端拒绝，界面标注尚未接入当前图片运行层。原H期图片适配仍需要显式ImageSettings、图片用途授权及预算；不把后台配置变更绕过这些授权。

真正 AI 编程还需按[Harness部署](../harness/README.md)构建并验证隔离容器及模型回合。环境未具备时可保存想法、手工编辑、运行浏览器预览、恢复版本和归档，模型状态明确未就绪。课程草稿、示例和真实学习证据分别标明。

演示继续由 `scripts/run_demo.py --resume <原统一演示清单> --port 8895 --app-url http://127.0.0.1:8894 --creative-studio` 在唯一演示端口提供；示例账号不能进入服务端管理。临时QA服务应在检查结束后关闭。
