# 首版开发与验收报告

日期：2026-10-26；版本：0.2。范围以《需求文档》为准。

## 1. 结论

本地可运行的赛内协作首版已完成。使用真实后端、SQLite 和浏览器，走通了：创建团队 → 录入规则/讨论 → 编辑草案 → 队长确认 → 分配任务 → 阻塞/恢复 → 提交 → 跨成员退回/通过 → 依赖解锁 → 交付清单/复盘/导出。

**真实模型生成尚未通过。** DeepSeek 官方模型列表读取成功，返回 `DeepSeek-V4-Pro / deepseek-v4-pro`。一次真实生成失败；随后一次公开的短输入诊断确认服务商返回 HTTP 402 `insufficient_balance_error`。未重复重试，未用规则结果冒充模型结果。已将此情况改为明确的 503 `model_insufficient_balance` 提示，并完成对应回归。需要可用余额或其他有效密钥才能继续真实生成验收。

## 2. 实际执行的验证

- **26 项接口/数据库测试全部通过**，最近一次耗时 0.787 秒。实际覆盖正常与非法输入、引用/依赖/预算、身份隔离、跨成员验收、旧版本及并发冲突、持久化、模型协议和错误处理。
- **真实 TCP 与进程重启通过**：独立端口和临时数据库中创建、录入、生成、确认四项任务；停止专用进程，再启动读取，原文、任务和操作记录完全一致；无凭据请求返回 401。
- **完整浏览器流程通过**：系统 Chrome 中，两个相互独立的自动化成员会话共享同一项目；一次阻塞、一次退回、四项交叉验收、依赖解锁与 Markdown 下载均通过。无未处理 JavaScript 异常。
- **窄屏通过**：390px 页面没有主体横向溢出；原本在横向导航外的“模型接入”入口可点击，切换后保持可见。
- **模型设置协议联调通过**：页面输入明确的测试密钥，读取模拟 `/models`、选择完整 ID、清空输入框、生成协议模拟草案、分别保存请求/响应模型 ID、切回内置清除临时配置。此项采用 `httpx.MockTransport`，不是实际 DeepSeek 生成。
- **一致性备份通过**：SQLite backup API 备份运行中数据库，并执行 `PRAGMA integrity_check`。备份在本机 `data/backups/`，不包含在源码包中。

浏览器成员是测试会话，不代表胡或其他真实队友已经使用；本轮没有验证跨设备公网部署，也没有测量节时比例或模型建议质量。

## 4. 本轮发现并修复

1. **模型失败提示过于笼统**：实际确认上游余额不足后，单独处理 402；密钥/权限错误与限流也分别提示。不会回显服务商响应体、凭据或自动重试。
2. **移动端导航切换后回到起点**：页面重绘丢失横向位置，已调整为让当前入口保持在可见区域，用原操作复测通过。
3. **验收截图被保存提示遮挡**：等待提示消失再采集，更新后的复盘截图文字完整。
4. **浏览器测试等待停滞**：定位为测试驱动读取动作响应体的等待；改用 HTTP 状态、真实后端读取及渲染后的任务状态联合判断，完整流程通过。没有以重写业务代码掩盖该现象。
5. **流程文档分支表述**：模型成功与规则演练汇合节点改为“生成待确认草案并标注真实来源”，避免将模型路径写成规则模板。

## 7. 当前限制与下一步

- 首版确认后冻结范围；执行中的修正靠阻塞与退回。尚无整套计划重排。
- 刷新同步；尚无实时推送、录音转写、GitHub 自动验收、真实账号体系或代码托管。
- 独立入口是原型访问方式，队长应保存入口；公网部署还需要账号恢复、访问控制加固、滥用防护和 HTTPS。
- BYOK 仅本次服务内存有效；服务重启后需重新接入。只支持明确允许的 HTTPS、OpenAI 兼容 Chat Completions 与 JSON 输出服务，并非任意模型 API。
- 接下来应先用有可用额度的密钥完成一次真实草案生成与人工质量核对，再和胡做一次真人联调；不据本次测试宣称“最优分工”或“显著提效”。
