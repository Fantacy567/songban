# 给胡的接口交接卡

日期：2026-10-26；依据实际 `app/main.py` 与自动生成 OpenAPI。基础地址默认 `http://127.0.0.1:8886`。接口 JSON 字段使用英文；页面文案使用中文。

## 启动与约定

启动命令：`.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8886`，在项目根目录执行。依赖安装见 README。`127.0.0.1` 指运行浏览器的那台机器；胡在另一台电脑联调时必须使用可达的后端地址。

除创建项目和健康检查外，业务接口都带 `Authorization: Bearer <本成员access_token>`。后端返回的 `me.captain` 决定界面权限；后端再次验证，前端隐藏按钮不能替代权限检查。

下文 ID 与 `<token>` 都是占位符，必须从真实创建响应读取。`GET /api/openapi.json` 是完整可机器读取约定。

## 1. 健康检查

`GET /health`。成功示例：

```json
{"status":"ok","service":"hackathon-collab","version":"0.2.0","model_configured":false}
```

## 2. 创建项目与独立成员入口

`POST /api/projects`；无需凭据。首位成员为队长。时间必须带时区且在未来；姓名去空格后不可空白或重复，工时为正数，成员 2—8 人。

请求结构（请把截止时间改为测试当时的未来时间）：

```json
{
  "name":"协作模拟",
  "deadline":"2099-01-01T18:00:00+08:00",
  "members":[
    {"name":"我","role":"产品与后端","skills":"Python、AI辅助开发","available_hours":4},
    {"name":"胡","role":"前端","skills":"JavaScript、界面实现","available_hours":4}
  ]
}
```

成功 201：`{project_id, invites:[{member_id,name,captain,access_token}], notice}`。只为创建者返回各成员入口；数据库保存哈希，不提供读取原始口令的 GET 接口。浏览器入口格式是 `/#project=<id>&token=<token>`，页面接收后清除地址片段并只保存本成员会话。

失败 422 示例：

```json
{"error":{"code":"validation_error","message":"输入不符合要求，请检查标记字段。","details":[{"field":"body.name","reason":"String should have at least 1 character"}]}}
```

## 3. 读取共享工作区

`GET /api/projects/{pid}`。返回 `project, me, members, sources, proposals, tasks, events, model_configured, current_model`。

- `project.phase`：`preparing` / `executing` / `ready`。
- `proposals`：最近十份草案，另外保留已确认方案，含 `id, version, context_version, mode, source_label, content, stale, capacity_warnings, model_id, model_display_name, response_model_id`。
- `tasks`：正式任务，含 `id, task_key, owner_id, acceptance, estimated_hours, priority, due_at, depends_on, evidence, status, version, deliverable, block_reason, review_note, reviewed_by`。
- `depends_on` 在草案中是任务 key，在正式任务中是任务 id。前端不要混用。
- `events` 显示最近 200 条；完整历史会在导出中提供。

## 4. 保存原文

`POST /api/projects/{pid}/sources`。任何本项目成员可添加。请求：

```json
{"kind":"rules","title":"赛事规则原文","body":"需提交真实可运行演示与项目说明。"}
```

`kind` 仅 `rules` / `discussion`。成功 201 返回 `{id,project_id,kind,title,body,created_at}`。每项目最多 12 份、单份 2 万字、合计 6 万字。追加会改变 `context_version`，使旧草案失效。正式方案确认后返回 409 `plan_locked`。

## 5. 生成建议草案

`POST /api/projects/{pid}/proposals`，仅队长。请求 `{"mode":"local_rules"}` 或 `{"mode":"model"}`。

成功 201 返回草案；不创建正式任务。需要规则和讨论至少各一份。

- `local_rules`：真实执行本地规则和角色模板，来源明确为非大模型；可有工时警告，确认前必须修正。
- `model`：真实调用服务端配置的兼容模型；字段、来源、成员、工时和依赖必须通过校验。
- 未配置模型：503 `model_not_configured`；超时：504 `model_timeout`；上游失败或返回非法内容：502。资料会保留，不会静默返回规则方案。
- 若生成期间原文更新：409 `context_changed`。

## 6. 编辑草案与确认

`PUT /api/projects/{pid}/proposals/{did}`，仅队长。请求 `{"expected_version":1,"content":<完整Draft>}`。完整 Draft 结构可以直接使用生成结果的 `content`，修改后全量提交：

```json
{
  "goal":"完成一个可验收流程",
  "decisions":["先做核心链路"],
  "open_questions":["确认请求字段"],
  "risks":["预留联调时间"],
  "tasks":[{
    "key":"T1","title":"实现接口","owner_id":"<本项目member_id>",
    "acceptance":"成功与失败各实际发一次请求","estimated_hours":2,
    "priority":"must","due_at":"2099-01-01T17:00:00+08:00","depends_on":[],
    "evidence":[{"source_id":"<本项目source_id>","quote":"需提交真实可运行演示与项目说明。"}]
  }]
}
```

来源 quote 必须是原文连续片段。依赖不可未知、重复、自指或成环；至少一项必须任务。成功 200，草案 `version` 加一。保存不等于确认。

`POST /api/projects/{pid}/proposals/{did}/confirm`；请求 `{"expected_version":<当前version>}`。只有队长能确认；成功 200 返回 `{project_id,phase:"executing",tasks:[...]}`。工时超预算返回 422 `capacity_exceeded`，附各成员计划与可用工时。确认是原子事务，只能一次；确认后源资料与分工冻结。

## 7. 更新任务与验收

`POST /api/projects/{pid}/tasks/{tid}/actions`：

```json
{"expected_version":1,"action":"start","note":""}
```

成功 200：`{task:<更新后的任务>, phase:<项目阶段>}`。每次写入 `task.version` 加一，前端要用新值。

- `start`：负责人，`todo → in_progress`；前置任务必须已通过。
- `block`：负责人，`in_progress → blocked`；`note` 必填原因。
- `resume`：负责人，`blocked → in_progress`；依赖仍需通过。
- `submit`：负责人，`in_progress → review`；`note` 必填成果说明，写入 `deliverable`。
- `accept`：另一成员，`review → accepted`；`note` 可填验收说明。
- `return`：另一成员，`review → in_progress`；`note` 必填退回原因。

接口不会访问用户填的成果链接或执行其中内容。成果和引用以文本呈现。负责人不能自验，即使他是队长。

常见失败示例：

```json
{"error":{"code":"self_review_forbidden","message":"请由另一位成员验收，不能自行通过或退回。"}}
```

上例 HTTP 403。前置任务未通过返回 409 `dependencies_pending`；旧版本返回 409 `version_conflict`，附 `current_version`。前端刷新最新数据后请用户核对，不静默覆盖或自动重试写操作。

## 8. 交付核对、复盘与导出

- `GET /api/projects/{pid}/recap`：返回 `ready, phase, source_label, stats, checklist, suggestions, event_count, project_name, goal`。
- 只有至少一项必须任务且全部已通过才 `ready=true`，可选任务未完成不会阻止。提交但未验收不计完成。
- 统计使用数据库中真实任务、阻塞和退回记录；建议是本地规则，不是已调用模型的赛后分析。
- `GET /api/projects/{pid}/export`：同样需要凭据，返回 Markdown 附件，含原文、清单和完整过程记录。前端用带 Authorization 的 fetch 获取 Blob 后下载，不能仅拼普通无凭据链接。

## 9. 重发普通成员入口

`POST /api/projects/{pid}/members/{mid}/rotate-token`，仅队长，普通成员入口可重发。返回 `{member_id,name,access_token}`，旧口令立即失效。队长入口首版不能重发，请保存。

## 10. 最短联调路线

1. `GET /health` 确认可达。
2. 创建两人项目，分别保存队长与成员 token。
3. 队长或成员保存规则、讨论各一份。
4. 队长生成规则草案，修改、保存，再用最新版本确认。
5. 两个浏览器会话分别读取工作区；负责人开始和提交，另一成员通过。
6. 刷新工作区确认同步；查看复盘，重复使用旧任务版本，确认返回 409。

本地另起前端需设置明确的 `ALLOWED_ORIGINS` 并重启后端；部署的命令、环境变量、持久化、健康检查与回退见 README。本轮未做远端部署。

## 实现真伪边界

真实功能：HTTP 接口、数据库持久化、权限、来源校验、预算、依赖、版本冲突、状态机、跨成员验收、记录与导出。

规则替身：`local_rules` 是待人工修改的角色模板；复盘建议为本地统计规则。模型适配器已实现，协议测试使用明确的本地模拟响应。真实 DeepSeek 列表读取成功，生成因上游余额不足被拒绝，真实生成质量未通过。首版不提供真实账号、录音、GitHub 自动验收或最优分工保证。

## 11. 模型发现与选择（0.2 新增）

默认 DeepSeek-V4-Pro，完整 ID `deepseek-v4-pro`，服务端需配置 `DEEPSEEK_API_KEY`。

`current_model` 返回 `mode, model_id, name, provider, key_configured, version, name_source, custom_key_memory_only`，没有密钥。`version` 用于防止两窗口覆盖模型设置；重启后内存设置重置为内置和版本 0，项目/任务不变。

`POST /api/projects/{pid}/model/discover`，仅队长：

```json
{"base_url":"https://api.deepseek.com","api_key":"<仅在本地页面填写，别写入代码或文档>"}
```

服务端仅向允许的 HTTPS 地址请求 `/models`，不传团队原文。成功返回 `{discovery_id,models:[{id,name}],provider,expires_in_seconds:600,notice}`。名称与完整 ID 来自该密钥访问到的服务列表，不能从 key 猜测。未提供 name 时原样显示 id。无权限 403；地址不允许或密钥无效 422；上游列表失败 502 / 超时 504。失败不回显上游响应体或密钥。

`PUT /api/projects/{pid}/model`，仅队长。选择自带模型：

```json
{"mode":"custom","expected_version":0,"discovery_id":"<刚返回的票据>","model_id":"<列表中的完整ID>"}
```

成功返回更新后的 `current_model`。未知模型返回 422 `model_not_in_list`；列表过期/票据错误返回 409 `model_discovery_expired`；旧配置版本返回 409 `model_version_conflict`。密钥仅留服务内存，不进入数据库或浏览器 localStorage。

切回内置请求 `{"mode":"builtin","expected_version":<当前版本>}`，同时清除本项目的自带 key 和待选列表。密钥已配置只表示配置存在；生成调用仍可能因权限、额度或 JSON 模式不兼容而失败。

生成时上游余额不足返回 503 `model_insufficient_balance`；密钥/模型权限错误返回 503 `model_auth_failed`；限流返回 503 `model_rate_limited`。不返回上游原始响应体，不自动重试或创建假草案，已录入原文仍在。
