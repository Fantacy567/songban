# 松伴前后端宪法

日期：2026-10-27。这份文件约束当前产品「松伴」。胡方耀改前端，后端维持现有服务。两边以这份文件和已经上线的接口为准。微信聊天不能覆盖这里的条文。

## 0. 怎么交给胡方耀

写进 GitHub，不要只发微信。

微信消息会沉、不能对照改动、也不能在接口变了以后留下版本。胡接下来是对着仓库改页面，规范必须和代码放在一起。他打开的是这个文件：`docs/前后端宪法.md`，仓库 `https://github.com/Fantacy567/songban`，分支 `main`。

微信只负责通知。把第 11 节那段原样发给他，附上文件链接。不要在微信里贴代码大段、`.env`、AccessKey、模型密钥、微信密钥或数据库。

他打不开仓库时，先在 GitHub 把 `Fantacy567/songban` 的读取或协作权限给他，再发那段微信。权限给了之后，仍以仓库里的文件为准，不以聊天记录为准。

`docs/接口交接.md` 写的是上一版 `/api/projects`。做松伴时不要照那份文档。

## 1. 现在做的是哪一个产品

用户打开的首页 `/` 是松伴，文件是 `static/studio.html` 和 `static/studio.js`。接口前缀是 `/api/studio`。

下面这些不在这次交接里，没有另说就不要改：

- `/classic`、`static/index.html`、`static/app.js`
- `/workflow`、`static/workflow.html`
- `/api/projects` 以及 `docs/接口交接.md`、`docs/需求文档.md` 里描述的那一版协作助手

本地查看：在项目根目录执行 `.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8886`，浏览器打开 `http://127.0.0.1:8886/`。

## 2. 谁改哪些文件

胡方耀可以改：

- `static/studio.html`
- `static/studio.js`
- 若页面拆开，新文件只放在 `static/studio/` 下，并由 `studio.html` 引用

后端维护者改：

- `app/`
- `tests/`
- `scripts/`
- 数据库、短信、微信服务端、比赛资料抓取、密码和登录凭证

两边都不要提交 `.env`、`.venv/`、`data/*.sqlite3`。

胡不改接口的路径、状态码、字段含义和权限判断。页面需要一个新字段或新动作时，先提给后端，后端改接口和测试，他再接。他不在浏览器里伪造一个成功结果来绕过还没做的接口。

## 3. 身份

账号就是手机号。没有第二个「账号」输入框。

- 登录：手机号 + 密码。请求 `POST /api/studio/login`，正文用现有字段 `account` 填手机号，加上 `password`。
- 注册：手机号、短信验证码、密码、再输入一次密码。请求 `POST /api/studio/register`，正文只有 `phone`、`code`、`password`。不要再传 `username`。
- 验证码由 `POST /api/studio/codes` 发给后端。页面不显示短信里的数字。获取后提示等一分钟，对应 `429 code_wait`。
- 第一次注册，验证码通过后若返回 `422 profile_required`，留在注册页，补名字、画像、目前做得到的事，再提交同一次注册。不要为此另做「账号」。
- 已经注册过的手机号再走注册，只补密码，不覆盖原来的名字和技能。用接口返回的 `notice` 告诉用户。
- 密码至少 8 位、至多 64 位，两次输入必须一致。不一致时停在页面上，不要发请求。

登录成功后只把当前会话写入 `localStorage` 的 `studio-token`、`studio-squad`、`studio-contest`。继续调用 `localStorage.removeItem("studio-accounts")`。不要保存密码、验证码、别人的 token，也不要做「换一个人」的账号切换。

请求头是 `Authorization: Bearer <token>`。`401` 时回到登录页，并展示接口返回的 `error.message`。新登录会使旧 token 失效。

微信登录按钮不要加回来。服务端还留着未完成的微信票据接口，页面不要调用 `/api/studio/wechat/start`。

## 4. 接口怎么说话

页面文案用中文。JSON 字段名用英文，沿用后端已经返回的名字，不要在前端改名后再假定后端会跟着改。

失败时正文是：

```json
{"error":{"code":"bad_login","message":"手机号或密码不对。"}}
```

把 `message` 显示给用户。不要把失败画成成功，不要对写操作自动重试。`409` 表示当前数据已经变了或这一步不被允许，先重新 `GET` 再让用户看这句话。

常用读取：

- `GET /api/studio/me`：当前的人、比赛、队伍、好友。
- `GET /api/studio/squads/{id}`：这一支队伍的现场。进入队伍内页面时用它，不要靠浏览器里另存一份权威副本。

上传比赛文件用 `POST /api/studio/contests/import-file`，`multipart/form-data`，字段名 `file`，请求头只带 Bearer，不要再写 `Content-Type: application/json`。网关允许到约 2MB，更大会被拒绝。

完整路径以运行中的 `GET /api/openapi.json` 里 `/api/studio` 开头的条目为准。这份宪法不另抄一套会过期的字段表。

## 5. 页面不能改口的规则

前端可以按身份藏起按钮。藏起按钮不是权限。后端仍会拒绝。

- 队长才能改队伍名称、确认组队、确认题目、发布任务。判断来自接口里的队长标记，不能由页面自己写一个 `captain: true`。
- 用队伍码加入。不必先加好友。好友接口失败，不能挡住填队伍码。
- 加好友要对方已经用手机号注册。不能加自己。
- 投票只记录同意或先不改。投票不改题目、不改主干、不改任务板。页面要把这句话写出来。
- 资料库记下的内容不自动改题目或主干。
- 题目确认之后，不能在选题页直接改题。要改，走团队空间里的建议和表决，而且表决本身也不改题。
- GitHub、飞书按钮只是本机标记，没有真正打开或绑定。页面沿用接口 `notice`，不要写成已经授权成功。

## 6. 前端不许做的事

- 不在页面、脚本、localStorage 或 Git 里放短信密钥、模型密钥、微信密钥、数据库。
- 不从浏览器直接调用阿里云、DeepSeek、微信开放平台。这些只走自己的后端。
- 不在浏览器里抓取用户粘贴的比赛网址。只把网址或文件交给 `/api/studio/contests/...`。
- 不把用户粘贴的内容插进 HTML。沿用现有的转义。头像只显示接口给的地址；现有内容安全策略允许本站、`data:` 和微信头像域名。
- 不把松伴重写成另一套需要构建的前端，除非先改这份宪法并得到同意。现在没有构建步骤，保存静态文件后刷新即可。
- 不改 `/api/projects` 那一版页面来「顺便」做松伴。

## 7. 改界面时的规矩

- 改了 `studio.js` 或它拆出去的脚本，同时把 `studio.html` 里的 `studio.js?v=日期-序号` 往上加一，避免浏览器继续用旧脚本。
- 文案保持现在的口吻：短句，说明下一步，不写「账号」这个词来指用户名。登录叫手机号，注册叫用手机号注册。
- 空状态、验证码错误、密码不一致、队伍码错误、不是队长，都要能看见接口或页面给出的那句中文，不能只在控制台里。
- 胡的分支用 `hu/简短说明`。不要用 `cursor/` 开头，那是自动化代理的分支。改完开 Pull Request 到 `main`，说明改了哪一页、怎么点出来的。
- 后端接口一旦要变，由后端的改动先合并，并改 `tests/test_studio.py`。前端不放宽这些测试来迁就页面。

## 8. 他开始前做这几件事

1. 打开本文件和 `static/studio.js` 里的 `viewLogin`、`viewSignup`。
2. 按第 1 节启动服务，用手机号走一遍登录页和注册页。注册页应只有手机号、验证码、密码、再输入一次密码。
3. 确认自己能提交 `hu/` 分支。不能就先说，不要把补丁发到微信。
