# 松伴核心协作 · 前后端与插件交接

本轮只做个人智能体 ↔ 团队空间 ↔ 总智能体。默认首页为 static/core.html，其他旧页面和业务接口返回423 feature_locked，不删除资料。沿用手机号登录。

## 启动

`.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8886`

公网使用时应由部署者配置HTTPS地址；另一台电脑不能使用这台电脑的127.0.0.1。健康检查 GET /health，应返回 core_only:true、version:0.8.0。

## 身份

网页通过 POST /api/studio/login（account、password）取得Bearer登录凭证。注册/验证码沿用现有接口。GET /api/core/me 读取本人和已加入团队。

插件连接凭证由网页 POST /api/core/teams/{sid}/connections 创建，输入label，返回token（仅一次）、id和expires_at。绑定本人和单支团队，30天到期，不提供发布或改方向权限。后续同样使用Authorization: Bearer，但必须是sbconn_开头的插件凭证，而非账号密码/模型密钥。

## 完整链路

1. POST /api/core/teams，输入name；返回id、code。队友 POST /api/core/join，输入code。
2. PUT /api/core/teams/{sid}/direction，队长保存goal、rules、rubric、non_goals、deadline和expected_revision。deadline可空，非空须带时区。
3. PUT /api/core/teams/{sid}/profile，成员保存strengths、willingness、hours（0–168）。不是按年龄评分。
4. GET /api/core/plugin.zip 下载无凭证的通用包，按包内README配置MCP/命令行/文件监听。
5. POST /api/core/teams/{sid}/reports 同步本人进展。具体示例见插件update.example.json。文件监听也会每5秒将共同方向和本人任务取回 .songban/team-state.json。身份由凭证确定，不接受user_id。status只支持discussion、in_progress、blocked、reported_done。task_key及plan_version可用于更新本人当前任务状态。excerpt是本人授权摘录，evidence只是待核对依据，不表示已独立验证。
6. GET /api/core/teams/{sid}：网页现场；GET .../context：插件读取团队方向、正式安排、最近进展和不同观点；GET .../my-tasks：本人正式任务与共同方向。
7. PUT .../automation，队长设置enabled:true，可在新进展后自动调用总模型并合并短时间更新。默认关闭，避免未经明确开启持续产生费用。POST .../review 手动统筹，同版本未确认草案优先复用。
8. POST .../proposals/{pid}/confirm，输入expected_revision。只允许队长网页登录凭证，禁止插件发布。来源/成员/任务依赖均先校验；输入变化或已存在更新草案返回409，不能覆盖。
9. GET .../my-tasks 取回新版本；后续报告附任务编号与版本。GET .../history 保留已确认版本。
10. PATCH .../connections/{cid}，action=pause/resume/revoke。撤销不能恢复。

## 错误

失败结构沿用 `{error:{code,message}}`，页面显示message。401重新登录/连接；403无权限；409资料版本或事件ID内容冲突；422输入不合法；429过快；503模型或网络不可用。写操作不要盲目重试。同步重试保持同一event_id和完全相同内容；新进展使用新ID。

## 总模型

优先使用服务端 TEAM_MODEL_API_KEY / TEAM_MODEL_BASE_URL / TEAM_MODEL_NAME；否则沿用现有内置模型配置。只调用受允许的HTTPS服务，不读取成员个人工具密钥，不继承个人订阅额度。团队资料作为待分析数据传入，不作为系统命令。

服务器检查JSON格式、成员、来源ID、依赖环和资料版本。这些检查只能防一部分错误，不能保证模型对事实和取舍的理解正确。工作台保留个人自报、不同观点和待核实标记。

## 范围与诚实说明

- 通用的是MCP服务和命令行，不是所有工具内部会话格式。每款客户端仍须实际安装验收。
- 共享文件监听只读取当前项目用户授权的文件。个人工具需要实际调用MCP，或写出共享文件；没有发生时不能宣称已同步。
- 本人进展每分钟最多30条。断网持久队列按连接隔离；永久拒绝移到rejected目录，不阻塞后续新进展。
- 网页每5秒刷新；总模型短暂合并重要变化后生成草案，失败可见，无无限重试。
- 最近80条报告用于当前统筹；历史仍保留。单次内容过长会拒绝而非偷偷截断。
- 多个AI可能一起出错。当前不自动运行队员代码，不独立证明报告真实。

## 回退

先备份SQLite，再更新服务。保留现有用户资料与旧代码。需要临时回退界面时，以 SONGBAN_CORE_ONLY=0 启动；不得在用户不知情时恢复旧功能。已有核心记录不会因此删除。完整恢复需停本项目服务后从备份还原数据库，避免带WAL文件的运行库直接覆盖。

## 本机一键安装（2026-10-28追加）

GET /api/core/install-options：网页登录后返回available、本机默认项目目录、可选工具。远程访问不返回服务器路径，不允许远程安装。

POST /api/core/teams/{sid}/install：输入tool（codex/workbuddy/cursor）、project_dir（已存在的具体项目目录）、consent:true。要求网页登录凭证、当前团队成员、本机来源且同源；不接受插件凭证。生成个人连接并安装后实际运行MCP取回任务验证；成功返回installed、bridge_verified、client_loaded:false及配置/备份位置，不回显凭证。失败回退并撤销新凭证。

只合并项目内MCP配置。Codex .codex/config.toml 的模型/供应商和其他设置必须保持；WorkBuddy/Cursor保留原mcpServers。拒绝配置软链接逃逸、同名陌生连接和另一成员的个人绑定。配置无效时不覆盖。全局~/.codex/config.toml完全不触碰。
