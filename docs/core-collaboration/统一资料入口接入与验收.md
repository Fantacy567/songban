# 统一资料入口：接口、运行与验收

日期：2026-10-31。分支：`feat/material-intake`。开发基线：`6d146fc6fee5e15437c6b0d8df192e83fa267ff2`。本文件所属提交即实现版本；最终提交号同时在交付消息中提供。界面沿用 `design-v1.1.0`，没有新增颜色 token。

## 范围与入口

`#/event` 原规则框和固定三栏已改为统一资料入口，默认读取登录者的个人空间。未登录输入只留当前页面内存，登录可继续；刷新前有明确丢失提示。`#/materials` 是实践中的团队资料入口。共享时明确展示目标团队、选中条目和将共享的完整原件；未引用的其他个人材料不会迁移。已有 `#/library` 记录和接口保持原样。

个人空间和团队空间分别保留资料。共享是经用户确认的副本：团队内继续补充读取的是同一团队空间；撤回个人副本不自动撤销已经分享的团队副本。需要撤回团队依据，应在团队资料入口撤回对应材料。撤回使相关结果待更新；原件与修订历史仍保留。当前没有自动清理或物理删除策略。

新模块：`app/materials.py`、`app/materials_parse.py`、`static/songban-materials.js`、`static/songban-materials.css`。主程序只增加注册、独立注入参数和资料上传大小限额；前台主脚本只增加入口、路由、身份清理和防止团队轮询覆盖资料编辑。保持无构建步骤。

## 输入、解析与容量

- 自由文字、聊天、PNG/JPEG 粘贴/上传/拖放、PDF、DOCX、TXT、公开 HTML/纯文本网页可以混合加入。一次选择多个文件，逐份接收与读取。
- 单文件 8,000,000 字节；图片最多 2000 万像素，识别前按比例缩至最多 2400 像素边长。PDF 最多 20 页。
- 单份读取文字最多 40,000 字，超限整份报错，不截断后称成功。每空间最多 40 份、50,000,000 字节（包含撤回原件），单次模型输入正文最多 80,000 字。网页响应还受既有公网请求器 2.8 MB 限制。
- 图片使用 RapidOCR/ONNX 本地中英文识别，无 OCR 云密钥。PDF 先逐页提取文字，无文字页由 PDFium 渲染后 OCR；部分页失败保留已读页并逐页说明。OCR 文字始终需要核对。
- DOCX 提取正文段落与简单表格。内嵌图片、复杂版式、批注和文本框不承诺完整读取；检测到图片明确提示另行上传。音视频、压缩包等会保存原件并报告不支持。
- TXT 支持 UTF-8 BOM、带 BOM 的 UTF-16 和 GB18030。长文本或页面拆成最多约 1500 字的定位片段，保留页码/段落/片段位置。
- URL 获取复用 `contest_intel.validate_public_url`、`public_request` 的公网 IP 检查、DNS 固定和逐跳重定向验证。不开启代理环境、不允许本机/内网，不绕过失败的 TLS 校验。静态网页正文不代表登录墙或动态内容已读取。失败保留原 URL；成功保留获取到的网页原件与原 URL 元数据。

## API v1

所有接口为 `/api/materials`，沿用 `Authorization: Bearer <网页登录凭证>`。不接受个人工具连接凭证，不继承学习演示会话身份。未登录返回 401，跨个人/团队访问返回 403。路径中的 space 应 URL 编码。

- `GET /space`：取得/初始化个人空间；`GET /space?team_id=...` 取得/初始化当前成员可访问的团队空间。
- `GET /spaces/{space}`：返回 revision、sources、result、result_revision、stale、最近 20 个批次、30 个草稿和 50 个修订记录；更早记录仍在数据库中。结果中的类别来自实际模型输出，没有固定栏目。
- `POST /spaces/{space}/sources`：接收 `{request_id, kind, name, content, author?, occurred_at?, nature?}`。kind 为 text/url/file，file 的 content 为标准 Base64。nature 为 unverified/sample/self_report/organizer_notice。author 默认未知；上传者不是原作者。返回 source 与 reused。收到不等于读取成功。
- `POST /spaces/{space}/sources/{id}/parse`：正文 `{expected_revision}`。读取或显式重试，返回该材料状态和已定位片段。已成功读取的材料直接复用。读取过程先持久化 reading；完成时再校验材料版本，不能恢复已经撤回的材料。
- `GET /spaces/{space}/sources/{id}/original`：鉴权后作为 attachment 下载原件，不在本站执行 HTML。
- `POST /spaces/{space}/sources/{id}/withdraw`：正文 `{expected_revision}`，撤回材料并使相关结果失效。
- `POST /spaces/{space}/generate`：正文 `{request_id, expected_revision}`。仅发送当前空间 ready/partial 的材料；批次保存材料 ID/版本、未纳入项和部分读取提示。成功后返回 `{id,status:"completed",output,reused}`。
- `PATCH /spaces/{space}/items/{id}`：正文 `{expected_revision,text,verification,note}`。verification 为 unverified/human_confirmed/deferred；保留引用、修改前后内容、操作者与时间，并对条目开启人工保护。
- `POST /spaces/{space}/drafts`：正文 `{request_id,expected_revision,team_id,item_ids,kind,share_sources:true}`，kind 为 direction/tasks。仅复制选中条目引用的完整材料到目标团队。团队材料不能复制到另一个团队。草稿最多 2500 字，以符合现有讨论入口限制。
- `POST /spaces/{space}/drafts/{id}/prepare`：正文 `{expected_revision}`，在继续使用草稿前重新校验团队成员和引用材料版本；撤回或版本变化返回 409。

输入由 Pydantic 严格校验，未知字段不被默默采用。JSON 错误沿用 `{error:{code,message,details?}}`。422 表示不合规输入或暂无可读取材料；413 表示容量限制；409 表示版本变化或请求标识复用错误；429 表示模型繁忙；模型未配置/权限/余额等返回明确 503，超时 504，输出无效 502。解析失败本身是材料的持久化 failed 状态，HTTP 200 回传该状态，页面不会当作读取成功。

## 模型与引用

生产模型沿用 `team_model_config()` 与 `check_model_base()`；不复制旧目录配置，不将密钥提供给前端。`create_app(..., materials_model_runner=...)` 是专用测试注入，只影响资料整理；输出和界面明确标注“协议测试替身”。没有模型时不使用规则提取冒充 AI。

模型收到当前范围的正文、性质、作者、有限的旧条目和团队成员白名单。材料不作为系统指令，模型没有工具。来源只在模型请求中使用 S1/S2 等短别名，返回后精确映射回持久化 ID；不进行模糊匹配。statement 必须有引用，所有引用都必须是所选片段的连续原文；成员必须存在于当前团队。服务端补上来源版本、性质、位置、字符偏移。网页/模型文字在前台转义显示。

结果区分材料表述、AI 建议和待确认；重要程度与核实状态分别呈现。冲突按模型返回的关联组并列保留。重复原文上传按元数据和内容指纹复用；完全相同的事实文字归并引用，同义合并依赖模型。不能据此保证模型发现了所有冲突或所有重复事实，用户仍可纠正并核对变化。

## 版本、幂等与正式安排

所有材料变动推进空间 revision。生成先在事务中记录输入版本，释放锁调用模型，再以同一版本提交。期间新增、撤回、人工修改或其他成员更新均让迟到结果返回 409，并保留上一版有效结果。

人工修正永不被新模型文字覆盖。新证据改变保护条目的引用或模型不再列出该条目时，保留人工文字并标记 needs_review；先人工复核再导出。界面显示新增、重复、不再出现、受保护内容及冲突。

上传与生成持久化 request_id。相同请求返回既有记录，不重复模型调用；不同内容复用同一 ID 返回 409。已完成读取不重复运行。客户端在网络回执不确定时保留请求 ID；明确失败后的手动重试使用新请求 ID，不自动重试写操作。进程中断的 running 批次会保留状态，用户可以明确发起新批次，系统不会虚构完成。

方向草稿带入原方向编辑页，由原权限和 expected_revision 保存。行动草稿作为 `status=discussion` 进入原团队报告接口，保留草稿标识；仍需生成统筹草案、队长确认才成为正式任务。该模块不写正式方向/任务表，既有队长权限保持有效。个人和团队的同一分享草稿共用 canonical_id，防止同一用户重复送入讨论。

## 数据库与部署准备

新增 `materials_spaces`、`materials_sources`、`materials_requests`、`materials_batches`、`materials_history`、`materials_drafts`，全部 `CREATE TABLE IF NOT EXISTS`。原件存 SQLite BLOB，数据随原应用备份；不放静态目录。无旧表字段迁移，也不删除旧资料。恢复旧代码时新增表可保留，但生产部署前仍应按既有流程备份数据库。
