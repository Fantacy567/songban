# 分工问答与内部AI任务发布

2026-10-31；视觉design-v1.4.0，静态资源20261031-division-v1。

## 用户流程

保存共同方向→每位队员完成分工问答→各自核对确认→最后一位确认后内部AI发布任务→个人页领取并开始→上传成果→同伴检查→提交核对→本人复盘与家长报告。

方向仍由队伍讨论并由队长保存。职责由本人确认，发布由内部AI执行；不再要求队长点击发布。新队伍采用新流程，旧计划、成果及历史确认人保留，不清空真实用户数据。

## 页面收敛

- 主导航为选题、方向、分工、任务、提交、复盘，按前置状态开放；直接访问受相同门槛限制。
- 任务页保留个人／团队两个视图。个人页只有具体任务、成果、本人进度；团队页显示姓名、进度和当前工作，保留同伴检查入口。
- 队伍码、成员设置、连接器、赛事原件和独立的选题／开发资料库改为折叠入口；任务页的新发现上传也折叠。
- 移除旧团队现场的统筹／队长发布面板，移除旧后台自动草案开关。旧API和数据保留兼容，进入新分工轮次后停用旧自动草案及手动发布。

## 分工与发布事实

目前问答由服务端根据真实个人资料和上一题回答选择问题模板，并非每题都调用大模型。设计、开发、路演等背景的首题不同；随后问清独立能力与边界、实际可投入小时、具体交付物与检查方法。每次只显示一题，逐题写入SQLite，可离开后继续。本人核对后确认，前端不能替其他成员确认。

全员确认后才调用团队大模型，输入包含共同方向、成员能力／意愿／时间、已确认问答及带来源的资料。结果必须通过现有任务结构、真实负责人、引用、无循环依赖等校验；有时间参与的每位成员都需有任务，不给0小时成员分配任务。通过后复用同一个active_plan与计划历史写入，发布人为internal-ai:member-confirmed，不建立第二套任务系统。

并发确认只触发一次发布；版本变化、成员变化或结果不合法时不发布。失败保留问答与确认，需要明确重试；运行超时显示结果未知，不自动重复付费调用，每轮最多5次。改变方向启动新轮，旧问答和历史保留。

## 接口

同一认证、成员隔离和SQLite事务：

- GET /api/core/teams/{sid}/division：本人当前问题、已保存回答和团队确认进度。
- POST .../division/answers：round_id、step、answer，按当前题号检查冲突。
- POST .../division/confirm：本人完成4题后明确确认；最后一位触发内部发布。
- POST .../division/reset：生成和发布前可重填本人回答。
- POST .../division/publish：成员可明确重试，不需要队长身份。

方向保存返回next=division。快照增加division_status和division_round_id，next_action指向分工。进入新流程后旧proposals/{id}/confirm返回409；没有分工轮次的历史流程保留兼容。
