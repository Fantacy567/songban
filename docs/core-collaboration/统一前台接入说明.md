# 统一黑客松前台与双登录

日期：2026-10-30。源码基线：`cee3dc3`。设计版本：`design-v1.1.0`。本轮用户确认采用链接中的黑客松体验，连接现有团队后端，同时保留密码与短信验证码两种登录方式。

## 范围与实现

根入口与 `/learning` 共用静态前台。品牌首页和活动页参考用户提供的公开站点；小松树使用 CSS 绘制，创作卡片为明确标注的方向示意。没有拷贝第三方照片或引入新的构建依赖。

一级导航为活动／实践。实践承载真实小队、方向、任务、个人工具、资料库、成员、交付和复盘。`songban-views.js` 复用并适配原 `core.js` 的工作流展示，`songban.js` 负责账号、路由、统一框架、活动与团队入口。正式任务仍由服务端统筹草案经队长确认产生；报告完成后仍需其他成员检查。

活动来自现有 `/api/learning/v1/events`，是虚构样例，不是新接入的赛事数据源。活动规则在进入团队时作为方向草稿，用户点击保存后才写入团队。复盘作为真实本人进展保存；页面不把检查记录解释为主办方收件或能力评价。

这次没有实现家长／孩子学习域、支付、真实活动推荐、自动报名或代提交。原学习演示 API 和数据保留，但不作为真实团队身份或任务来源。

## 双登录契约

密码方式保持 `POST /api/studio/login`，请求 `{account: 手机号, password}`。新增 `POST /api/studio/login-code`，请求 `{phone, code}`。两个接口均返回原有登录结构，包括 `user_id`、`token`、`name`，并对同一 `people` 账号更新登录凭证。验证码登录不修改密码、个人资料或团队成员关系；成功登录使该账号的旧网页登录凭证失效。

验证码继续通过 `/api/studio/codes` 发送，沿用现有十分钟有效期、五次错误后销毁、正式短信发送约束。验证码登录还使用现有账号／来源限流，失败尝试持久化；成功后消费验证码，禁止重复使用。仅验证通过但尚未注册的手机号返回 `422 registration_required`，保留该验证码供显式注册表单使用，不静默创建用户或重设已有密码。注册仍要求设置密码与填写本人资料。

前端展示发送中与重发倒计时；服务未配置明确报错。仅隔离的开发测试环境可以显示测试码，正式发送成功不回显数字。两种登录方式在同一个可键盘操作的弹窗切换，敏感表单不写入草稿存储。

## 状态与恢复

团队写操作等待服务端回执后才显示成功。读写失败保留当前表单；版本冲突提供读取最新数据的操作，并在当前页面会话内恢复未保存的输入，要求用户核对后再保存。未保存草稿只留内存，刷新页面后应从服务端恢复已保存事实。定时刷新遇到输入或弹窗时不覆盖页面。

账号或团队切换时清理私有页面状态，迟到响应通过身份版本检查拒绝进入新页面。跨标签页登录状态通过 storage 事件更新，事件处理不反写凭证。个人工具连接凭证与网页登录凭证仍分开；本轮没有替用户执行工具安装或调用付费模型。

## 本地启动与验证

Python 依赖沿用仓库锁文件。普通启动：

```sh
python -m uvicorn app.main:app --host 127.0.0.1 --port 8886
```

相关后端回归（83 项）：

```sh
# PowerShell 先设置 $env:SONGBAN_CORE_ONLY='0'；POSIX 使用下方前缀。
SONGBAN_CORE_ONLY=0 python -m unittest tests.test_dual_login tests.test_core_workflow tests.test_team_core tests.test_learning_shell tests.test_studio -q
```

浏览器验证需要 Playwright 与可用 Chromium/Edge。启动独立测试服务，再运行检查：

```sh
python scripts/qa_unified_server.py
node scripts/e2e_unified.cjs
```

测试服务仅监听 `127.0.0.1:8892`，使用 `.browser-cache/` 下的独立 SQLite、模拟短信和显式模型 fixture，不调用真实服务。脚本可用 `PLAYWRIGHT_EXECUTABLE_PATH` 指定浏览器，`NODE_PATH` 指向现有 Playwright 安装；截图默认保存在 `.browser-cache/unified/`。

已验证：真实 HTTP/SQLite 的注册、验证码登录、密码登录、同账号团队恢复、两成员加入、保存方向、fixture 统筹、队长确认、提交进展、同伴检查、刷新恢复。另检查 390／768／1440 三种宽度下 10 个路由不横向溢出，以及版本冲突保留输入。无浏览器未捕获运行错误。短信／模型为测试替身；这些结果不证明真实短信送达或模型建议质量。

## 迁移与回退

无数据库结构变更。旧团队和账号继续使用，新增接口为兼容扩展。旧核心工作台保留 `/core`，旧 `core.*` 文件未被替换；`SONGBAN_CORE_ONLY=0` 保持原 studio 兼容行为。回退应用代码前仍按原部署流程备份数据库。

本轮实现通过仓库分支交付，尚未部署到公网，参考 Sites 站点也未被修改。真实短信、模型及公网后端域名须在部署环境配置并分别验收。
