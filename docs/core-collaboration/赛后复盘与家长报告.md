# 赛后复盘与家长报告

2026-10-31。入口为统一前台 `#/review`，沿用松伴视觉契约与真实身份。

## 用户流程

1. 孩子自己填写本场感悟、自己的想法与比赛结果。未公布结果时如实填写未知。仅本人可读取和更新，保存到 SQLite，不自动发到团队。
2. 明确点击生成报告，调用平台配置的模型。输入为已保存感悟、结果自述、本人的获准共享工作记录、当前本人分工和对本人成果的同伴检查。不读取队友的私有记录。
3. 报告包含概况、本场观察、下一次行动与资料限制。观察必须引用实际输入来源ID；分配任务不等于完成，AI回复不等于本人能力。比赛结果单列为本人填写、未经主办方核实。
4. 孩子预览并勾选分享确认后生成家长二维码。二维码只打开整理后的只读报告，不开放原始聊天、凭证、队友原文或编辑入口。链接持有人均可查看，非家长身份认证；30天有效，可撤销。重新生成二维码使旧码失效。
5. 感悟或工作记录更新后必须生成新报告才能重新发布。已经分享的版本保持为历史快照，孩子可自行撤销。

## 状态与写入

- `recap_reflections` 按团队和本人唯一，版本检查防止覆盖他处修改。
- `recap_reports` 保存生成请求、输入指纹、来源说明、状态和模型标记。生成请求幂等，失败/中断不自动付费重放；每人每小时最多5次新请求。超过10万字上下文拒绝，不截断冒充完整读取。
- `recap_shares` 记录随机不可猜链接、30天期限和撤销状态。响应禁止缓存、索引及来源转发。
- 与现有任务、交付、资料库使用同一SQLite；报告不修改任务、名次或正式交付事实。
- 模型仅给有保留的本场解读，不做人格诊断、天赋结论或个人能力认证。没有资料时说明未知。

## 接口

- GET/PUT `/api/core/teams/{sid}/recap`：本人复盘和本人报告历史；更新需expected_version。
- POST `/api/core/teams/{sid}/recap/reports`：明确新请求生成，需request_id及expected_version。
- POST/DELETE `/api/core/teams/{sid}/recap/reports/{id}/share`：本人确认分享或撤销。
- GET `/family/reports/{token}`：持码只读报告。
- GET `/family/reports/{token}/qr.svg`：本地qrcode生成，无第三方二维码服务。

## 部署与模型

分享地址使用管理员配置的PUBLIC_BASE_URL，不采用客户端Host/转发头。本机loopback地址不允许伪装成手机可访问二维码。局域网地址要求手机同Wi-Fi；跨网络访问仍需固定公网部署。

本机服务商需使用已配置网络代理，报告适配器遵循HTTP代理环境。平台模型由服务端结算，失败保留感悟；本轮没有实现订阅扣额或在线支付。
