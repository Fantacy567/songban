# 阿里云短信配置与验收

本项目支持号码认证服务（PNVS，默认）和经典企业短信服务。配置存在不等于实际送达；需要用本人授权号码实测。

## 已完成的仓库配置

2026-10-31 已在 `Fantacy567/songban` Repository Secrets 配置以下名称，密钥值没有进入源码：

- `ALIYUN_ACCESS_KEY_ID`
- `ALIYUN_ACCESS_KEY_SECRET`
- `ALIYUN_SMS_SIGN_NAME`
- `ALIYUN_SMS_TEMPLATE_CODE`
- `ALIYUN_SMS_MODE`（当前 pnvs）
- `SONGBAI_REQUIRE_SMS`（1）
- `SONGBAI_ALLOW_TEST_CODES`（0）

GitHub Secrets 仅供明确引用它们的 Actions 使用，不会自动注入外部服务器。部署时应在真实应用进程的私密环境变量中配置同样的值，再重启应用；不要把 `.env` 上传或作为 Actions artifact 下载。

PNVS 必须使用号码认证控制台赠送的签名与模板；企业模板不能混用。正式服务禁止开启网页测试码或 Mac 信息转发模式。

## 本机运行仍提示未配置

GitHub 中配置成功不等于本机已配置。[Actions Secrets 只在相应工作流中使用](https://docs.github.com/en/code-security/reference/secret-security/secret-types)，普通 `git clone`、`git pull` 和启动 Python 都不会把这些值带入本机。

在当前克隆目录运行配置向导（Windows）：

```powershell
.\.venv\Scripts\python.exe scripts/apply_aliyun_access_key.py
.\.venv\Scripts\python.exe scripts/check_sms_config.py --check-identity
```

向导要求填写 AccessKey ID、AccessKey Secret、短信签名名称和模板 CODE，默认 `pnvs`；企业短信使用 `--mode enterprise`。AccessKey 不回显，全部填完才写入私密 `.env`，不要求文件预先存在。已有模型、数据库等设置保留，网页测试码和 Mac 转发关闭。不要将凭据粘贴到聊天、源码或命令行参数中。

应用和检查脚本使用同一套 UTF-8（兼容 BOM）读取规则，默认读取当前仓库根目录 `.env`，不依赖命令执行目录。检查脚本的 `--env-file` 可检查另一个明确指定的私密文件，但不会替应用导入它。正常服务仍应使用其自身仓库的 `.env` 或进程环境变量。

保存后重启当前服务，保留原启动端口和数据库路径，再检查 `/api/studio/sms-status` 的 `configured`。仅配置检查或 STS 身份校验成功仍不代表送达；最后由本人在网页请求验证码、收信并完成登录。缺少真实参数时，服务继续返回未配置，不用网页测试码代替手机号所有权验证。

## 不发送短信的检查

本机私密配置检查：

```sh
python scripts/check_sms_config.py --env-file /私密位置/.env --check-identity
```

该脚本仅输出配置完整性、模式、测试码是否关闭及 STS 身份认证结果，不打印密钥、签名、模板内容或账户身份。身份认证使用只读请求，不发送短信，也不能证明短信权限、余额和送达。

GitHub Actions 的 **SMS configuration check** 同样只进行该检查；分支首次 push 自动运行，合并后可从 Actions 手动运行。

公共接口 `GET /api/studio/sms-status` 只提供配置状态。`configured`/`ready` 表示配置完整；`delivery_verified: false` 表示此接口本身未探测实际收信。登录界面据此提示能否发验证码。供应商失败只返回白名单中文说明，不透出原始供应商 Message、密钥或验证码。

## 真实验收记录（2026-10-31）

经用户指定号码并授权，发送一条真实验证码：阿里云返回 `Code=OK, Success=true`；用户收到后在隔离库注册成功。相同验证码再次提交返回 401，不能重复使用。接口没有回显验证码，号码与验证码不纳入源码或报告。

这证明当前阿里云凭据、签名和模板在本次测试中可用。尚未验证固定公网部署环境、其他运营商或批量发送。
