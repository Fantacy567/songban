## 01 项目思路与本轮取舍

服务对象是缺少 AI 经验、不知道孩子能尝试什么的家庭。家长负责了解、选择和付费，孩子实际学习与创作。机构可以成为未来渠道，但本轮产品不按机构已有 AI 学生的需求设计。

松伴提供一套可操作的 AI 学习环境：孩子在平台中接触任务、工具配置、请求、响应、模型对比和测试，理解真实电脑上使用 AI 的流程。学习从基础操作和认识输入输出开始，逐步走向独立选择工具、接入模型和完成项目。

产品交付的单位是一次有目标、有操作、有检查、有成果的小项目。每个项目留下作品版本、关键选择、失败与修正、所用帮助和迁移任务结果。家长据此看懂孩子做了什么、哪里仍需要帮助。

现有团队协作代码可以为后续多人项目提供来源记录、分工和同伴检查；基础学习阶段独立成立，不要求先找比赛、建队或安装个人智能体插件。

### 方向取舍

**用户与付费方**

- 本轮规划：孩子是学习者，家长是选择者和付费者；不把家长不懂 AI 等同于已经有付费意愿。

**环境的真实感**

- 本轮规划：复现任务、配置、调用、结果、检查、保存的工作流程；首版不复刻整个操作系统。

**小白或大神**

- 本轮规划：保留亲切的自选入口，说明只是起点偏好；结合短任务校准，后续可补基础或挑战。

**年龄**

- 本轮规划：填写年龄用于表达方式和材料推荐，最小化采集；不据年龄判定能力，不要求精确生日。

**课程与 AI 分工**

- 本轮规划：课程骨架、目标和检查标准由产品与教研确定；AI 负责分步提示、解释和反馈建议。

**旧文档**

- 本轮规划：机构优先融资稿、早期比赛平台路线保留为历史；后续路演、页面和需求统一按本轮家庭学习方向修订。

## 03 核心链路完整性检查

结论：概念方向成立，但当前代码还不能完成家庭 AI 学习闭环。以下缺口是上线学习产品必须处理的工作，不表示现有团队协作功能全部失效。

建议主链路：家长了解与试用 → 建立家庭及学习者 → 年龄与起点选择 → 短任务校准 → 推荐第一项目 → 学一点、做一步 → 模拟练习 → 真实模型实验与比较 → 修正与独立检查 → 保存作品和过程 → 家长查看成果 → 开通下一项目并继续。

模拟练习允许先体验；真实调用需要家长允许、服务可用和额度检查。课程中断可以恢复，未通过可以回到具体练习，服务故障不会被记为孩子能力不足。

### 必须补齐的六个闭环

**需求到首次体验**

- 为什么会断：家长看见功能名却不知道孩子能做什么；孩子一开始就面对 API 术语。
- 补全方式：展示一个明确标注的作品样例，第一课先完成简单输入与修改；把接入概念放到后续。
- 完成证据：新家庭无需解释能找到体验入口，孩子完成第一次有意义的操作。

**自选等级到合适课程**

- 为什么会断：自称大神可能跳过必要基础，零基础可能被术语挡住。
- 补全方式：短任务验证输入、修改、判断等表现；给出推荐理由，支持挑战和回补。
- 完成证据：同一年龄不同表现可走不同起点，失败不永久贴标签。

**看懂到亲手会做**

- 为什么会断：观看教程、复制答案或模型生成成功不能证明掌握。
- 补全方式：每课都做、检查、解释，再换一条材料独立完成小任务；记录帮助来源。
- 完成证据：作品、操作、解释、迁移任务能互相对应。

**实验到可恢复**

- 为什么会断：密钥、模型、网络、额度问题会让孩子卡住或重复消耗额度。
- 补全方式：模拟/真实/回放标识；请求状态持久化、幂等、防重复扣额、失败原因与恢复动作。
- 完成证据：刷新后找回原 run；未知结果先查状态，不盲目重发。

**成果到家长理解**

- 为什么会断：只给聊天记录、分数或一张好看的作品，家长仍不知道孩子贡献。
- 补全方式：报告展示起点、作品前后、关键选择、帮助、独立检查和下一步。
- 完成证据：每项结论能打开对应证据，缺证据写未观察到。

**满意到继续学习**

- 为什么会断：作品做完后没有下一任务，付费只卖模型次数。
- 补全方式：把后续课程路径、可交付成果、有效期和支持范围说清；权益决定可进入的项目。
- 完成证据：开通、到期、退款和继续学习状态一致；真实付款与口头兴趣分开统计。

## 04 端到端产品流程

### 每一步的动作 数据和出口

**F01 了解**

- 用户动作与页面：家长匿名看适合谁、能完成什么、明确标注的样例与注册入口。
- 系统保存或判断：匿名只看公开示例；校准、保存尝试和模型运行需要家庭与学习会话。
- 下一步与失败恢复：注册后进入指定体验课；首版不提供匿名真实API调用。

**F02 建立家庭**

- 用户动作与页面：家长注册登录，创建孩子昵称与年龄，了解学习数据用途。
- 系统保存或判断：家长身份、家庭关系、同意版本；已有账号不覆盖历史技能资料。
- 下一步与失败恢复：建立学习者；短信失败保留非敏感表单，显示重试条件。

**F03 选择起点**

- 用户动作与页面：孩子选择小白、有一点基础、大神，也可先从第一课试试。
- 系统保存或判断：自选值与年龄分别保存，不据此授予后台或付费权限。
- 下一步与失败恢复：进入短任务；可返回修改，未知年龄使用通用表达。

**F04 校准**

- 用户动作与页面：完成一条小任务，修改一次输出，并说出怎样判断结果。
- 系统保存或判断：保存尝试、提示使用、实际操作与简短解释；服务故障独立标记。
- 下一步与失败恢复：推荐路线并说明理由；可挑战更高任务或补基础。

**F05 选项目**

- 用户动作与页面：学习首页显示现在要做什么、预计步骤、最后得到什么。
- 系统保存或判断：课程版本、先修要求、权益与额度；显示推荐依据。
- 下一步与失败恢复：开始或续学；锁定项解释原因并给可做的替代任务。

**F06 学与做**

- 用户动作与页面：工作台读一个概念，看一个例子，修改自己的任务配置。
- 系统保存或判断：自动保存草稿和步骤；提示只按需展示；课程目标保持固定。
- 下一步与失败恢复：运行练习；未保存时明确提醒，重开恢复已确认版本。

**F07 实验**

- 用户动作与页面：先模拟连接，再在允许范围内选择模型、参数并发送请求。
- 系统保存或判断：校验模型/参数/输入、权益、额度；记录 run_id、模式和实际模型信息。
- 下一步与失败恢复：展示结果或准确错误；超时未知查原状态，不能直接判失败重扣。

**F08 比较与改进**

- 用户动作与页面：同一材料和测试集下比较两次实验，指出差异并修改。
- 系统保存或判断：固定材料/提示/测试版本，标明比较变量；两模型不可用时改称配置比较。
- 下一步与失败恢复：再实验或进入检查；一次结果只解释本次观察，不给全局模型排名。

**F09 检查**

- 用户动作与页面：先保存候选作品快照，再运行检查、解释选择并完成一条新材料任务。
- 系统保存或判断：检查绑定候选artifact_id/version/hash和测试版本；系统观察、AI建议、本人解释分别记录。
- 下一步与失败恢复：通过后提交同一候选版本；改内容生成新快照并重检，未通过回具体步骤。

**F10 成果**

- 用户动作与页面：孩子给作品命名，选择已检查的候选版本，说明自己做了什么与用了什么帮助。
- 系统保存或判断：提交接口核对candidate hash及check_ids后标为成果；不允许提交不同内容却沿用旧检查。
- 下一步与失败恢复：生成家庭报告；成果仍可建立后续新版本，但旧证据不静默改写。

**F11 家长反馈**

- 用户动作与页面：家长重新验证身份后查看报告、支持方式与下一项目。
- 系统保存或判断：仅访问本人家庭；报告按来源版本生成，可回看且不静默改写。
- 下一步与失败恢复：决定继续、暂停或开通；不会把孩子原始私人对话默认公开。

**F12 开通与续学**

- 用户动作与页面：家长看清课程范围、额度、期限、支持与退款规则后开通。
- 系统保存或判断：已核验订单或试点授权生成权益；孩子会话不具备购买权限。
- 下一步与失败恢复：权益到账继续学习；已完成成果在到期后按约定仍可查看。

## 05 从零到进阶的课程结构

每课统一循环：目标 → 简短示范 → 自己操作 → 看到结果 → 按标准检查 → 修改 → 独立小任务 → 保存证据。课程深度逐步增加，页面可以逐步展开配置项，不在第一课暴露全部技术选项。

本轮“迁移任务”专指在平台内更换资料或约束的独立小任务。迁移到真实电脑上的外部AI工具属于后续阶段，需单独观察和验收，不能由平台内通过推定。

### 学习阶段与可见成果

**L0 第一次使用**

- 学什么：输入、输出、复制、保存、AI 会出错；不要求先会编程。
- 孩子实际做什么：对一份短资料提问，找到答案出处，保存结果。
- 怎样判断：能自己完成输入与保存，指出一处需要核对的信息。

**L1 说清需求**

- 学什么：任务、背景、限制、输出格式与迭代。
- 孩子实际做什么：将笼统要求改成可检查的指令，对比修改前后。
- 怎样判断：结果满足明确条件，能解释自己改了什么。

**L2 认识模型类别**

- 学什么：文本、图像、语音等输入输出及用途、能力边界。
- 孩子实际做什么：为不同任务选合适类别，说明为什么；首版以材料演示其他模态。
- 怎样判断：知道模型名称与类别不同，能把任务匹配到合适工具。

**L3 比较效果**

- 学什么：相同任务下比较正确性、格式、速度和用量。
- 孩子实际做什么：控制其他条件，只换模型或一个参数，记录观察与选择。
- 怎样判断：有相同测试材料和结果依据，不把一次好坏说成永久优劣。

**L4 API 与接入**

- 学什么：服务地址、模型标识、认证、请求/响应、状态码与额度。
- 孩子实际做什么：先在模拟环境修复错误配置，再完成受限真实调用。
- 怎样判断：能识别错误发生在哪一步；真实秘密由服务端保管。

**L5 独立实验与迁移**

- 学什么：任务分解、测试集、失败分析、版本、成本与局限。
- 孩子实际做什么：基于新材料完成一个小应用，解释选择与不足；之后可做多人项目。
- 怎样判断：不同输入下可运行，有失败样例和独立说明，不只复现教程。

## 06 首版范围与一个完整项目

首版建议做“基于一页虚构活动资料的问答小助手”：孩子让 AI 回答资料中的问题；遇到资料没有的信息，应说明不知道。项目只用已知、简短、非私人材料，便于检查来源、比较效果和解释错误。

零基础路线从输入输出开始；较熟练的学习者通过挑战后进入模型比较或 API 排错。所有路线最终都保存同一种可检查的作品与过程记录。

建议首轮只开放一个家长管理一个学习者；数据层仍按family_id与learner_id隔离，为以后扩展留出空间。指定体验课的范围和正式课程包由服务端配置。

### 首版交付边界

**必须完成**

- 具体交付：家长账号与学习者、年龄/起点与校准、单项目递进课程、工作台、模拟与受控真实文本调用、测试与修正、作品版本、家长报告、额度和权益。

**比较实验**

- 具体交付：有两个真实可用模型才展示模型对比；只有一个时比较提示或参数，并准确命名。

**课程规模**

- 具体交付：先写完一个项目全部课次与检查标准，再扩课程数量；具体年龄试点范围与课时由教研验证确定。

**付费试点**

- 具体交付：可先人工核验收款并由后台发放课程权益，记录订单与操作日志；不把人工开通画成支付接口已上线。

**后续再做**

- 具体交付：图像/语音真实工作流、多人项目、外部工具迁移、已有团队协作和连接器、更多家庭成员。

**本轮暂缓**

- 具体交付：整套桌面系统、任意终端代码执行、任意模型地址、公开社区/排行榜、比赛搜索、机构管理后台、复杂自动订阅。

**P03 年龄 起点与校准**

- 前端负责：步骤式填写、可返回操作、短任务、推荐解释。

- 美术设计负责：不同起点入口、题目呈现、非评判式反馈。

**P04 学习首页与项目路线**

- 前端负责：继续学习、课程顺序、先修/权益锁定说明。
- 后端负责：可进入课程、进度、推荐原因、版本与权益。
- 美术设计负责：路线层级、当前任务突出、锁定/完成/需补练状态。

**P05 学习工作台**

- 前端负责：任务、提示、配置、运行、结果与检查的交互；草稿恢复。
- 后端负责：尝试保存、运行调度、权限额度、模型网关、结果持久化。
- 美术设计负责：布局、区域层级、完整状态稿、响应式、说明插图。

**P06 实验比较**

- 前端负责：相同条件提示、两列/分步对照、变量与结论填写。
- 后端负责：实验绑定、材料/测试版本、模型信息与用量口径。
- 美术设计负责：差异与失败的阅读方式，不用颜色单独表达结论。

**P07 检查与补练**

- 前端负责：检查项结果、证据跳转、重做入口和迁移任务。
- 后端负责：固定检查标准、判定来源、记录版本、人工复核状态。
- 美术设计负责：通过/需修改/未观察到/待复核的清楚区分。

**P08 作品与个人贡献**

- 前端负责：预览、版本切换、本人说明、帮助记录、导出。
- 后端负责：成果快照、证据关联、访问控制、导出脱敏。
- 美术设计负责：成果可读版式，清楚区分孩子操作与 AI/成人帮助。

**P09 家长报告**

- 前端负责：摘要、前后对比、证据展开、下一步与家庭反馈。
- 后端负责：本家庭权限、报告快照与来源、反馈保存。
- 美术设计负责：家长语言、真实成果优先、避免能力雷达和夸大评分。

**P10 课程权益与开通**

- 前端负责：权益说明、申请/订单状态、到期与恢复入口。
- 后端负责：订单核验、权益账本、额度、退款撤销与重复通知处理。
- 美术设计负责：内容范围、价格与期限清楚呈现，支付状态不误导。

**P11 内容与试点运营**

- 前端负责：最小的课程版本/复核/开通界面；早期可用内部脚本。
- 后端负责：课程发布校验、管理员权限、审计、暂停模型、人工发放权益。
- 美术设计负责：必要后台表单与状态规范；首版无需完整运营视觉系统。

**P12 进阶多人项目**

- 前端负责：后续连接已有团队工作台，区分个人学习与团队成果。
- 后端负责：受控关联学习成果与团队任务，不直接共享家庭私密记录。
- 美术设计负责：个人/团队场景切换与来源标签；后续阶段设计。

## 08 前端工作包与交付标准

前端负责把产品规则和设计变成可操作、可恢复、能显示真实后端状态的界面。沿用原生 HTML/CSS/JavaScript，按视图拆分文件；是否未来更换框架另行评估，不把重写当作本轮前提。

建议文件边界：static/learn.html；static/learn/tokens.css、layout.css、components.css、app.js、api.js、state.js、views/、components/、assets/。名称为规划，当前仓库没有这些学习模块。原 core 文件只做必要入口连接。

### 前端任务清单

**FE01 应用与身份**

- 负责内容：学习入口、页面导航、家长/学习者会话切换、401/403恢复。
- 交付与验收：GET session恢复当前身份；切换清缓存并忽略旧请求结果；孩子会话无法进入购买和家庭设置，回家长区必须再认证。

**FE02 基础学习页面**

- 负责内容：首次设置、校准、路线、课次步骤、继续学习。
- 交付与验收：新用户能从入口走到首个任务；返回和刷新不会丢已确认进度。

**FE03 工作台**

- 负责内容：任务说明、分步提示、参数表单、运行控制、响应预览、检查区。
- 交付与验收：点击运行即禁重复提交；loading/失败/未知/额度用尽全部可见，输入草稿保留。

**FE04 比较与证据**

- 负责内容：选择实验、锁定比较条件、填写选择理由、作品版本、报告展示。
- 交付与验收：显示实际模型/模式/来源，旧版本不显示为当前检查通过。

**FE05 组件与设计落地**

- 负责内容：按 tokens 实现按钮、输入、标签、任务步骤、检查行、提示面板。
- 交付与验收：公共组件用于所有学习页；不把按钮文字、布局容器切成图片。

**FE06 响应式与可访问**

- 负责内容：桌面工作区、平板折叠、手机步骤化；键盘、焦点和状态播报。
- 交付与验收：390/768/1440px可完成核心动作；长中文/模型名不遮挡；提示不只靠颜色。

**FE07 联调与质量**

- 负责内容：使用契约样例独立开发，再接真实测试后端；浏览器链路与视觉走查。
- 交付与验收：演示数据明显标记且隔离；不在浏览器伪造成功，不存模型密钥，不以隐藏按钮代替权限。

## 09 后端工作包与数据责任

后端是身份、权限、权益、课程进度、实验结果和证据版本的权威来源。建议新增学习域，复用现有认证、数据库和模型请求的合适部分；现有旧 Studio 的个人 model_key 会写入 SQLite，不能把它直接作为新儿童实验的密钥方案。

建议模块：app/learning_auth.py、learning.py、learning_models.py、lab_gateway.py、learning_checks.py、learning_reports.py、learning_billing.py，courses/ 保存课程定义。实际模块数量由实现者调整，但职责不能混成一个聊天接口。

### 后端任务清单

**BE01 家庭与会话**

- 负责内容：抽取公共认证能力；家长新入口适配现有必填字段；家庭、学习者、受限学习会话。
- 交付与验收：不伪造profile/skills填空通过；旧账号可继续使用；孩子不必拥有手机号；跨家庭访问被拒绝。

**BE02 课程与校准**

- 负责内容：课程版本、先修要求、年龄表达配置、校准记录、推荐与重新评估。
- 交付与验收：课程有固定目标和检查项；自选等级可调整，跳级也记录依据。

**BE03 尝试与草稿**

- 负责内容：lesson_attempt、步骤事件、草稿revision、恢复入口、运行关联。
- 交付与验收：冲突返回409和最新版本；中断恢复不覆盖已保存成果；隐私数据不混入团队资料库。

**BE04 模型实验网关**

- 负责内容：允许的服务商/模型与参数、秘密保管、输入检查、模式隔离、请求审计。
- 交付与验收：浏览器只传受控模型标识；模拟失败不能发往真实服务；实际响应模型不明时保持未知。

**BE05 状态与额度**

- 负责内容：运行持久化、幂等、用量账本、预算预占/结算、超时未知及异常恢复。
- 交付与验收：平台同操作只建一次run、避免重复发送和扣额；重启后恢复或转待核对。上游无幂等能力时保留未知状态，不承诺绝对一次执行或超时零费用。

**BE06 学习检查**

- 负责内容：确定性检查、任务解释与迁移证据、人工复核；AI建议单列。
- 交付与验收：模型成功不直接解锁。先保存候选快照，再按该hash检查；服务端根据必需检查、解释与迁移记录完成课次，人工复核有实际责任人。

**BE07 成果与报告**

- 负责内容：作品版本、个人选择/修改/帮助事件、报告快照、导出脱敏。
- 交付与验收：每条结论可追到证据，报告不能泄漏其他家庭；新版本不沿用旧验收。

**BE08 权益与开通**

- 负责内容：试点人工核验或支付服务回调、订单/权益/退款/到期状态。
- 交付与验收：价格/期限/额度从服务端取得；只有核验通过才开通；操作可审计、重复回调不重复发放。

**BE09 发布与运行**

- 负责内容：迁移、备份恢复、课程校验、用量监测、错误日志、限流和暂停入口。
- 交付与验收：学习服务异常不破坏现有协作数据；真实试点前验证部署包、权限与恢复链路。

### 建议新增的数据对象

**families / guardian_links / learner_profiles**

- 关键关联与规则：家长与学习者独立；昵称、年龄、自选水平、校准结果；家庭关系由服务端校验。

**learning_sessions / consents**

- 关键关联与规则：受限学习者会话与家长会话不同；同意文本版本和时间可追踪。

**course_versions / lesson_versions**

- 关键关联与规则：已发布内容不可静默覆盖；课次、前置、材料、参数限制、测试标准一起版本化。

**lesson_attempts / learning_events**

- 关键关联与规则：每次尝试绑定学习者、课次版本；草稿、关键操作、帮助与解释分开。

**model_catalog / lab_runs**

- 关键关联与规则：模型能力由维护者标注来源与日期；run绑定attempt和输入快照，保留请求/响应模型及mode。

**usage_ledger / entitlements**

- 关键关联与规则：额度预占、确认、释放与待核对有账本；用量未知不写成零。

**artifact_versions / checks**

- 关键关联与规则：作品版本不可变；检查绑定作品hash、材料/测试版本和判定来源。

**family_reports / feedback**

- 关键关联与规则：保存生成所依据的版本和证据ID；区分家长反馈与孩子表现记录。

**orders / audit_events**

- 关键关联与规则：开通或退款依据、操作者、重复请求标识与权益变更；不保存支付卡等无关数据。

## 10 前后端接口契约草案

以下 /api/learn 路由全部是拟新增接口。正式实现前由后端维护 OpenAPI，前端核对页面需要的字段和错误分支；设计稿只引用业务状态，不自创后台状态。先对齐契约样例，前后端可以并行开发；真实联调以服务端返回为准。

家长新注册先完成认证服务适配，不直接复用要求画像与技能的旧注册正文。已有登录可以通过适配进入家庭引导；长期会话存储方案须随认证设计确定，禁止把家长高权限 token 原样交给孩子页面。

新学习端建议使用独立HttpOnly会话及写请求CSRF防护。进入孩子模式时不留下可直接调用管理接口的家长会话；返回家长区需要重新认证。课程发布、人工复核和权益核验由受限运营角色执行并留审计记录。

### 首版接口分组

**POST /api/learn/auth/codes|register|login；GET /api/learn/session**

- 调用身份与职责：提取公共认证基础但使用独立学习会话；注册不要求伪造工作画像和技能。
- 关键结果或失败：当前actor、scope、learner、allowed_actions；重复手机号走登录/找回流程，不覆盖旧账号。

**POST /api/learn/onboarding**

- 调用身份与职责：家长；完成家庭初始化与学习者建立，认证适配另附契约。
- 关键结果或失败：family_id、learner摘要、consent_version；输入错误与重复初始化分别处理。

**POST /api/learn/sessions**

- 调用身份与职责：家长为本人家庭学习者创建受限学习会话。
- 关键结果或失败：受限会话；禁止购买、家庭管理和跨学习者访问。

**GET /api/learn/home**

- 调用身份与职责：学习者；取得当前项目、可做课次与继续学习位置。
- 关键结果或失败：课程版本、attempt、unlock_reason、权限与额度摘要。

**PUT /api/learn/profile**

- 调用身份与职责：学习者或家长按字段权限更新年龄/起点。
- 关键结果或失败：expected_revision；自选值不覆盖历史校准证据。

**POST /api/learn/calibrations**

- 调用身份与职责：学习者；提交短任务的尝试和说明。
- 关键结果或失败：推荐、理由、依据；AI建议不是最终能力评分。

**GET /api/learn/courses/{id}**

- 调用身份与职责：学习者；读取可访问的发布版本及课次。
- 关键结果或失败：目标、步骤、材料、可用模型/参数和检查说明。

**POST /api/learn/attempts**

- 调用身份与职责：学习者；按课次版本创建尝试。
- 关键结果或失败：attempt_id、revision；重复创建策略明确。

**GET /api/learn/attempts/{id}**

- 调用身份与职责：本人；恢复已保存尝试、课次版本、当前草稿与运行。
- 关键结果或失败：revision、current_step、artifact_versions与run_ids；用于刷新/重新登录后的续学。

**PATCH /api/learn/attempts/{id}**

- 调用身份与职责：本人的学习会话；保存草稿与解释。
- 关键结果或失败：带expected_revision；保存成功返回revision、input_version和content_hash，后续run与候选作品引用此版本；409返回可恢复路径。

**POST /api/learn/attempts/{id}/hints**

- 调用身份与职责：学习者；申请指定步骤的提示。
- 关键结果或失败：提示等级、来源、帮助记录；模型提示失败时仍有固定课程提示。

**POST /api/learn/runs**

- 调用身份与职责：学习者；mode、attempt_id、input_version、model_ref、参数和幂等键。
- 关键结果或失败：202 + run_id/status；先校验额度和允许配置，不接收任意真实密钥。

**GET /api/learn/runs/{id}**

- 调用身份与职责：本人；读取原运行状态、输出和用量。
- 关键结果或失败：queued/running/succeeded/failed/unknown；允许轮询读取，不自动重放写请求。

**POST /api/learn/attempts/{id}/checks**

- 调用身份与职责：学习者；检查当前作品与迁移任务。
- 关键结果或失败：check_id、各项结果与来源；不能由前端传passed=true。

**POST /api/learn/artifacts**

- 调用身份与职责：学习者；先保存不可变候选作品快照，供检查使用。
- 关键结果或失败：artifact_id、version、content_hash、source_run_ids；新内容必须生成新版本。

**POST /api/learn/artifacts/{id}/finalize**

- 调用身份与职责：本人；提交同一已检查版本，附check_ids与expected_revision。
- 关键结果或失败：核对候选hash、必需检查、孩子解释和平台内迁移记录，由服务端转课次为已通过或需补练/待复核；通过后回传artifact_id、report_id及report_status。

**GET /api/learn/family/reports/{id}**

- 调用身份与职责：绑定家长；查看报告与证据索引。
- 关键结果或失败：报告版本、作品与帮助摘要、下一步；403越权拒绝。

**GET /api/learn/entitlements**

- 调用身份与职责：家长看明细，学习者仅看自己的可用状态。
- 关键结果或失败：可用课程、有效期、额度、开通状态，不能由浏览器修改。

**POST /api/learn/orders**

- 调用身份与职责：家长；选择服务端定义的课程包，试点可返回人工核验状态。
- 关键结果或失败：pending/verified/closed/refunded；收款方式确定后补回调或后台核验契约。

**GET /api/learn/family/reports；POST /api/learn/family/reports/{id}/feedback**

- 调用身份与职责：绑定家长；找到本家庭报告并保存是否理解、下一步意愿与困难。
- 关键结果或失败：报告摘要、来源版本、下一项目引用；反馈不得改写孩子的实际检查记录。

**GET /api/learn/orders/{id}；POST /api/learn/admin/orders/{id}/verify**

- 调用身份与职责：家长查询自己的订单；运营角色核验试点收款并发放权益。
- 关键结果或失败：核验依据、操作者、订单版本和幂等键；拒绝孩子与普通家长发放权益。

**GET /api/learn/admin/reviews；POST /api/learn/admin/checks/{id}/review**

- 调用身份与职责：受限教研人员处理明确进入待复核的任务；范围由后台授权。
- 关键结果或失败：真实检查者、依据、结论和时间；AI不能冒充人工复核，学习者可查看对应反馈。

**POST /api/learn/admin/courses/{id}/publish**

- 调用身份与职责：课程维护者；可先由内部发布脚本实现同样校验，无需完整CMS。
- 关键结果或失败：课程/材料/测试/提示版本一起校验发布；旧尝试保持旧版本。

**POST /api/learn/sessions/end；POST /api/learn/family/reauth**

- 调用身份与职责：退出使当前会话失效；回家长区重新验证家长凭据并签发管理会话，不能靠我是家长按钮。
- 关键结果或失败：刷新通过GET session恢复身份；切换学习者先撤销旧学习会话并清前端私有缓存，迟到响应不得显示。

**GET /api/learn/admin/runs/reconciliation；POST /api/learn/admin/runs/{id}/resolve**

- 调用身份与职责：受限运营/后端维护者处理unknown运行和额度核对，不允许学习者自行改执行结论。
- 关键结果或失败：核对依据、结果、用量来源、额度处理、操作者和时间全留痕；无法确定时可关闭核对但仍保留执行/用量未知。

### 统一响应与版本约定

**失败结构**

- 约定：沿用 error.code/error.message；补 request_id、retryable 和字段错误。message给用户，技术详情只入脱敏日志。

**状态码**

- 约定：401需重新认证；403无权限；409版本冲突；422字段/课程校验；429按error.code区分频率限制和额度不足；503服务暂不可用。

**运行元数据**

- 约定：保存mode、requested_model_id、response_model_id、输入/课程版本、耗时、usage及usage_source；未知值为null，不伪造。

**幂等**

- 约定：幂等键绑定学习者、操作类型与正文摘要；短事务原子建run及预占额度。同键同正文只返回原run，不再外发；同键不同正文拒绝。平台避免重复发起，上游无幂等支持时不能承诺严格只执行一次。

**比较口径**

- 约定：比较绑定相同材料和测试版本，显式记录变化参数；同配置重复运行也注明随机性。

**模拟数据**

- 约定：契约fixture和真实生产数据隔离；mode=mock/live/replay持续可见，回放标注原记录时间。

**报告生成**

- 约定：finalize先形成成果事实与来源，再按固定结构生成报告；可同步完成或返回pending并有界查询。生成失败可按原artifact重试，不能重跑模型实验或丢成果。家庭报告列表提供发现入口；报告ready不代表整个能力已掌握。

## 11 关键状态与失败恢复

不要用一个“完成”代表所有结果。课次有进行中、已提交、需补练、待人工复核、已通过；实验有排队、运行中、成功、失败、结果待核对；作品有草稿和已保存版本；订单有待核验、已确认、关闭与退款。不同领域分别保存状态。

unknown运行设置review_due_at，超过平台约定窗口进入运营核对队列。有可靠依据时转成功或失败；无法查证时标记核对已关闭、执行与用量仍未知。按照事先明确的用户额度规则释放或调整预占，并将实际供应商成本未知单独保留；人工处理带幂等与审计，避免永久冻结、重复扣额或把未知写成免费成功。

### 必须设计和联调的状态

**首次无记录**

- 界面与动作：说明第一步，给可执行按钮；不展示假进度、假成果。
- 后端与数据要求：区分尚未开始与读取失败。

**自动保存中/失败**

- 界面与动作：显示保存时间或未保存提示，保留当前输入，可重试保存。
- 后端与数据要求：版本检查；保存失败不能让页面显示已保存。

**离开与续学**

- 界面与动作：已保存部分可恢复；关闭前有未保存提示。
- 后端与数据要求：读取尝试/运行状态，不靠浏览器缓存当权威记录。

**排队/运行中**

- 界面与动作：保留任务与输入，按钮禁重复点击，可离开后回来。
- 后端与数据要求：持久化run并保证单次请求；真实任务状态可查询。

**模拟认证错误**

- 界面与动作：引导检查教学凭据字段，明确这是模拟故障。
- 后端与数据要求：不触发真实上游、不消耗真实调用额度。

**真实服务错误**

- 界面与动作：区分配置、限流、服务故障；给返回课程或稍后查询入口。
- 后端与数据要求：保留request_id、脱敏错误和计费状态，不把服务故障计为学习失败。

**超时结果未知**

- 界面与动作：显示“正在核对这次结果”，可查询；不提供误导性的立即重试。
- 后端与数据要求：unknown状态与额度预占待核对；不擅自重复发送。

**额度用尽**

- 界面与动作：显示剩余可做的模拟练习，家长可查看开通方式。
- 后端与数据要求：原子额度检查，孩子无权扩大预算。

**检查未通过**

- 界面与动作：指出哪项不符、依据和回到哪一步；保留旧结果。
- 后端与数据要求：记录具体测试版本，允许新的尝试；不覆盖失败历史。

**模型回答被截断**

- 界面与动作：明确结果不完整，可缩短任务或在允许范围内调整。
- 后端与数据要求：保留finish_reason；不把截断响应当完整作品。

**登录失效/越权**

- 界面与动作：重新认证或回到自己的学习入口；不会显示其他孩子资料。
- 后端与数据要求：逐个资源验证家庭/学习者归属。

**版本冲突**

- 界面与动作：提示有新版本，允许对照草稿后重新保存。
- 后端与数据要求：409和最新revision，拒绝静默覆盖。

**报告无足够证据**

- 界面与动作：显示已观察事实与尚未观察的项目，建议下一任务。
- 后端与数据要求：不让AI补造独立完成、提升比例或个人贡献。

**开通未到账/退款**

- 界面与动作：展示待核验/退款状态与联系入口；旧作品按约定可查看。
- 后端与数据要求：核验到账才赋权，退款后的权益规则固定并可追溯。

### 权益规则建议 供人工开通与未来支付共用

**未开通**

- 模拟学习：公开样例、校准；注册后可进入明确指定的体验课。
- 真实调用：不可用。
- 继续与历史成果：可查看已保存的体验成果；正式课程显示范围与开通入口。

**试用有效**

- 模拟学习：仅试用范围内的课次和模拟练习。
- 真实调用：默认不开放；若试点授予，须家长允许并有独立上限。
- 继续与历史成果：允许续学试用课；有效期由服务器返回。

**正式权益有效**

- 模拟学习：已购范围内课次与练习。
- 真实调用：模型可用、家长允许且额度足够时开放。
- 继续与历史成果：可继续未完成项目，查看自己的历史作品和报告。

**权益有效但真实额度用尽**

- 模拟学习：已购课次中无需真实调用的部分仍可做。
- 真实调用：暂停；孩子不能增加预算。
- 继续与历史成果：保存草稿和历史；真实实验步骤等补足额度，不能伪装完成。

**权益到期**

- 模拟学习：回到公开/体验范围；正式课程停止新操作。
- 真实调用：不可用。
- 继续与历史成果：已保存正式作品、报告及草稿只读；续期开通后按版本恢复。

**退款已确认**

- 模拟学习：撤销该订单授予的正式课程权限；保留独立体验范围。
- 真实调用：不可用，其他有效权益不受误伤。
- 继续与历史成果：已保存本人作品与报告只读，不删除学习历史；未完成正式尝试暂停。

> 这是待产品负责人确认并写入购买说明的统一权益规则，尚未生效。真实调用quota与课程权益分开；到期/退款不删除作品的承诺需与实际数据保留和删除机制一致。

## 12 美术设计的责任与交付包

这里的美术设计包含品牌视觉、界面视觉、教学示意图和必要动效。美术不负责决定课程正确答案、后台权限或接口字段。产品与教研先给真实任务和文案，前端提供实现约束；若团队只有插画能力，需要明确谁承担 UI 设计与交互状态设计。

视觉方向建议：清楚、友好、有秩序，初学者优先看到任务和下一步，进阶用户可以展开技术信息。同一套组件随课程深度展开，避免按年龄做两套割裂产品。具体配色、形象和插画风格在首个工作台样张确认后再批量制作。

### 美术交付清单

**D01 视觉基准**

- 交付物：可编辑设计源文件与一页风格基准。
- 必须包含：品牌用色、文字层级、间距、圆角、图标风格；说明与现有品牌的关系。
- 谁验收：产品确认定位，前端确认能实现。

**D02 设计变量**

- 交付物：设计变量表或tokens JSON及变更记录。
- 必须包含：语义名称、值、用途、状态；不只给一张颜色截图。
- 谁验收：前端映射CSS变量后与设计核对。

**D03 组件库**

- 交付物：按钮、输入框、选择器、提示、步骤、结果卡、检查行、弹层。
- 必须包含：默认/悬停/焦点/禁用/加载/成功/失败；长文案和缩窄规则。
- 谁验收：前端组件展示页与设计共同验收。

**D04 页面稿**

- 交付物：P01–P10首版相关关键页面，P11只做必要后台状态。
- 必须包含：桌面/平板/手机布局，主路径与异常状态，真实长度中文与示例内容。
- 谁验收：产品验流程，前端验布局约束。

**D05 教学资产**

- 交付物：模型类别示意、请求响应说明、必要空状态插画。
- 必须包含：按课程目标画图，关键文字仍用可编辑文本；替代说明、来源与授权。
- 谁验收：教研验准确性，前端验清晰度与文件。

**D06 动效说明**

- 交付物：时长、触发条件、循环次数与静态替代。
- 必须包含：用于反馈操作与状态，不遮挡学习、不模拟未返回的成功；尊重减少动态效果偏好。
- 谁验收：前端实现后，设计与产品复核。

**D07 开发交付包**

- 交付物：源稿版本、状态清单、导出资源、manifest、尺寸规范与验收截图。
- 必须包含：每个资源有ID、版本、用途、尺寸、格式、许可、替代文本；无需让前端猜对应页面。
- 谁验收：前端接收签字后进入开发。

**D08 设计走查**

- 交付物：基于实际预览地址的差异清单。
- 必须包含：页面ID、组件、视口、截图、问题、建议、优先级；不只说不像设计稿。
- 谁验收：修复后复看实际页面，记录接受的差异。

## 13 美术到前端的交付落地流程

设计工具可用 Figma、Penpot 或团队已有工具；关键是可编辑源稿、固定版本与完整规格。设计工具链接是协作入口，仓库中的交付说明、变量和资源是开发可追溯的依据。设计工具导出的自动代码只能作为参考，前端仍需负责语义结构、交互和数据绑定。

### 从需求到页面上线的八步

**H01 锁定任务**

- 主责：产品/教研
- 输入与动作：明确页面目标、用户、主路径、文案、错误分支和验收；后端说明数据与权限。
- 完成出口：一张页面任务单，页面ID、状态清单和优先级齐全。

**H02 低保真走查**

- 主责：产品+美术+前端
- 输入与动作：用简单线框走完成功、失败和返回流程；先解决入口与信息顺序。
- 完成出口：确认能完成任务，再进入精细视觉。

**H03 共建组件**

- 主责：美术+前端
- 输入与动作：设计tokens与基础组件；前端评估字体、断点、图标、表单和响应式可实现性。
- 完成出口：一页实际组件样张，命名与状态一致。

**H04 交付冻结**

- 主责：美术
- 输入与动作：导出有版本号的设计稿、资产manifest、完整状态和响应式说明；前端逐项接收。
- 完成出口：设计版本如design-v0.1，缺项退回明确补齐，不口头算交付。

**H05 页面实现**

- 主责：前端
- 输入与动作：先建tokens.css和复用组件，再拼页面；按契约fixture做交互并标记演示。
- 完成出口：可访问预览与代码提交；布局、键盘和异常状态均可操作。

**H06 接口联调**

- 主责：前端+后端
- 输入与动作：将fixture换成隔离测试服务，验证字段/权限/状态/幂等/恢复；后端确认数据。
- 完成出口：真实HTTP流程记录，接口版本与代码提交对应。

**H07 三方验收**

- 主责：产品+美术+开发
- 输入与动作：产品验流程与文案，美术验实际视觉，开发验状态和数据；按问题优先级修复。
- 完成出口：阻断问题清零，已接受差异有记录，关键截图与录屏可复查。

**H08 发布和变更**

- 主责：开发负责人
- 输入与动作：合并已验收提交、更新静态资源版本、发布并走一次关键路径。
- 完成出口：发布记录关联需求/设计/接口/代码版本；后续改动开变更单。

### 资源格式与接收标准

**图标**

- 交付规则：优先SVG，统一viewBox和笔画，移除脚本/外链与编辑器冗余；单色图标支持currentColor，复杂品牌标识按原规范。

**插画与图片**

- 交付规则：矢量适合SVG，位图用WebP或PNG；说明透明背景、裁切范围和展示尺寸，必要时提供1x/2x；不导出整页截图做页面。

**文字与字体**

- 交付规则：按钮、标题和正文用真实文本；字体明确授权及回退栈，不强制大体积字库；教学关键文字不烙进图片。

**命名**

- 交付规则：按用途语义命名，例如 learn-model-type-text-v1.svg、learn-empty-runs-v1.webp；不使用最终版2或无语义数字。

**manifest**

- 交付规则：逐个登记asset_id、file、version、usage/page、尺寸、格式、许可、alt/decorative与设计版本；无法提供授权的资源不进入发布包。

**大小预算**

- 交付规则：前端先测首屏与常用网络下的加载情况，再约定每类资源预算；超预算压缩或替换，不用画质无限制换体积。

**交付接收**

- 交付规则：前端核对文件可打开、名称与页面一致、状态完整、断点明确、源稿可编辑；产品/教研核对文案与示意准确。

## 14 具体示例 学习工作台怎样落地

以 P05“第一次真实文本请求”为例：孩子已完成模拟练习，当前任务是让助手只依据虚构资料回答一个问题。页面主动作是运行，次动作是获取提示和保存；系统必须保留孩子已写内容。

桌面布局建议：左侧课程步骤，中间任务/输入/结果，右侧可折叠配置与提示。手机改成任务、操作、结果三个顺序区域，保留当前步骤和主按钮；参数说明按需展开。此为布局建议，具体宽度由组件样张验证。

### 同一页的三方交付示例

**产品与教研**

- 实际需要交付什么：页面任务单P05；本课目标；一页材料；输入样例；至少一个资料内问题与一个资料外问题；检查标准；提示层级和孩子能理解的错误文案。

**美术**

- 实际需要交付什么：P05桌面/平板/手机稿；空白、已填、运行中、成功、失败、未知、额度不足、未保存等状态；模型徽标/模式标签/提示图标与变量清单。

**前端**

- 实际需要交付什么：实现LessonStepper、TaskBrief、ModelSelector、PromptEditor、RunButton、RunResult、CheckList、HintPanel；读取接口权限；创建run后按run_id查询。

**后端**

- 实际需要交付什么：返回课次允许的模型/参数与额度；校验input_version；幂等创建run；保存结果和用量来源；返回检查结果；服务错误不改变学习等级。

**共同验收**

- 实际需要交付什么：同一学习者完整走完模拟→真实→检查→修正→成果；刷新可继续；重复点击仅一条run；手机和键盘均能完成；mode始终正确。

- 应用位置：任务标题、正文、输入文本。

## 15 决策权与跨角色协作

### 谁负责决定 谁负责实现

**用户与范围**

- 最终责任：产品负责人
- 协作与边界：综合家庭访谈与试点反馈取舍；设计稿或模型输出不能自行新增商业承诺。

**课程与学习判定**

- 最终责任：教研/内容负责人
- 协作与边界：定义年龄适配、任务、样例、测试和补练；后端实现规则，AI只给辅助建议。

**界面体验与视觉**

- 最终责任：产品确认流程，美术确认视觉
- 协作与边界：前端共同评估响应式和可实现性；不能只交一张漂亮的成功页面。

**接口与数据权限**

- 最终责任：后端负责人
- 协作与边界：前端确认字段可用，美术理解状态；权限由服务器执行。

**页面工程**

- 最终责任：前端负责人
- 协作与边界：负责组件、状态、访问性、性能与接口绑定；可提出设计调整但要记录差异。

**模型与实验有效性**

- 最终责任：后端+教研
- 协作与边界：后端确保请求/数据/用量正确，教研确保任务与比较条件合理。

**付费与支持**

- 最终责任：产品/运营
- 协作与边界：确定范围、价格、期限、退款和支持承诺；后端落权益，前端清楚呈现。

**上线验收**

- 最终责任：产品负责人收口
- 协作与边界：前端、后端、美术分别提交验收证据；没有完成的功能不能在路演写成已上线。

> 以上是角色分工，不是本轮为具体成员重新分派权限。现有前后端宪法的人名与历史路径需要另行更新后再作为新范围的协作依据。

## 16 实施阶段与进入下一阶段的条件

### 按完整链路交付

**A 范围与样张**

- 产品与美术：确定首个项目、试点人群、课次目标；完成P03/P05/P09线框和组件样张。
- 前端：搭最小学习视图及可操作fixture，验证响应式和状态。
- 后端：确定家庭/会话、数据、OpenAPI、run状态与额度规则。
- 阶段出口：能用同一份样例讲清楚从起点到家长报告，交付标准无歧义。

**B 教学闭环**

- 产品与美术：写完首项目课程与检查；交齐首版页面和全部异常状态。
- 前端：接入设置、校准、工作台、检查、作品和报告。
- 后端：完成学习数据与模拟网关、版本和报告；迁移不破坏旧数据。
- 阶段出口：隔离环境跑通一名学习者全流程，刷新/失败/权限可验证。

**C 真实实验**

- 产品与美术：检验模型比较是否有教学价值；校正文案和错误提示。
- 前端：真实状态、模型信息、用量、比较和恢复交互。
- 后端：真实受控API、预算和幂等、未知状态恢复、服务暂停。
- 阶段出口：在授权预算内走通真实调用；模拟/真实结果始终可区分。

**D 家庭试点**

- 产品与美术：观察家长理解、孩子独立操作与补练；确定支持范围与课程包。
- 前端：修复阻断使用的交互，完善家长反馈和开通状态。
- 后端：部署/备份恢复、人工核验权益或支付、异常监测。
- 阶段出口：真实家庭走完整链；记录实际帮助、付款/退款和运营投入。

**E 扩展进阶**

- 产品与美术：根据证据扩展模型类别、项目与多人协作课程。
- 前端：扩展已验证组件，接入进阶团队场景。
- 后端：增加模态适配与受控协作关联，保持隐私边界。
- 阶段出口：首项目学习效果与交付成本已有依据，再扩规模。

> 不在未知人员与投入的情况下承诺工期。先把每阶段拆成可验收任务，再由实际负责人评估排期；原飞书资料库与比赛平台待办不自动并入学习MVP。

## 18 成果 商业验证与路演表达

家长买的是有顺序的学习实践和可理解的成长证据。作品好看与孩子学会是两件事；技术跑通与家长愿意付费也要分别验证。首轮不预设价格、提升百分比或续费率。

### 成果与个人贡献证据页

**起点与任务**

- 记录方式：本次学习目标、自选起点与校准表现；不公开精确年龄或联系电话。

**作品与版本**

- 记录方式：可查看的输出、材料与版本；保留修改前后对比。

**孩子的具体选择**

- 记录方式：改了哪条要求、选了哪个模型/参数、怎样解释差异；关联实际操作。

**获得的帮助**

- 记录方式：固定提示、AI生成、成人帮助分别记录；本人自述与系统事件区分。

**检查和局限**

- 记录方式：哪些测试通过、哪些未通过、哪次迁移任务独立完成；未观察到就保留未知。

**下一步**

- 记录方式：一项具体补练或更难任务，以及家长可以提供的支持。

### 试点分别观察什么

**技术链路**

- 记录口径：完整流程成功与失败记录、恢复情况、真实用量和单次运行成本。
- 不能据此推出：不能推出孩子学会或家长会续费。

**学习过程**

- 记录口径：开始人数与完成首项目人数、关键任务独立完成情况、提示与成人介入、迁移任务表现。
- 不能据此推出：不能把自动生成的成品或点击完成当掌握。

**家长理解**

- 记录口径：看报告后能否复述具体成果、帮助程度与下一步；记录困惑和退课原因。
- 不能据此推出：不能把满意评价当真实购买。

**商业意愿**

- 记录口径：接触、试用、明确报价、真实付款、退款、再次付费分别计数并注明观察期。
- 不能据此推出：不能把口头愿意、机构关系或路演兴趣算收入。

**交付成本**

- 记录口径：模型费用、教研投入、人工反馈与客服时间分别记录；缺失成本明确待补。
- 不能据此推出：不能只看API成本就认定商业模式成立。

### 建议路演演示顺序

**家庭问题**

- 展示重点：家长不知道怎么开始、也看不懂孩子使用AI的结果。

**从零开始**

- 展示重点：孩子选起点，做短任务，进入一条具体课程。

**真实学习**

- 展示重点：一次实验错误、一次修改、一次同条件比较；清楚标记演示或真实调用。

**成果证据**

- 展示重点：展示孩子自己的选择、所用帮助与独立检查，不只展示漂亮作品。

**商业与下一步**

- 展示重点：分别说明现有代码、开发中规划、真实家庭反馈与真实付款；未验证部分如实列出。
