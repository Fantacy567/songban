# 松伴连接器与赛后成长报告宪法

版本：1.0.0-draft。日期：2026-10-31。

本文件记录用户本轮明确的产品意图，并提出必须满足的行为与证据边界。连接器是已有底座；速读卡、完整可见回复归档、家长报告、跨比赛记忆仍需实现。多 Agent 的角色划分是供讨论的建议，不是已确认的技术选型或已上线能力。

本扩展适用于黑客松比赛协作，不将既有 AI 入门课程草案整体改成比赛产品。与项目主宪法共同使用；家庭隔离、真实状态、证据关联和接口契约继续适用。后续功能规格必须说明新增与兼容范围，不能另建第二套团队任务事实。

## 一、功能意图

松伴连接器应让参赛者继续使用自己的 Codex、Cursor、WorkBuddy 等 AI 工具，在明确共享的对话中，将本人输入与 AI 的可见反馈可靠送回指定比赛的团队空间。

它有两个核心用途：

1. **比赛中减少沟通成本。** 用户少做复制粘贴；队友先看简洁的进展、建议、待核实点和协作需求，需要时再追溯允许共享的原文，避免逐段阅读大量 AI 文字。
2. **比赛后看懂个人成长。** 结合共享对话、孩子自己的解释与复盘、可核对的贡献、队友交接反馈、赛事结果与当时条件，形成家长能读懂的成长报告；再将适合复用的理论与协作经验整理成下一场助手可读取的记忆。

两个用途共享事实来源，但展示内容与读取权限不同。团队共享不自动等于家长可看所有队员原文，家长报告也不是把团队聊天再发一遍。

## 二、当前代码事实

基线：GitHub main `369f8afb`。本轮在隔离真实 Chrome 中确认当前统一前台存在以下入口，未在真实个人工具中重新安装插件。

| 项目 | 当前状态 | 证据 |
|---|---|---|
| 实践 → 个人工具 | 已有 | `static/songban.js` 的实践导航、`static/songban-views.js` 的 `plugin()` |
| Codex 原生插件安装 | 已有安装器与源码；当前会话加载仍要单独确认 | `app/connector_plugin.py`、`plugins/songban-native/` |
| Codex、Cursor、WorkBuddy 项目 MCP 配置 | 已有对应配置路径与合并逻辑；不代表三个真实客户端都已验收 | `app/team_install.py` |
| 通用插件下载、个人凭证、暂停/撤销 | 已有 | `plugin()`、`connectionList()`、`plugins/songban-team/` |
| 共享对话写入与团队资料库 | 已有，成员经本队授权读取 | `POST /api/core/teams/{sid}/conversation-notes`、`GET .../library` |
| 当前记录内容 | 用户原话、服务端绑定的姓名、AI 回复要点、实际模型名 | `plugins/songban-native/skills/team-sync/SKILL.md`、`app/team_core.py` |
| 全部可见回复原文及整场完整记录 | 尚不具备完整保证；字段有长度上限，当前主要保留回复要点 | 当前没有完整回复分段归档、覆盖率与缺失回合协议 |
| 家长端成长报告与比赛记忆 | 当前连接器链路未实现 | 既有学习产品文档是规划，不能当作代码能力 |

GitHub 历史查询确认，原生连接器随提交 `9b927384`（Ship Songban core collaboration and native connector）入库，当前 main 仍保留模块，无须回滚旧网页来恢复。

旧《选择式松伴连接器》文档中“上传后自动分析”的描述是历史行为；当前带用户原话/回复要点的记录走 `capture_only`，上传不会触发统筹。本文件以当前代码为事实基线。

## 三、安装与共享必须由用户掌握

1. 安装只增加松伴自身所需连接，保留用户模型设置、其他插件与项目配置；失败应撤销新凭证并可恢复。
2. 分别记录“安装文件完成、工具注册启用、当前会话加载、绑定验证、真实回合入库”。前一步成功不能替代后一步。
3. 原生插件、项目 MCP、文件监听、手动补传是不同接入能力，界面必须说明实际支持方式。远端网页不能直接把插件装到访问者本机；应提供本地安装助手或下载配置并验证。
4. 共享授权明确到本人、比赛、队伍、工具和对话范围；允许逐回合选择，也可在用户明确授权的本次对话内持续共享，提供暂停、撤销和补传入口。不得把“曾经安装”解释为以后所有对话永久共享。
5. 当前 `selected:true` 是调用方声明，不是宿主签名的授权证明；未完成宿主侧校验前不得宣传为不可绕过的自动采集系统。
6. 不扫描其他私人聊天，不抓取模型隐藏思考，不上传密码、密钥或短信码。原话应说明脱敏情况，不能把脱敏后的内容标为未经改动的完整原文。

## 四、先可靠记录，再按用途提炼

每个共享回合至少关联本人、比赛、队伍、来源工具、会话、稳定回合标识、发生时间、用户输入、可见回复、回复要点及实际模型名。模型未知留空，不能用工具品牌代替模型名称。

**已授权完整回复是追溯层，摘要是速读层。** 既有摘要共享授权不自动扩展为完整回复归档；完整回复共享方式未确认前，不默认启用全文上传。两者分别保存并关联。长回复应分段并校验是否完整；无法取得原文时明确记录“仅摘要”，不得让摘要冒充完整回复。版本、截断、补传和缺失范围必须可见。不得追求“所有记录”而扩大到用户未授权的对话。

写入先核验本人和本队权限，以稳定事件标识去重并返回记录号；收到记录号后才显示共享成功。失败保留可重试队列，同一回合重复重试不制造多条事实。撤销授权后的排队记录不得继续上传。

上传不直接改选题、任务、贡献结论或成长画像。队员纠正摘要、更新原文或调整共享范围时保留版本关联；由旧材料生成的分析、报告与记忆应标记需要复核，不能继续当成最新结论。

当前接口与字段需兼容迁移；本文件不擅自把已有 `assistant_summary` 改成完整回复，也不假设任何新增接口已经存在。

## 五、团队先看到能行动的内容

团队速读卡回答：谁在处理什么、本人问了什么、AI 建议是什么、实际做了什么、哪些尚未验证、需要谁配合。默认保持简短，允许查看权限范围内的原文和成果依据。

“AI 建议可行”“本人说完成”“文件可打开”“同伴检查通过”必须分别呈现。重要约束、不同意见、不确定性和失败尝试不能为了简短而消失；没有获得检验证据时显示未知。

上传可以更新速读内容，但正式分析只在比赛阶段条件满足、由有权限的人发起时执行。分析 Agent 输出候选方向、取舍、风险、剩余时间与评分匹配；队伍确认最终方向，队长发布任务，同伴确认验收。

连接器应在组队后出现一次明确的安装/验证引导，平时以“已连接、最近一次共享、失败待补传”呈现，不要求用户反复进入工具后台。

## 六、成长报告必须说明孩子本人做了什么

报告在本场复盘后生成，事实输入包括：

- 孩子获准共享的 AI 回合及记录覆盖情况。
- 本人选择、追问、解释、修改、验证、成果版本与同伴检查。
- 孩子对得失的见解与赛后复盘；有来源的队友反馈及协作事件。
- 比赛名次、奖项、评委意见及其来源；未知或尚未公布时留待补充。
- 任务难度、本人角色、时间限制、AI/成人帮助和团队背景。

名次是团队比赛结果，不能直接换算为孩子的个人能力；没有名次不阻止记录已有成长。补录结果产生报告新版本，不能重写先前发生的事实。

能力评估应落在可观察维度，例如问题澄清、AI 使用与核验、执行与迭代、沟通与协作、表达与反思。分别说明本人独立做到的、借助帮助做到的、尚未观察到的，以及判断所依赖的具体记录。

“成长了什么”需要前后可比较的行为或作品；缺少起点证据时只能写本场表现，不能编造进步幅度。AI 写出的漂亮方案、发言长度、上传数量、工具熟练度和团队名次均不能单独证明能力。

用户提出的“性格分析”在报告中采用**本场协作表现与偏好**：例如本次更愿意先画图、倾向先提问题或主动整理需求；附例子、情境和不确定性。不据一次比赛下固定人格、智力、心理诊断或职业定论。

未来优势以待验证的假设与下一次可尝试任务表达，不能写成天赋已经确定。例如“本场多次发现需求歧义，下次可以尝试主持一次需求澄清，再观察是否仍适合”。无证据时写资料不足，不硬凑评分或雷达图。

建议家长版固定回答六件事：本场做了什么；孩子实际贡献；可观察的优势；经历了什么变化；协作偏好与仍不确定之处；家长可以怎样支持下一步。正文自然语言、少术语，每项判断都可追溯到允许查看的证据。

## 七、解释其他队员，只为看清本人的协作

可以拆解“谁提出问题、谁给出建议、孩子如何回应、后来怎样验证”，帮助理解孩子在团队中的角色。不得把队友原话自动复制进另一个家庭的长期档案，也不得生成面向本家庭的队友人格或能力排名。

队友反馈保留来源与可能偏差，孩子可以补充或指出异议。关键解释有冲突时并列说明，不能由模型强行选出一个事实。家长端默认只看本人孩子的报告和经允许的必要背景，不继承整队资料库权限。

## 八、给下一场助手的记忆要可用、可改、可忘

**理论记忆**保留概念、孩子解释的要点及其证据引用、用过的方法、已尝试的条件、常见误区和待练内容；必须区分“AI 曾提到、孩子能解释、实际应用过、已检验”。不把模型回答过的知识写成孩子已经掌握。

**协作记忆**保留本人的尝试角色、有效协作办法、交接问题与下次可改进方法，不给孩子固化岗位。结构应包含来源比赛与证据、时间、版本、确认/异议状态、适用条件和下次验证建议。

建议记忆写回遵循：生成草稿 → 核对来源与掌握状态 → 按另行确认的授权规则确认 → 写入可供下场读取的版本。确认机制未收口前，草稿不得自动成为正式记忆；孩子原解释是否另存全文仍待讨论，不影响保存经确认的解释要点与来源。

下一场开始时由孩子确认本次允许读取哪些记忆；新助手据此调整帮助与建议，仍重新了解本次目标和意愿。旧推测不能自动升级为事实，旧角色不能自动成为本次分工。允许更正、撤回和删除，并同步处理由它衍生的缓存与报告可见状态。

## 九、建议的多 Agent 分工（讨论稿）

前台保持“当前阶段助手”，后台可按职责分工：

| 建议角色 | 输入范围 | 输出 | 不能替人做的事 |
|---|---|---|---|
| 团队决策 Agent | 本场获准共享的速读卡、规则、时间、成员当前意愿 | 选题建议、风险与任务草案 | 自动定题、发布任务或确认验收 |
| 成长解读 Agent | 本人证据包、复盘、经授权的必要团队背景与赛事结果 | 给孩子/家长看的自然语言报告草稿 | 给队友建画像、把 AI 代做算作独立能力 |
| 比赛记忆 Agent | 经确认的本人事实、报告中的证据性结论、理论记录 | 面向下一场助手的结构化记忆草稿 | 把未证实推测写成长期能力标签 |

建议增加**证据整理与校验环节**：先按授权取材料、核对来源和矛盾，后检查生成内容是否越过证据。基础工作可由普通程序完成；需要语义复核时再考虑专用 Agent，不必为每一步都增加一个模型。

不同职责可以由同一个模型的不同提示与权限承担。多 Agent 不等于多模型，也不等于多份独立证据；一个 Agent 的推测被另一个引用，不能算再次验证。

共享同一事实存储，按人、队、比赛与用途裁剪输入；不共享无限聊天上下文，不另外发明一套可编辑任务状态。统一调度记录所用材料版本、模型、成本来源与错误，设置调用与轮次上限；未完成校验的草稿不得直接发布。

本轮仅讨论该分工，不引入运行框架、不自动调用这些角色。模型供应商、角色是否拆开、预算与复核方式留在实施规格中确认。

## 十、报告发布与送达

报告草稿与发布是两个独立动作。建议流程为：复盘完成 → 固定本场证据版本 → 生成与校验草稿 → 孩子核对事实并可提出异议 → 有权限的人确认发布版本 → 已验证关联的家长在家长端查看。

以上发布流程是建议方案，确认发布人的身份、未成年人/监护人授权流程及异议处理责任须在家庭试点前收口。家长关系由后端验证，不能只靠“我是家长”按钮；家长不得访问未关联孩子或队友的私密资料。

“发到家长端”默认指账户内可查看，不自动等同于短信、微信或邮件推送。通知渠道需另行明确授权与送达记录；通知成功也不证明家长已阅读或理解。

报告生成失败不影响比赛成果与复盘保存，允许从同一证据版本重建，不重跑比赛或模型实验。重建、补录名次、更正事实产生新报告版本，旧版本和更正理由可追踪。

## 十一、验收底线

- 三种工具分别完成安装、实际客户端加载、一次授权回合上传和记录号回读；未授权回合不上传，不能用 Codex 的结果替代另外两个工具。
- 手机/远程网页的安装引导不会误写服务端项目配置当作“已安装到孩子电脑”。
- 同回合重试、断网补传、超长分段、脱敏及只得摘要等情况真实可辨，撤销后停止共享。
- 队友可先看简短信息并核对原文；摘要遗漏关键约束时可以纠正，结论版本随之更新。
- 未达到选题阶段条件不能自动分析；模型建议不能直接变成已确认方向、任务或验收。
- AI 给出完整答案但孩子没有解释或实际操作时，报告不能记为独立掌握；没有名次、起点或完整记录时仍诚实说明未知。
- 名次、消息数量、反复引用同一 Agent 推测均不能冒充个人能力证据。
- 服务端拒绝跨家庭访问、未经授权查看队友原文及无发布权限者发布报告；更正或撤回后衍生内容被标记复核。
- 家长能用自己的话说出孩子做了什么、获得什么帮助、下次可尝试什么；下一场助手读取的是已授权、带证据与不确定性的记忆。

## 十二、建议实施顺序与待讨论项

先补连接器端到端可靠性与队友速读卡；再接个人贡献/复盘证据和一份可追溯的报告样稿；随后落地家长身份、发布与查看；最后实现跨比赛记忆，并按实际需求拆分后台 Agent。

待讨论而非默认定案：完整回复共享的默认方式、不同年龄的确认流程、谁负责复核发布、家长能展开到哪一层证据、数据保留与删除期限、理论记忆是否同时保留孩子原解释、所需角色数和模型预算。
