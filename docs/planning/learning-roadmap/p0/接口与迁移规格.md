## 2. 协议总则及所有权

新前缀固定为 `/api/learning/v2`；P0 版本是提案，不表示现有 `/api/openapi.json` 已出现这些接口。同源 JSON、UTC 带时区 ISO 时间、随机不含身份含义的 ID。成功资源返回 revision；列表返回 items/next_cursor（游标不透明，服务端限制数量）。接口拒绝未声明字段；所有归属从会话和父资源推导，不能接受客户端 family_id/actor_id/owner_id/paid/passed 作为权威。新表建议 `learn_` 前缀，与 learning_sessions 分离，且无 squad_id 必填。

资源归属链是 family → learner → enrollment → run → attempt/artifact/check/reflection → report。每次校验全链，不能只验证路径中 learner 然后按裸 artifact_id 查询。reviewer 按有效案件分配读取最小材料；model worker 按不可转移的运行任务读取。ID 不可枚举只是防御补充，不能替代权限。

读权限矩阵（以下每项中的写权限为穷举，其余默认拒绝）：

- 未登录/旧 Bearer/旧 demo session/分享链接持有人：只可读取 session-bootstrap、已发布课程目录及无私人数据的客户端配置；不能调用 v2 私人读写。旧登录成功也不自动证明 guardian_link。
- `manager`：已认证 people；可以建立本人家庭、孩子档案与关系声明，提交同意、申请课程权益、进入孩子模式；仅在 verified 关系及相应 consent scope 下看摘要、已保存作品、已发布报告。关系 pending 时只看自己创建的声明与最少档案；不能借 pending 读孩子学习记录。不能修改孩子作品、代写过关、核款或审自己的关系。
- `learner`：绑定唯一 learner_id，读本人课程、起点、尝试、作品、帮助、本人报告事实核对预览；写本人起点、尝试输入、作品版本、解释/迁移、求助及报告异议。不能读家庭账务、同伴资料、增加额度、改同意、发布报告。
- `staff`：账号拥有后端授予的 scope；`relationship_review` 仅核验分配关系案，`learning_review` 仅审分配作品案，`report_review` 仅审分配报告案，`report_publish` 仅发布已获准快照，`support` 仅处理分配求助，`usage_reconcile` 仅看分配运行用量案件。是否同一人具多个 scope 由排班决定，不由 UI 角色名决定。
- `content_publish` / `payment_verify`：另行授予；P0/P1–P4 不暴露收费核款接口，内容通过 S00 管理的版本化导入发布；运营不因此获得孩子完整私聊。P5 订单接口另补，不复用 enrollment 开通为“到账”。
- 服务 worker：服务端任务租约 + fence 校验，不能作为人的浏览器会话，也不能替 reviewer 发布或把 Agent 建议写入 passed。

监护记录至少含 declared_relationship、status=pending|verified|rejected|revoked、verification_method、evidence_ref、reviewer_id、reviewed_at；证据引用存受限材料，不在普通响应暴露证件。人工审核结果表示按项目流程核验，不宣称法定身份认证。MVP 不提供“认领一个现有孩子 ID”或多监护人邀请；新建孩子默认新资源，已有关系的合并另行评审。

## 3. 会话迁移、旧标签页与迟到请求

这是 P1 的中央接线依赖，不能由独立领域模块自行绕过。

1. 新浏览器绑定随机 `browser_context_id`，服务端存当前 mode、mode_epoch；凭证是不可读的 HttpOnly、Secure、SameSite=Strict、Path=/、无 Domain 的 `__Host-songban_session` cookie。登录前 bootstrap 发受保护的匿名绑定与 CSRF token；写操作核验精确 Origin、CSRF token 与服务端绑定。无 cookie / 无 Origin 的浏览器写入不能退回 Bearer。loopback 开发专用例外须独立配置且禁止公网，不在本文捏造生产域名。
2. `/sessions/authenticate` 使用现有密码哈希/一次性验证码核验服务；password 或已验证的一次性 challenge 必须有新鲜证明，旧 Bearer 不可交换管理 cookie。challenge 绑定浏览器/用途、单次消费。失败频控复用旧机制；禁止把明文密码、OTP、会话 cookie 写入幂等正文或审计。MVP 凭据请求只留带密钥指纹、已消费 proof_id 和结果引用。
3. `/sessions/enter-learner` 在一个事务中检查关系、同意、learner 与 expected_revision，递增 browser mode_epoch，撤销该浏览器全部 manager/staff session 与 refresh grant；保守递增该 people 的 legacy_auth_epoch，并把 people.token_hash 换成从不返回的随机墓碑。旧 token 没有浏览器绑定，故这一步会使该账号其他旧网页登录也需重新认证；这是明确的兼容成本，不静默承诺“仅影响当前标签”。创建单一 learner session，返回 cookie 及新 session epoch。
4. 所有已注册的账号鉴权路径都必须纳入中央模式防护，包括 core、studio/account、materials、workbench、recap、parent-report 及旧模式可启用的接口。孩子 cookie 访问旧账号 API，即使附带 Bearer / sbconn_ 也拒绝 `child_mode_restricted`；sbconn_ 本身永远不进入 v2。原连接器后台任务继续按原凭证权限工作，不获得家庭数据；进入学习不会新增/删除个人插件。
5. 切换与旧受权请求提交通过同一持久 epoch/fence 排序：在事务内重查会话撤销、模式 epoch、账号 epoch、关系/consent revision，持锁提交。切换先提交，则旧写入 401，不能留模型触发、权益、报告等后续副作用；旧写入先提交，则是切换前已完成事实，保留审计。不能只在请求入口检查一次。外部调用前再次验权且写 dispatch 标记；已发出的调用无法保证撤回，后续结果与费用按第 7 节归档，禁止成为新的家长管理动作。
6. 所有新私人读取在构建响应末尾重验 epoch；旧读取适配同样处理，禁用私人响应缓存。已经发到网络的旧内容无法撤回，因此 UI 每次请求捕获身份 epoch，切换同步清 state、AbortController、local/sessionStorage 私有缓存与旧 workbench，停轮询；BroadcastChannel/storage 通知只用于体验。迟到响应、bfcache pageshow、visibilitychange 一律先核验当前 `/session`，epoch 不符丢弃，不重新灌回旧内容。不能承诺擦除用户此前已下载资料。
7. 普通请求不能刷新认证 cookie，防止旧响应 Set-Cookie 盖回高权限；有权轮换 cookie 的端点仅 authenticate/enter-learner/logout，提交必须检查 mode_epoch。旧轮换响应即使晚到也只能携带已撤销 cookie，服务端不接受。收到身份失效先读当前 session，禁止自动使用旧 token 恢复管理。
8. 返回管理仅走显式重新认证，成功时撤销当前 learner session，递增 epoch，清孩子缓存后建立 manager/staff session。staff scope 由服务端 grant 选择。child 模式下旧 login/register/访客 bootstrap 等发凭证路径不能旁路提升权限，统一转入该显式流程；允许用户输入新证明重新登录，不能凭旧 token/隐藏表单升级。
9. 会话切换幂等记录含前后 session_id；响应丢失后，旧凭证不能重发取得新的权限。浏览器先 GET /session：新 cookie 已生效则恢复；否则重新认证。相同 request_id 仅对当前仍有效且有权的会话重放资源引用，绝不保存/重放明文凭证。

有效期、认证证明新鲜期、刷新策略最终由 S00/S04 冻结；在未设定且未经越权/并发验证前不得打开真实家庭入口。UI 清理不能替代第 3–5 项。

## 4. MVP 端点与前端操作

完整字段、类型、权限、成功码见 `contracts/openapi.proposed.json`；无 Bearer 安全方案，所有写入 request_id，修改带 expected_revision。端点分组如下：

- 身份：GET session-bootstrap/config/session；POST sessions/authenticate、sessions/enter-learner、sessions/logout。
- 家庭：GET/POST families；GET families/{family_id}；POST families/{family_id}/learners；GET/PATCH learners/{learner_id}/profile；GET/POST learners/{learner_id}/consents；GET consent-texts/{consent_version}；POST consents/{consent_id}/revoke；POST learners/{learner_id}/enrollments。
- 首页/起点：GET learners/{learner_id}/home、learners/{learner_id}/start；PATCH learners/{learner_id}/start。0.2.0以PATCH替代初稿PUT，没有已上线API需兼容。GET courses、courses/{course_version_id} 返回发布内容与三关 task/tool/rubric 版本。
- 任务：POST learners/{learner_id}/runs；GET runs/{run_id}；POST runs/{run_id}/attempts；GET/PATCH attempts/{attempt_id}；POST attempts/{attempt_id}/model-runs；GET model-runs/{model_run_id}。
- 四角色：POST runs/{run_id}/help；GET runs/{run_id}/help。服务端将 role_id 和 prompt_version 固定在帮助事件，Agent 可调用同一受控 model-run 引擎；三级静态帮助不消耗模型，AI 模式仍执行预占/unknown 规则。
- 作品：POST runs/{run_id}/artifacts；GET learners/{learner_id}/artifacts、artifacts/{artifact_id}；POST artifacts/{artifact_id}/versions；POST runs/{run_id}/checks；GET checks/{check_id}；POST runs/{run_id}/reflections。
- 人工：POST runs/{run_id}/cases；GET cases、cases/{case_id}；POST cases/{case_id}/claim、transfer、resolve。case 响应对孩子只露状态、处理人公开显示名、due_at、下一步，后台才看到分配权限和必要审核依据。
- 报告：POST runs/{run_id}/reports；GET reports/{report_id}；POST reports/{report_id}/disputes、submit-review、reviews、publications、revocations；GET learners/{learner_id}/reports。草稿只给本人有限事实核对/已分配复核者，家长列表和详情只给 published；revoked 统一 410，不向无权限用户泄漏存在。
- 用量：GET learners/{learner_id}/usage；GET reconciliation-cases/{case_id}；POST reconciliation-cases/{case_id}/resolve，仅 usage_reconcile 可处理。孩子看到可用/不足/待核对状态；金额与供应商凭据不得下发孩子。

L01“开始/继续”读取 home.current_action → 建 run 或回到 run；L02逐主题保存起点PATCH start；L03先建/保存attempt再model-runs、保存作品版本、checks（须明确purpose）；L04读取artifact/check并提交reflection（含改动解释和迁移尝试引用）；F01 family/home/published reports；A01 cases/reviews/publications/reconcile。返回管理只能authenticate，所有界面不能PATCH status=passed。固定路由为 `#/learn`、`#/learn/start`、`#/learn/run?id=…`、`#/learn/works`、`#/family`、`#/learning-admin`。

课程 enrollment 创建仅在已有试点 grant 或已核验 entitlement 下生效；未知/未授权返回 403 entitlement_required。P0 不提供自发 grant、购买、补额度或付费核款接口。后台版本化导入与试点 grant 由将来 S00 的受审运维入口管理，不能在 seed 文件预埋真实家长。每个 learner/enrollment/course_version 的活动 run 唯一；已有未结束 run 时返回该 run，不因换 request_id 重建课程进度。

### 家庭与授权刷新恢复（0.2.1，最小增补）

Session不另塞家庭权威快照。管理者清空缓存并新鲜认证后，GET `/families`由服务端按当前manager的owner_person_id返回本人家庭；无家庭为items=[]，MVP最多一个，next_cursor=null。不接受user_id/owner_id/actor_id过滤，也不提供跨用户搜索；孩子与staff不得调用此入口。查询只读、no-store，前端不用localStorage里的family_id作为恢复前提；401/403/服务失败不当作空列表。家庭创建另由唯一owner_person_id约束保证至多一个；新request_id重复建家庭返回409 family_exists，同request_id按原幂等结果恢复。

从返回Family.learners取learner_id/revision，再GET `/learners/{learner_id}/consents`。仅有效manager的本人关联范围或具有consent_read且正分配该案件的获准人员可读，不能由“老师/运营”角色名推得权限。verified管理者看获准记录，pending只看submitted_by=当前actor的本人既有记录，没有则空列表；pending只读不授予新的提交权限（POST仍要求verified）。孩子会话拒绝，跨家庭/无关系404。摘要只含consent_id/revision、learner_id、consent_version、所选scopes、active/revoked、记录时间、text_sha256和effective_scopes，不含成人联系方式、其他监护人身份、证件或原始核验材料。

授权列表按recorded_at降序加id稳定排序，支持同归属绑定的cursor/limit；由服务端计算effective_scopes，不能把历史status=active或用户勾选的scopes当作当前有效授权。pending/rejected/revoked关系、撤回记录、未获批准/已撤下文本不产生有效范围。前端可直接用返回的consent_id/revision提交撤回，历史记录不会被“最新版本”覆盖。

Config.consent_version仅标识当前建议展示的文本版本，不代表获批。GET `/consent-texts/{consent_version}`返回该确切版本的locale/title/text/scope_purposes、text_sha256、approval_status、approved_at和acceptance_enabled；没有任何私人账号信息，可公开读取已配置版本。正文与用途以UTF-8 JSON固定键顺序locale/title/text/scope_purposes计算SHA-256，数组顺序保留。正文或用途变动必须新版本，批准/撤下状态是另有审计的元数据；旧授权保持原version/hash。读取历史同意必须用其版本，不自动替换成Config中的最新文本。

UI只能呈现服务端原文和用途，不自行撰写、拼接或让模型补“法律确认内容”。本包样例全部是**研发草案，未获真实试点批准**，approval_status=draft、approved_at=null、acceptance_enabled=false；正式文本仍由产品及实际责任人收口，缺文本或未批准时显示待确认，不开放正式授权按钮。真实POST consents须当前文本approved_for_pilot且acceptance_enabled=true，结合verified关系和文本中允许的scope；服务器绑定版本/hash，不接受客户端改写文本或批准状态。draft/withdrawn以及隔离fixture不能签发真实权限。

恢复链为authenticate → GET families → GET family（如需详情）→ GET learner consents → GET consent-texts/{记录版本}；新确认另读取Config指定版本。UIA-13/14映射已更新。examples提供家庭、授权摘要、版本化草案、pending空列表；RECOVERY-01要求实现后清缓存/重登、两家庭隔离及角色限制验收。离线样例与schema检查不证明实际后端恢复或权限实现。

### 起点逐主题草稿（0.2.0，关闭 UI-Q1 / D-S01-06 的契约缺口）

GET start 始终给出完整 `answers` 快照和服务端派生字段。六个主题为 age_band、experience、interests、help_preference、mini_attempt_text、chosen_start；新记录 revision=0，各主题都是 `{state:unanswered,value:null}`。PATCH SaveStart 只提交本次编辑的 `answers` 子集，至少一个主题；未出现的主题保持原值。每个出现的主题作为整体替换，不再合并其内部state/value，避免旧答案残留。客户端不得写completion/recommendation/missing_fields等派生字段。

每个答案的语义独立：`unanswered/null` 表示尚未回答，PATCH中显式发送表示清空该主题（旧修订仍留痕）；`skipped/null` 表示本人明确选择“暂不填写”，不能由超时或没点按钮推断；`answered/value` 表示实际输入/选择，value必须符合该主题类型。小尝试answered不可为空串或null；用户可跳过。interests answered/[] 表示明确选“暂无兴趣选项”，不能代替未答。年龄仅使用服务端已配置选项，具体招生范围仍未冻结。

chosen_start额外允许 `accepted_default/value/recommendation_revision`：只有本人点“采用当前建议”才产生。它必须单独PATCH，且recommendation_revision=expected_revision=服务端当前推荐版本，value必须等于该版本推荐；过期返回409，不把新推荐当旧选择。`answered` 表示自行选定。未选、清空或跳过仍保留null；服务端可用effective_start=guided、effective_start_source=conservative_fallback开始教学，但不得把该兜底写成孩子已确认chosen_start或help_preference。

`missing_fields` 精确列unanswered主题；`skipped_fields`精确列skipped主题。全部未答为not_started；存在未答且至少一个已答/跳过为draft；全部主题已有回答/明确跳过为completed或completed_with_skips。这里只表示起点问卷的处理程度，不是能力、学习过关或“已完成小尝试”；mini_attempt_status单独为not_attempted/skipped/answered。missing_fields用于补充提示，不阻止在有效授权下采用保守起点进入首课；不反复强迫填选填项。

推荐与本人选择分别保存。0.2.0采用可版本化的确定规则：仅当前experience及mini_attempt_text均已答、且规则能形成建议时可记recommendation_basis=rules，并精确列这两个recommendation_source_fields；材料不足或规则无结论时recommendation=guided、basis=insufficient_evidence、sources=[]。规则版本和起点revision同存；不使用年龄判能力、不调用模型来完成静态小尝试、不把模型故障解释为小尝试没完成。具体教学推荐映射由S01/S00冻结配置，未配置时保守降级。

PATCH事务：鉴权/幂等/expected_revision → 只合并出现的主题 → 校验明确采纳推荐的旧版本 → 保存不可变修订/新revision → 计算missing/completion/recommendation/effective_start → 返回完整Start。所选路线是本人事实，后来推荐改变不覆盖本人选择；accepted_default保留当时的recommendation_revision。刷新GET返回同一已保存快照。`examples.json`含“首步暂不填年龄，其余仍未答”的PATCH与恢复响应，以及显式跳过小尝试、采纳推荐的独立请求；`contract-cases.json`验证缺失字段不能被清空及未答不能伪装成完成。

### 与 S01/S02 的交叉核对补充

0.2.1本包共66个拟议操作、100个schema。`contracts/ui-actions.json`将UIA-01–18对应到operation_id；UIA-18的核款/退款写入明确留P5，当前只读取权益和兑换已有grant。回顾建议按S02使用 `#/learn/run?id=…&view=review` 子视图，作品使用不透明artifact_id/version_id；不另占用比赛 `#/review`，只读导航不触发过关。路由命名仍由S00最终冻结。

第一关独立requirements：GET/PUT `/runs/{run_id}/requirements`保存材料、七项事实、目的/表达、材料定位、本人确认、帮助披露。首次GET返回404尚未建草稿，PUT expected_revision=0；草稿可不完整，confirmed=true必须完整。保存/确认本身不解锁，再POST checks(stage=clarify,purpose=advance)按R01/R02事务推进；purpose=preflight只反馈。不会伪造尚不存在的作品ID。

作品固定字段对齐 S01：title/audience/date/start_time/end_time/place/preparation/invitation_line。日期/时间是材料中的文本，不受用户电脑时区转换；事实比较规则由内容版本定义。标题40字、邀请语160字、解释300字为候选工程容量，不是理解分数。材料 GET `/courses/{course_version_id}/materials/{material_id}` 仅输出当前任务获准材料，绝不整包下发 reviewer_only 标准答案。`fixture` 是内容包标记，接口 mode 使用 mock；界面必须明确显示模拟，不能将 fixture 当 live。

第二关固定attempt_revision/requirements_ref与模型输入，保存artifact_version后GET指定版本，服务端返回绑定会话和版本的read_receipt_id；孩子显式POST readbacks记录回读。回读是操作证据，不证明理解。check(stage=create,purpose=advance)要求已知成功运行、当前作品与同版本回读；预检可返回缺口但不推进。P2 mock/replay仅通过协议验收，正式教学live操作事实须P3验证。

第三关POST self-checks先独立保存字段、本人判断、理由和材料定位，无需先做迁移；新版作品记录previous_artifact_version_id、change_intent、change_explanation、help_disclosure。迁移是kind=transfer、task_id=S3.3、材料MAT_B的attempt，transfer_response单独保存结构化事实、本人邀请语、至少两处变化解释与帮助披露；不会替换主作品MAT_A。最终reflection固定transfer_attempt_revision/self_check_ref/artifact_version，正式check(stage=review,purpose=submit_review)固定整组精确id+revision；预检允许未完成迁移/反思。人工结论须M1–M4每项一条supported、有效source_ids，缺一项不passed。

0.2.0补齐原样采用AI候选的 `authorship=ai_candidate_unedited`；服务端核对候选/保存内容及版本，不能把原样候选记为child_edit或ai_candidate_edited。Attempt、Reflection及作品保存统一使用HelpDisclosure，移除旧窄枚举declared_help；支持unknown、adult_content、peer_content、ai_content、example_reference等，引用示例必须携带可访问的example_source_ids。原样候选的作者来源不会因未报告额外帮助变成独立创作。H0/none_reported不能推断线下无人帮助；来源/帮助历史均保留。

case 补充 evidence（按分配最小投影）、extensions（原期限保留，理由与通知）、messages（补充原案件）。同 learner/run/reason_category 已有未结求助时复用原案，不能换 request_id 刷单。返回 allowed_actions、saved_at、support_contact_label，不把空负责人包装成已安排老师。allowed_actions 使用 operation_id 白名单，资源动作另用 Action.type 白名单，任意字符串不得执行；它只是 UI 提示，后端仍重新鉴权。

补充 revision 归属：requirements PUT 为 requirements revision，首次为0；self-check 新建为 run revision；readback 为 artifact revision，回执不可用于其他会话或版本；case extensions/messages 为 case revision。历史 attempt 每次 PATCH 生成不可变修订保留输入；新模型只能固定一版，保存作品不能引用被后续修改覆盖的输入。

刷新恢复由 Run 返回 current_attempt_ref/current_requirements_ref/current_self_check_ref/current_reflection_ref/current_transfer_attempt_ref/current_artifact_id/active_model_run_id；再 GET 相应资源。补充 GET self-checks/{id}、reflections/{id}，不依赖浏览器记忆最后一次 POST 回执。作品存 template_version_id，帮助存 task_id/task_card_version，旧资料无法由新版模板或提示静默替换。

## 5. 请求、错误、幂等与版本

request_id 是客户端生成的随机稳定操作号，不作归属证明。唯一键 `(actor_id, effective_scope_id, operation_id, request_id)`；effective_scope_id 含 learner/family，资源路径纳入指纹。规范化 JSON 后计算指纹（顺序无关；保留值与显式 null；拒绝重复 key、非有限数），不含 CSRF、cookie 等传输数据。

先鉴权/验证结构，再在事务内查幂等记录，最后校验 expected_revision。同 ID 同正文返回原资源及原结果码/Location，不再次写入/扣额/调用；资源状态演进从 GET 获取。若访问权限已撤销则拒绝，不能从缓存泄漏旧结果。同 ID 异正文为 409 idempotency_conflict。并发插入靠唯一索引收敛；后续异步工作始终以稳定 resource_id 查状态。未知请求不能换 ID 绕过“同 attempt 存在未结算运行”的约束。

expected_revision 针对路径聚合根：enter-learner/logout 针对 session；start 针对 start；attempt PATCH/model-run 针对 attempt；run 的 artifacts/checks/reflections/reports/help/cases 针对 run；artifact version 针对 artifact；审核/发布/撤销针对 report；case 动作针对 case。POST 新资源若影响父资源也携带父 revision；事务返回资源与 parent_revision。不可变内容没有 PATCH。

错误结构统一 error.code/message/retryable/recovery/current_revision。current_revision 仅对有权资源返回；所有字段在 OpenAPI 约束。常见语义：401 session_expired/session_revoked；403 forbidden/consent_required/entitlement_required/child_mode_restricted；404 resource_not_found（包括跨家庭）；409 revision_conflict/idempotency_conflict/active_run_unknown/evidence_stale/invalid_transition；410 report_revoked；422 invalid_input/invalid_sources；423 learning_paused；429 rate_limited；503 model_unavailable/support_unavailable。预算不足用 409 budget_exhausted，不声称付款失败。

网络断开先读服务器已保存 attempt 与 request 对应资源；未知写入允许同 request_id 重交，不自动换 ID。模型受理成功一律 202 + model_run_id，页面轮询 GET；供应商结果未知是资源状态 unknown，不把 504 当“可重新生成”。冲突先读新版，保留本地待合并输入，经用户确认后换 request_id 与 revision；不能自动覆盖。

## 6. 三关、作品和检查事务

course_version/lesson_version/task_card/tool_card/rubric/prompt 都有不可变版本。run 固定课程；S01 最终材料 ID 通过版本化内容包交付，本协议不编造已批准年龄段。阶段码 `clarify`、`create`、`review` 仅作为拟议稳定键；S00 与 S01 对齐后冻结映射。

关卡状态 locked→available→in_progress→pending_review 或 needs_practice→passed；服务端根据课程 rubric 决定转换，不能按对话数/输出长度评分。起点推荐可调整，不删除实际经历。第三关包含独立改动、解释、换材料迁移 attempt，以及帮助记录；缺少则 checks 返回未满足项或人工待办，不能用作品漂亮来放行。

保存作品事务：验权+revision → 插入不可变 artifact_version（结构化文本、input/attempt/model refs、作者来源、help refs）→ 更新 artifact.current_version/revision 与 run revision → 写 learning_event/幂等结果。版本内容不能执行 HTML/JS。model 输出作为候选，不自动覆盖孩子作品。成人代录标 `adult_transcription` 并留 actor，不冒充独立完成；MVP 由孩子会话提交本人确认的代录说明，家长不直接修改作品。

### 检查意图与事务（0.2.0，关闭 UI-Q2 契约缺口）

POST checks强制 `purpose=preflight|advance|submit_review`，缺失或不合法组合返回422。rule_result为pass/needs_practice/incomplete/unknown，仅表示规则反馈；必须同时看progress_effect/outcome/case_id，不能看到pass就展示过关。Check保存purpose、证据hash、evidence_complete、model_state及本次操作结果，human_result与规则分开。AI建议单独标ai_suggestion，不作人工verdict。

- **preflight，任一stage**：校验所提供引用的归属和当前revision；可缺requirements、作品、自查、反思或迁移，返回缺口。创建check反馈/幂等记录/审计，可递增run的技术revision，但不改关卡状态、artifact检查适用性、passed或下游解锁。case_id/human_result/reviewer_available必须null，progress_effect=none，outcome=feedback_only；不查询/锁定值班，不创建人工案。即使证据完整且规则pass也只反馈。旧passed事实也不由预检撤回。
- **advance，仅clarify/create**：入口鉴权、run expected_revision及精确证据检查后，在同一短事务中重查授权/证据当前性，插入正式check与幂等结果；clarify按已确认requirements的R01/R02，create按当前要求、成功运行、保存/回读的R01/R03/R04。条件成立时写lesson_progress=passed、下游available、learning_event和审计并提交，progress_effect=passed_and_unlocked/outcome=advanced；第一关不要求作品。条件不成立只返回缺口或补练，不产生任何人工案。规则明确发现可修改错误可记needs_practice，资料缺失则blocked_evidence且progress_effect=none。预检快照不能绕过此次重新校验。
- **submit_review，仅review**：请求结构必须带完整requirements/artifact/self-check/reflection/transfer/readback引用；实际服务器再验证当前版本及R01–R08（包括S01更新的R05全体事实逐项对照A）。evidence_complete只表示确定性前置齐备，不代表人工M1–M4已经通过。仅规则pass、模型succeeded且有效值班/负责人/due_at可用，才在一个事务中锁定可接案安排、创建或返回同证据hash的唯一人工案、关联check并变pending_review；返回progress_effect=pending_review/outcome=awaiting_review及case_id，绝不直接passed。缺引用结构422、过期/跨归属拒绝；实际材料不足则保存blocked_evidence反馈且无案件；无值班则保存blocked_support、reviewer_available=false、progress_effect=none、case_id=null，不能显示“已交老师”。

检查反馈资源创建成功返回201，即使outcome为blocked_support/blocked_evidence，也仅表示反馈已保存；不等于送审成功。该行为区别于单独请求人工帮助NewCase的未配置503。服务器本身不可用仍503；任何网络未知先同request_id查询/重交，不生成第二单。通过唯一(run_id,stage,evidence_hash,case_kind)约束避免用新request_id重复派单；来源变更必须新check，旧案标需重确认。

如果依赖模型处于pending/running/unknown，rule_result=unknown、progress_effect=none、case_id=null：预检为feedback_only，正式动作为blocked_unknown。它表示等待已保存运行/核对结果，不是孩子学习失败；不把预算释放、不自动重新调用、不进入人工作品审核。unknown核对案件本身依第7节已单独存在。供应商已知失败才按缺口反馈，不把所有失败写成“不会做”。

人工通过事务：重查案件分配、check 和当前 artifact/rubric/evidence hash → 写不可变人工决议 → 更新 check/lesson_progress → 解锁下一关 → learning_event/outbox 一起提交。旧版本被修改后审核提交返回 evidence_stale，旧审核留历史，不推进最新作品。

ResolveCase的learning_review分支可提交decision=needs_information，将已填M1–M4分项和unclear/source_ids持久保存，案件仍claimed、过关状态不变，反馈具体补问和截止时间；不强迫老师二选一结案。后续完整提交沿当前case revision更新，历史发现保留。decision=passed在schema和服务端均要求M1–M4恰好各一条supported且来源当前有效；重复项、缺项或unclear不能通过。Check.progress_effect记录发起该check时的事务效果，后续人工结果另由human_result及最新run进度呈现，不改写预检历史。

改版后旧 passed 事实继续保留在原版本；当前成果投影改为 recheck_required，当前关显示 needs_practice/需要重查。已打开的下游草稿仍可编辑；依赖旧检查的下游新过关/最终发布暂停，等新版本重查明确恢复。不能无提示删除历史成果或将旧 check 贴到新版本。已发布报告保持旧快照并显示 evidence_changed，需要更正时生成新版本或撤销；隐私/同意撤回则立即停止可见，不能只打旧标记。

## 7. 真实模型、预算及 unknown 核对

mode 固定 mock|live|replay；live 的供应商、模型白名单、配置版本、费用规则、预算、人工值班均未配置时拒绝发起，不能用 fixture 补。actual_model 未获真实响应时为 null。replay 引用源 model_run_id 与原时间，不调用供应商、不扣真实额度；mock 的零真实扣额不是 live 成本零的证据。

T1 事务：验 session/consent/enrollment/source access/attempt revision → 已保存输入引用 → 配置/预算版本快照 → 唯一 model_run(pending) + reservation(held) + dispatch outbox + 幂等记录。预算单位为服务端报价定义的整数 unit，不把 unit 宣传为人民币；收费估值未知为 null。预占检查 `available = granted − settled − held`，SQLite 用短写事务条件更新，余额不可为负。每个 attempt 至多一个 pending/running/unknown 实际调用，帮助请求同样受 learner 并发与额度限制。

T2 事务：worker 用 lease_token/fence 抢占 pending，重新核验授权/配置开关，写 durable dispatch_started_at 后提交；事务外调用供应商。未标 dispatch 的待办可安全恢复；已标 dispatch 的失联工作，即使租约到期也不能再次发出，转 unknown。供应商明确支持幂等才可使用稳定 provider_request_id 查询或受控重放；否则不承诺外部严格 exactly-once。

T3 事务：匹配 fence、provider_request_id、状态 → 保存响应及 output_hash/actual_model/usage_source/truncated → model_run succeeded 或已知 failed → 用量 ledger 唯一结算（model_run_id + settlement_kind）；释放剩余预占；候选输出与 usage/audit 同次提交。响应格式拒收但已产生费用，仍登记用量；失败不是默认免费。确认未发送/未计费才可直接释放。

可能已送达后 timeout/进程中断：model_run=unknown，reservation 保持 held，输入不丢；同事务创建 reconciliation_case，要求有 owner_id、due_at、escalation target 和人工退出路径。派单规则及实际人未定，live 必须关闭；不能随意填写“24 小时处理”冒充承诺。

核对 `/reconciliation-cases/{id}/resolve`：证据是供应商查询/账单/可核对响应；accepted_result→succeeded 并结算，confirmed_no_charge→failed 并释放，confirmed_charge_no_output→failed 且结算（无可用作品），administrative_adjustment→failed 并以独立 adjustment 处理预算。最后一种 usage 仍可 unknown、cost=null，不能称真实费用零；需要权限、理由、引用、审计。到期升级仍 unknown，不按时间自动释放。重复结算/迟到回包只能一次入账；已人工结案后的冲突回包开启差异案件，不静默覆写。

若在途授权已撤回，已发生费用仍核对；响应放到受限运行归档，标 visibility=restricted，不自动写孩子作品/过关/报告。正常前端显示权限已变更与已保存事实，不能通过重放拿到被撤回内容。

## 8. 四角色及报告事务

guide 读当前动作/最小状态；tool_guide 读当前工具卡/本次输入和错误；creation_coach 读当前候选、孩子要求和被选版本；review_coach 读该作品、rubric、帮助及本人解释。共同只能读取本人明确允许来源和必要最近历史；每次记录 prompt/content 版本、source_ids、截断覆盖、帮助级别与 mode。唯一写入出口为 help_event/candidate，不能写订单、关系、任务 passed。输出白名单动作 open_tool_card、save_candidate、request_human_help，仅作为建议；正文与检索材料均不作系统指令，不接受任意 URL、文件或终端执行。

报告状态 draft→pending_review→published，生成失败为 failed；退审回到新 revision 的 draft；published→revoked。另设 generation_status=pending|running|succeeded|failed|unknown，避免把未知模型结果误写 failed。报告生成也走第 7 节计量引擎，但只读取已冻结事实，绝不重跑孩子的实验。

生成 T1：验证必要成果/检查/本人反思；固定 source_snapshot（作品、check、解释、帮助、起点、迁移的精确版本与可见范围），生成 draft 与 generation job。每条 observation 必须引用该快照内真实 source_ids，区分 child_statement/system_record/ai_suggestion/human_review；无证据写尚不了解，不能杜撰成长、人格或排名。验证失败不自动送审，草稿可读的范围按角色投影。

`submit-review` 原子检查生成完成、source hash、本人事实核对或异议状态，创建 report case 并进入 pending_review。reviewer 可在 reviews 中提交 corrected_observations/new_text（仍受引用校验）和 approved/changes_requested；审核写新 revision、审计，不修改旧快照。已批准 revision/hash 与待发布内容绑定。

发布事务：report_publish scope + assignment → expected_revision → 审核批准同 revision/hash → 无未处理异议 → consent/link 有效 → sources 仍在授权内且符合当前证据要求 → 写唯一 publication 与 immutable published_snapshot、audit/outbox → 状态 published。默认只在家长账号可读，不发送短信/邮件，不生成持码公开链接。发布响应包含 publication_id，不表示家长已阅读。

撤销事务：有权 reviewer/publisher 或已验证管理者的撤回请求 → publication revoked_at/reason + report revoked + visibility cache version 更新；后续访问 410。同意撤销/关系撤销必须同事务撤销关联 learner sessions、停止新的 live、失效报告访问并登记派生审计；不删除预算账本、作品历史或恢复旧 token。无法撤回此前下载副本。更正/重建生成新 report_id，旧 report 与其来源仍可审计。
