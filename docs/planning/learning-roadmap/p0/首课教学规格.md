# P0 首课教学规格：班级活动邀请卡

文档版本：`invitation-lesson 0.1.1`；日期：2026-11-02；负责人：S01（规格编写），教研复核人待产品负责人指派。本次同步 S03 0.2.1（继承0.2.0教学语义），内容包、材料及 rubric 仍为0.1.0，教学目标不变。状态：供 S00 冻结的研发候选，六项契约差异已关闭、运行待实现；未教学验收、未儿童试用、未接业务或真实模型。最终 G0 由 S00 评审，不因本文件完成自动通过。

本规格以本目录上级 01–05、P0、S01 任务为输入；不改中央接口、UI 或旧比赛角色。所有 `S1.*` 等编号是内容内稳定标识，不是已经实现的 API、数据库字段或服务端状态。数据落地名称由 S03 映射，差异见第 12 节。

## 1. 课的范围与可观察目标

孩子使用一张虚构活动资料卡，先说明要求，再用受控文本工具生成候选文案，保存为固定模板邀请卡，核对事实并亲自改一处，最后换一张资料卡做小迁移。无团队、比赛、外部账号、任意文件、URL、图像模型或代码执行依赖。不实际发送邀请。

只有一份主作品：`invitation`，保存产生不可变版本。迁移是该课次内单独绑定材料 B 的练习记录，不另建第二份公开作品，不替换主作品的材料 A。家长反馈来自本人的作品、修改、解释、帮助与检查快照。

可观察目标依次为：

1. 能从材料中选择对象、时间、地点、准备物品，说明邀请目的和一种表达偏好。
2. 能决定何时调用工具，区分候选结果与保存作品，并重新找到保存版本。
3. 能对照材料判断至少一项事实，作出有意义的修改，解释理由，并在新材料中重新选择事实。

这些是待试用的产品/教学设计目标，不是已经证实的教学效果。一次完成只能支持本课具体观察，不支持“已掌握 AI”“独立创造力提高”或跨任务能力认证。

## 2. 内容包、固定预览与来源

内容包见 [虚构材料与样例.json](content/虚构材料与样例.json)，角色卡见 [角色与工具卡.md](content/角色与工具卡.md)。课程、课次、任务卡、工具卡、角色提示、材料与 rubric 均绑定版本；修改已发布内容需新版本，进行中的课默认继续原版本。JSON 含 `reviewer_only` 审阅答案，未来内容服务必须按任务和权限投影，不能把整包发送给孩子或角色模型；尤其不能提前泄露迁移答案。即便是允许展示的错误样例，也只投影 ID、标签、材料引用和 artifact；`expected_*`、`example_reason`、`example_changed_fields` 均为审阅元数据，不下发到孩子或角色上下文。

### 2.1 两张虚构材料

- A：松果班故事交换会；对象“松果班同学”；2030年5月18日14:00–15:00；松果活动室；带一本愿意分享的故事书。
- B：星叶班纸桥挑战；对象“星叶班同学”；2030年5月25日10:00–11:00；星叶活动室；带两张废旧A4纸。

页面常驻说明：“这是练习用的虚构活动，不是真实通知。”不补真实学校、姓名、联系方式、报名链接、费用或监护关系。正文出现的新活动事实须回到材料核对，不能由模型猜测。材料被撤回或不可读取时停止相关检查并保留草稿，不把失去依据的观察发布给家长。

### 2.2 可编辑要求与作品

要求记录含：材料 ID/版本、活动名称、对象、日期、开始/结束时间、地点、准备物品、邀请目的、表达偏好。前七项事实由孩子选取或填写并确认；目的可选“让同学知道活动安排并愿意参加”；表达偏好可选“友好简短”或自行描述。选择推荐选项算“本人选择了预设选项”，不算独立组织了整段提示词。

作品字段固定为 `title`、`audience`、`date`、`start_time`、`end_time`、`place`、`preparation`、`invitation_line`。标题和邀请语可改写，其他字段须与材料吻合。预览顺序为标题、对象、日期和时段、地点、准备物品、邀请语，所有值转义为纯文本。只允许固定模板；无富文本、HTML/JS、任意链接或自由排版执行。

为开发收敛建议标题 1–40 字、邀请语 1–160 字、每条解释 1–300 字、目的/偏好各不超过120字（均为待体验校准的输入上限）。长度仅用于容量和空输入检查，绝不据此评价理解。超限保留编辑内容并提示缩短，不静默截断；朗读和大字不改变评分条件。

### 2.3 示例与本人事实

- 材料卡是课程来源，候选模型文案是 `ai_output`；保存动作是孩子的操作事实，不将 AI 文案改标为孩子原创。
- 教学样例始终带 `example` 和用途标签；“练习样例：这里预设了一处错误”与真实生成失败明确区分。样例不自动进入个人作品或报告。
- 孩子主动参考/复制样例可以继续练习，但记录被查看/引用的样例与帮助，不以复制结果满足独立修改或迁移。
- 成人只帮助打字时记录“孩子口述、成人代录、孩子已确认”；成人提供内容时记成人帮助。系统不能识别全部线下帮助，允许“不确定”，不能将未检测到帮助写成无人帮助。
- `fixture`、`live`、`replay` 必须可见。P0 JSON 全是虚构 fixture；即便含“孩子”的模拟叙事，也不能成为真实 learning_event、正式报告或真实模型联调证据。

## 3. 起点、年龄与提示

起点使用经历、小尝试和本人帮助偏好，不按年龄划能力。三种入口是“带着我做”“让我先试试”“我想挑战一下”，目标、最终 rubric 和访问权限一致，可随时改提示力度。

小尝试无需模型：展示 A，问“这张邀请卡是给谁的？同学几点到哪里？”选答或填写均可，保留答案及帮助，只产生可调整建议。暂时未答也可选择带领模式开始；不能宣称通过入学评估。

起点按 `PATCH /learners/{learner_id}/start` 逐题保存，`answers` 只传当前主题；未传主题保持原值。`unanswered/null` 与 `skipped/null` 分别表示未答与本人明确暂不答，`answered` 才保存实际内容。问卷 `completed/completed_with_skips` 不代表小尝试已答或能力通过；看独立的 `mini_attempt_status`。信息不足时可用保守 `effective_start=guided`，不能回写成孩子已选择；本人明确采用推荐时用 `chosen_start.state=accepted_default` 并绑定推荐 revision。年龄不参与能力判断，静态小尝试已答不受模型故障影响。

年龄段候选为“6–8岁／9–12岁／13–17岁／暂不填写”，仅用于表达与字量试验，不是冻结招生年龄或已验证分龄方案，不要求精确生日。成人练习使用标明的体验入口，不虚构儿童身份。P1 起点工程支持版本化可配置选项，不把本候选固化为能力/招生枚举；按中央 Q01，由产品/教研在 P4 真实试用前收口。更小年龄或特别支持需求如何服务仍待确认。

初学者默认展开当前一句任务和材料，按需进入三级帮助：H1 提问定位、H2 操作或填写骨架、H3 明确标记的局部示例。H0 表示本步骤尚无系统内容帮助；不能由 H0 推断线下无人帮忙。每次展示帮助都记录角色、任务、等级、内容版本和来源，不仅记录点击次数。

有经验者默认折叠提示，可自行组织要求、查找矛盾并比较两个表达；不增加免费模型次数，不跳过保存、解释和换材料。年龄较小者可由成人朗读/代录，仍按实际贡献描述；有阅读困难时由本人选择逐句显示，不推断诊断。

时长初值：总计约30–45分钟，三关约8–12／8–12／14–21分钟；可随时暂停并恢复，不设答题倒计时。此为排期假设，未经试用校准，不能写成学习承诺。

## 4. 第一关：说清要求

关卡 ID `G1_requirements`；孩子看到“先让工具知道：给谁、什么时候、在哪里、带什么”。主陪伴为主向导，表达时可请求创作教练。

### S1.1 读材料、挑事实

输入：A 及说明“虚构活动”。任务：“找出同学需要知道的活动信息。”孩子选取/填写活动名称、对象、日期、时段、地点、准备物品；字段不预先替孩子勾完。产出：可编辑的要求草稿及每个事实的材料定位。

初学 H1：“先找给谁看的那一行。”H2：“把对象填到‘邀请谁’。”有经验者可一次填写，并说明最容易漏哪项。检查 R02 对照材料，不用错字数量贴能力标签；错误只回到相应字段。不会时展开材料定位或暂停，原草稿保留。

### S1.2 说目的、选表达

输入：本人事实草稿。任务：“想让同学知道什么？希望语气怎样？”产出：目的、表达偏好，以及一次本人确认/编辑。初学者可选预设短语；有经验者自写并判断是否有材料外承诺。H3 只展示局部表达示例，不替孩子确认整份要求。

主行动“确认我的要求”。先保存 `requirements.confirmed=true`，取得回执后发 `checks(stage=clarify,purpose=advance)`，规则 R01、R02 及当前 revision 检查必填、材料一致和本人确认事件，由服务端决定 `passed` 及第二关解锁。保存本身与 `purpose=preflight` 都不解锁，第一关不造作品 ID。这里表示本关要求记录齐备，不是人工确认已掌握表达能力。歧义、看不懂材料或需要代录时可求助，不强制模型对话。

补练：若忘记对象或时间，定位对应材料，改后再次确认；错误尝试保留，报告不可只记录最后正确答案。修改要求后生成新 revision；已存在的生成尝试保留其原输入快照。

## 5. 第二关：操作与保存

关卡 ID `G2_create_save`；孩子看到“试着生成，再保存你要继续修改的那一张”。主陪伴为工具向导。

### S2.1 看输入并运行一次

输入：已确认要求、受控文本工具卡。任务：“看看要交给工具的要求，再点‘试着生成’。”服务端先保存输入，再校验授权、版本和预算，创建模型尝试。产出：输入快照、mode、真实响应模型（未知为空）、运行 ID、候选结构化文本及来源。

初学 H1：“按钮上写的是生成，还是保存？”H2 展示“看要求→生成→看结果”操作顺序。有经验者可先编辑表达偏好再提交，不以多次调用作为进阶要求。生成结果显示“这是工具的候选文案，还没有经过检查”。

结构不合法时保留运行记录、显示无可用候选，不执行输出。结构合法但活动事实错误可作为待检查草稿展示，标明“还需核对”，不可自动改成正确后声称孩子发现了错误。内容风险由既定内容审核处理，不因教学需求暴露应拦截文本。

### S2.2 选择、保存、重新找到

输入：候选及其固定预览。任务：“这是准备继续修改的一张吗？保存后再打开看看。”产出：本人选择候选事件、主作品 `v1`、保存回执、重新打开同一版本的操作记录。主行动“保存这张作品”；保存成功后变为“打开已保存的作品”。读取指定版本得到绑定会话/版本的 `read_receipt_id`，本人明确确认后提交 `readbacks`；预取或自动预览不记本人回读。之后 `checks(stage=create,purpose=advance)` 才请求正式推进。原样采用候选用 `authorship=ai_candidate_unedited`，不冒充孩子已编辑。

初学者对照“候选／已保存”标签；有经验者简述两者区别。规则 R01、R03、R04 及当前 revision 核对来源、结构、真实保存与回读，不以生成成功、按钮点击或动画结束代替；该关通过只表明本课操作证据齐备。回读回执仅证明版本已取回，是否理解“已保存”仍看 M2。没有保存回执不得写“已经保存”。

补练：找不到作品时主向导定位服务端当前草稿/版本；遇到保存冲突展示两份内容供选择，不能覆盖新版本。模型完全不可用时可用明确标识的样例练习编辑，但只能记录“样例操作练习”；真实工具操作目标未完成，不能用它冒充正式第二关通过。

## 6. 第三关：检查、改进、解释与小迁移

关卡 ID `G3_check_transfer`；孩子看到“对一对资料，亲手改一处，再换一张资料试试”。主陪伴为检查复盘教练；表达求助才交给创作教练。

### S3.1 自查再看规则结果

输入：A、本人 `v1`。任务：“任选一项时间、地点或对象，指出你对照了材料哪一行，并说相同还是不同。”产出：本人判断、材料定位、被查作品版本；先用 `POST self-checks` 独立保存，不要求迁移已完成。随后“检查我的结果”发 `checks(stage=review,purpose=preflight)` 产生规则反馈快照；允许缺迁移/反思，不派人工案、不改变通过或解锁。

初学 H1：“邀请卡的时间和材料相同吗？”H2 并列相应字段；有经验者检查事实之外是否有新增承诺。H3 可展示局部检查示例。自查勾选不等于客观正确；规则只能判断结构化字段，邀请语中的矛盾由人工复核。

如果本人作品事实都正确，不故意篡改生成结果制造错误。可另看 `EX_A_WRONG_TIME`：“这是预设错误的练习卡”；样例发现记录单列，之后仍需对本人作品作实质改进。

### S3.2 本人决定、修改并解释

任务：“选一处你想改的地方，亲手改好，再告诉我为什么。”事实有错可纠正事实；事实已正确可把空泛邀请语改得更具体、清楚、适合对象。仅换颜色、空格、标点或照抄教练给出的最终句子，不满足这次独立修改要求。

产出：孩子指出修改位置和意图、`v1→v2` 差异、修改来源、是否参考建议/示例、帮助记录，以及“我把___改成___，因为___”解释。不要求作文长度；允许孩子口述由成人忠实代录并确认。

初学者可看操作骨架和问题，先不显示目标答案；有经验者可说明另一种改法为什么没选。每次保存生成新版本；`v1` 的检查不能支持 `v2`。如果用了具体内容建议，允许完成本次练习但标“有内容帮助”，再在新的修改点尝试本人决策；不能隐藏帮助重置为独立。

“独立修改”在本规格中特指：该修改点由本人选择并提出修改内容，证据含前后差异、本人理由和帮助披露；操作/朗读/忠实代录可记录为辅助，内容代做不可算独立。系统记录只能支持可观察过程；人工可写“依据记录，本次由孩子提出修改”，不能证明线下绝无帮助。无法判断时保留 `unknown` 并安排短补练。

### S3.3 换材料小迁移

输入：B，空白迁移练习区。A 原要求不自动套入，B 答案不预填；不调用模型生成迁移答案。任务：“现在换成纸桥挑战。重新写清给谁、何时、在哪里、带什么，再写一句邀请语，说明与刚才至少两处不同。”

产出：B 的完整事实选择、目的/表达偏好、一句本人邀请语、至少两处变化的解释、材料定位、帮助披露；内容保存为 `transfer_response` 的不可变 revision，附在本课次，和主作品分开检查。

初学可看字段标签、回读材料或操作提示；有经验者可再判断“沿用 A 的旧时间会造成什么问题”。两者都需本人重新选择事实。H3 或 AI/成人提供了具体答案时不惩罚，记录“在提示下完成”，安排一次新尝试；新尝试仍保留帮助历史，是否已有本人迁移证据由人工判定，不承诺重复原题等同未提示迁移。缺乏可判断的新尝试时教研需补充版本化材料后才能补测，不随机让模型编题。

### S3.4 重查与提交老师

S3.1 自查与 S3.2 修改/解释分别先保存；S3.3 迁移完成后，再保存正式 `reflection`，绑定确切 `transfer_attempt_id/revision`、`self_check_ref` 和主作品版本。不提前伪造迁移 ID 来保存前置判断，也不让前序内容等到课尾才持久化。

主行动先“保存修改并重新检查”，保存各项回执后以 `purpose=preflight` 核对当前主作品 `v2` 与迁移 revision；随后本人明确点击“交给老师看看”，发 `checks(stage=review,purpose=submit_review)`。提交包含要求、运行模式、保存/回读、原/新作品、材料对照、自查、正式反思、迁移、帮助及精确版本引用。

仅确定性证据完整、规则通过、依赖模型已知成功且实际值班/负责人/期限可用，服务端才创建唯一人工案并进入 `pending_review`，不由 Agent 写 `passed`。HTTP 201 只说明反馈记录已保存；只有 `outcome=awaiting_review`、`progress_effect=pending_review` 及非空 `case_id` 才显示“已交老师”。`blocked_support/blocked_evidence/blocked_unknown` 保留可恢复状态，不能显示送审成功；预检即使全绿也不派单。

人工按第7节给 `passed`、`needs_practice` 或继续待复核；`unclear` 可用 `decision=needs_information` 保存分项依据、具体补问和期限，案件保持 `claimed`，不强制通过/不通过结案。需要补练只重做缺少的部分，历史记录保留。禁止用“聪明/落后”评价。正式家长报告仍须另外审核发布，课程通过不等于报告已发布。

## 7. 规则、人工 rubric 与过关依据

规则版 `invitation-rubric 0.1.0`。R01–R08 是确定性前置检查，不能输出“理解力”等判断。

- R01 来源/范围：本 learner、run、课次、材料、内容版本存在且可访问；样例只能进入样例练习，不可伪装成个人事件。无授权、版本缺失或来源撤回时阻断。
- R02 要求完整：第2.2节所有要求已确认；事实逐项与材料比较，仅允许明确的空白/全半角格式归一，不作语义猜测。目的/偏好非空只表示输入存在。
- R03 结构有效：字段类型、长度范围正确，未知字段不得进入模板；转义显示。邀请语包含矛盾、虚构收费等内容不靠此规则判正确，需 M1。
- R04 操作可追溯：输入先保存、已知成功运行及候选选择、作品保存回执、同版本回读齐备；`fixture/replay` 不满足正式 live 操作验收，P2 可另验协议。
- R05 自查与作品事实：有对具体作品字段的判断和可定位材料引用；同时把当前主作品的对象、日期、起止时间、地点、准备物品逐项对照 A，存在差异则列出待修字段。结构事实相等可自动核对，但判断理由是否成立由 M2 核对，邀请语/标题的语义矛盾由 M1 核对。
- R06 修改：同一主作品同材料下存在旧/新版本及非空差异、修改意图、理由和帮助记录；“是否实质修改、是否本人提出”由 M3，不靠字符数。
- R07 迁移：绑定 B 版本的当前 response、事实匹配、本人邀请语、至少两处变化记录、帮助披露齐备；解释含义和独立性由 M4。
- R08 当前性：检查绑定当前要求 revision、主作品版本、自查/反思 revision、迁移 revision、rubric 版本及证据集；来源变化不得沿用旧检查。幂等、归属与前置阶段条件由服务端校验。

人工 rubric：每项记录 `supported`（本次证据支持）、`needs_practice`（有具体补练）、`unclear`（证据不足需追问），附 source_ids，不计算年龄排名或总分。

- M1 信息可用：结构事实正确，标题/邀请语未新增冲突时间、费用、真实身份或其他无依据承诺；对象读得懂安排。事实错则指出材料位置，补改后重查。
- M2 判断与操作：本人能指出至少一项核对依据，并区分生成候选和已保存作品。可依据已记录短答，不要求所有人再进行长访谈。仅有勾选/点击无法支持时，补一个具体问题。
- M3 修改与解释：至少一次实质修改由本人提出，理由与变化有关；成人代录和操作帮助可并列说明。整句代写/照抄只支持有帮助完成，需新的修改机会；帮助不明时不推断独立。
- M4 小迁移：在 B 中重新选择事实，能说明至少两处材料变化及为什么不能直接沿用 A；邀请语由本人提出。只复制 A、现成样例或成人答案不能支持，反馈到对应字段。

第三关 `passed` 条件：当前证据集 R01–R08 满足，M1–M4 均 `supported`，且获分配复核人员签署当前版本结论。M3/M4 未得到本人贡献证据时保持补练/待复核，不降低独立要求或用 AI 多角色一致替代人工。阶段通过记录、教学观察、是否采用辅助分别展示，不能混成“全程独立”。

修改已通过作品时保留历史通过及其作品版本，当前新版本显示“修改后待检查”；不删除此前成果。新版本检查通过前，不能成为“已通过作品”或新报告依据。若修改影响前置要求，后续证据标待重新确认；历史后续结果不静默撤销，当前可执行动作由服务端按版本返回。是否还需人工重审由 changed evidence 判断，不能前端自行继承。

## 8. 四角色职责与最小资料

角色使用 `guide`、`tool_guide`、`creation_coach`、`review_coach`，不更改旧工作台枚举。角色可共用模型，不称四个独立专家。

- 主向导：读当前任务/关卡、保存与阻塞摘要、起点偏好及必要帮助记录；给一个当前动作、解释去哪和怎么恢复。无需完整私聊、预算账单或家庭管理资料。
- 工具向导：读当前工具卡、确认要求、必要运行/保存状态与经过裁剪的错误信息；解释生成/保存/回读，指导重试条件。不能自行启动扣费调用、重发 unknown、变更预算或替孩子保存最终作品。
- 创作教练：读当前材料、要求、正在编辑的字段和明确选中的上下文；用提问与局部示例帮助表达。不得默认读其他孩子作品，不直接代交完整邀请卡，不把样例标本人创作。
- 检查复盘教练：读当前作品及必要前版、材料、规则结果、自查/反思/迁移及相应帮助；引导对照和解释、给可引用建议。不能输出人工签署、正式过关、报告发布或权限结论。

角色输出只有可见文本、引用和白名单建议动作：打开当前材料/工具卡、定位当前字段、展示分级提示、请求本人确认、打开人工求助入口。实际保存、运行、检查、求助提交由本人明确操作和后端授权完成。模型输出无直接写权限；服务端记录真实 role/prompt/context 版本和 help_event，角色不得伪造 learner/human_actor。

## 9. 等待、错误与恢复

服务故障不是学习失败。界面区分草稿状态、模型状态、关卡状态和报告状态；下一行动由后端事实决定。

- 编辑未保存/断网：显示最后已确认保存时间和仍在本机的内容；保持当前编辑，“恢复连接后保存”。没保存成功不能说“你写的都已保存”。身份切换不把旧孩子缓存带给新人。
- 已知模型失败：保留要求和尝试，说明原因；用户选择后以新请求 ID 创建新尝试，同请求查询不重复调用。
- 模型 `unknown`：提示“这次结果还在核对，先保留你的要求”；查状态或求助，禁止自动/无条件再次生成，预算预占保留并形成核对案件。
- 预算不足：保存要求，继续读材料和已有作品；转获授权成人处理，孩子不直接进入支付或看到秘密凭据。
- 保存冲突：保留两份，先取当前版本，供本人选择/合并；不以迟到模型结果覆盖手改。
- 身份失效/授权撤回：停止敏感读写，清显示与私有缓存、丢弃迟到响应，重新进入受限会话后读服务端草稿；明确未同步内容可能无法恢复，不能以保留高权限凭证换取草稿恢复。
- 内容待复核/结果不可用：显示“这段结果暂时不能用”，保留允许保存的输入和状态；孩子可继续已获准的步骤或求助，不自动放行被拦内容。
- `needs_practice`：给一个具体缺口和可做的补练；旧作品与检查保留，补练后重新检查受影响证据。
- `pending_review`：显示提交版本、队列/认领状态、实际配置的截止时间和“查看进度／补充说明／返回作品”。修改时告知新版本需重查，待办旧版本不得悄悄通过新版本。
- 报告失败/待审核/撤销：不影响已成立的作品证据；重建报告只读已有来源，不再次跑孩子的生成尝试。未发布内容对家长不可见。

人工求助、作品复核、unknown 核对、报告审核分别建 human_case。最低信息：类型、本人问题、获准证据引用、版本、队列负责人、认领人、创建/截止时间、状态、升级去向、结案依据；不要默认附全部聊天。

建议待评估服务窗口：教学求助4个服务小时内首次回应、作品/报告1个工作日内复核；每份作品复核约8–12分钟、报告约3–5分钟。这些都只是人力测算假设，尚无值班承诺。上线前产品须指定实际队列负责人/替班人、工作日/营业时间/时区、截止计算、超时升级及支持入口；无承诺配置时明确“人工支持尚未开放”，不可创建无人负责且无期限的真实等待。非营业时段显示下次服务时间，自动升级不能伪称老师已阅读。

## 10. 家长观察与报告来源

家长只看整理后的本人过程和已发布报告，不默认看全文私聊，不读取团队消息。报告每条观察含文字、source_ids、确切作品/检查/帮助版本、来源类型、限制说明。快照不可静默随作品修改；生成、审核、发布、撤销分别留痕。

可写观察及必要依据：

- “本次选择了对象、时间和地点”：本人要求确认事件、材料和 revision；如选了预设项写清“在选项中选择”，不能写成独立撰写提示词。
- “保存后重新找到了作品”：保存回执及同版回读；只点击保存或打开样例不支持该句。
- “把时间改回材料中的14:00，并说明同学需要按时到”：前/后作品、本人理由、材料引用、M3 人工结论及帮助。若成人提供改法，改写为“在成人提示下修正”，不能声称独立发现。
- “换成纸桥活动后重新选了地点和准备物品”：B、迁移记录、至少两处变化解释、帮助和 M4；不能引用 A 的检查替代迁移。
- “目前还需要一次本人修改的记录”：M3 unclear/补练结论及缺失说明；不写“孩子缺乏创造力”。

报告同时写本次模式、提示/代录、哪些尚不了解和下一步一个小练习。帮助未知就写未知，不把同学协作、AI 建议、规则检查或人工评价互换为本人行为。自动摘要不能取代正式报告复核；来源不存在、撤回、跨家庭或版本不匹配时拒绝发布。
