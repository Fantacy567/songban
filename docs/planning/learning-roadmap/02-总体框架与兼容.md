# 总体框架与现有流程兼容

版本：1.1.0；日期：2026-11-02。P1–P4底座已有工程实现；本版新增体验目标待E0–E4执行，详细接线见[数据衔接与兼容](experience/03-数据衔接与兼容.md)。

## 一、现有事实与复用

当前是 FastAPI、SQLite、原生统一壳；私人工作台为 React/TypeScript 静态挂载。以下可复用机制，业务含义须重新适配：

- `app/onboarding.py`、`static/songban-onboarding.js`：原兴趣和经历、访客、资料恢复；家庭关系、学习起点和受限会话已在`app/learning_v2/`独立实现，不能由旧访客身份直接替代。
- `app/interview.py`、`app/interview_store.py`：逐题访谈与持久化；学习问答不应与原参赛访谈重复。
- `app/workbench.py`、`app/workbench_model.py`、`frontend/workbench/`：私人会话、角色、选定来源、模型状态与明确共享；现有角色是理资料、想方向、排下一步。
- `app/team_core.py`、`app/core_workflow.py`、`app/journey.py`、`app/division.py`：现行团队权威及顺序约束，学习模块不得替换。
- `app/materials.py`：个人、团队资料的解析与来源思想；首课不开放任意 URL、任意文件解析或终端执行。
- `app/parent_report.py`、`app/recap_reports.py`：两条现有报告实现，复用事实投影和引用校验；新学习报告接新来源适配器，不能直接取消旧 API。
- `app/connector_plugin.py`、`plugins/`：进阶外部工具接入；首轮教学不依赖连接器，不承诺跨 Agent 后台自动捕获。

现有路由以代码为准：`#/work` 是个人任务，`#/team-work` 是团队任务，`#/workbench` 是讨论工作台，`#/tasks` 为兼容个人任务，`#/collaboration` 进入分工。旧文档中仍有过期映射，不能照抄接线。

## 二、学习独立、比赛保留

学习域管理家庭关系、起点、课次、尝试、作品检查、角色帮助、学习报告和课程权益。比赛域继续管理活动、队伍、方向、投票、分工、任务与提交。共享认证主体、受控模型调用、品牌组件；不共享一个含义模糊的完成字段。

个人学完不自动创建队伍；队伍交付不自动通过孩子的课程。P6 只将本人授权、指定版本的作品复制为有来源的参赛草稿，团队仍按原确认流程决策。

## 三、导航与进入规则

目标一级导航为“AI 学习／黑客松”，个人入口包含作品与成长记录；后台和家长管理使用自己的导航。黑客松包含原活动目录和实践项目，不再把课程放到原实践二级标签中。

现有学习宿主为`/learning-prep`，复用其中`#/learn`、`#/learn/start`、`#/learn/run?id=...`、`#/learn/works`、`#/family`和`#/learning-admin`。实现时以宿主路由表和权限契约核对跳转，不能把旧`#/onboarding`统一重定向到学习。原比赛哈希链接保持语义；它们的导航高亮归入黑客松，旧书签不跳到课程。

从AI学习进入的新孩子完成简短访谈并本人确认总结后，在学习身份、授权与课程条件满足时直接进入首作工作台；已有学习恢复本人有权限的作品。缺少准备时只补所缺内容，并保留返回学习的去向。已经回答的年龄、经历和偏好经本人确认复用，不再重复整套起点问卷；小尝试放入实际任务。

首次学习主流程已经确定为访谈确认后进入创作，回访以继续作品为主。三关地图作为工作台内步骤提示；后续带图课程大厅用于找下一课，不成为首作前的强制页面。显式选择黑客松、打开旧比赛书签的用户继续原比赛流程，不被学习任务拦截。具体入口优先级见[入口与访谈衔接](experience/01-入口与访谈衔接.md)。

## 四、MVP 内容与四角色

工程首课沿用已有班级活动邀请卡。给定虚构活动资料，孩子提出要求、在受控文本生成器中生成文案、检查时间地点和对象、修正后用固定模板展示。生成内容是结构化文本，不执行模型输出 HTML/JS；无需新增图像供应商。新增作品类型需另行制作课程，不在本轮冒充已可学习。

三关：说清要求、操作与保存、检查改进与解释。至少一处独立修改和一项换材料的小迁移；为初学者和有经验者提供相同目标、不同提示力度，不用年龄硬分层。

四个内部职责：主向导控制指引与恢复；工具向导解释操作及选用工具卡；创作教练帮助表达和改写；检查复盘教练协助自查与反思。孩子默认只面对一个“松伴”，工作流按任务选择职责并留痕。实际过关由规则检查和必要人工复核决定，角色不能互相投票制造“验证”。

## 五、技术路线

先沿用 FastAPI，学习组件使用同源 React 静态挂载，复用现有模型传输。SQLite 用于隔离开发与限量试点，备份与恢复必须验证；并发与部署需求在 P4 测量后决定是否迁移 PostgreSQL，不先进行全站重写。多节点生产写入前必须另行完成存储架构与迁移验收。

课程卡先采用版本化内容与标签检索；MVP 不以 pgvector、LangGraph、Dify 或 Coze 为前置依赖。后端明确编排持久状态；后续只有实测需求支持时才引入新组件。对象存储在出现真实文件需求时以受控文件类型、大小、访问权限和生命周期接入，不把本地文件路径冒充公网作品。

## 六、不破坏旧流程的接线办法

复用P4已实现的默认关闭学习与导航开关；新增首课直达和工作台体验按E0确定独立控制范围，关闭时仍可恢复原页面。开发使用隔离数据库；新表和资源只增不删。新页面使用独立根节点和学习作用域样式。

中央集成者统一改 `app/main.py`、认证接入、`static/songban.js`、`static/songban.html`、全局 tokens 与构建配置。其他会话输出模块，不抢改中央文件。学习容器仅在本人身份/路由变化时挂载与卸载，旧比赛轮询不得清掉学习输入。

## 七、文档冲突清单

新学习导航优先于旧“仅活动／实践”；P4已有默认关闭的能力，本轮在E3核对后按环境启用。学习四个内部职责不覆盖旧比赛工作台三角色。新授权API版本与旧样例v1隔离；已有家庭会话保护不得退化成只隐藏按钮。访谈衔接不自动交换高权限凭证。邀请卡作为工程首课，不改动历史作品；新的对话预览布局优先于旧学习页面表单与默认四角色面板，旧测试记录作为历史保留。

## 八、上线与回退

首批先发布完整学习单元，原比赛功能继续独立可用。回退关闭学习入口与新调用，不删除作品、账本、报告或审核记录。已扣预算/unknown 请求在旧版本下不可重放；需保留受控查询和人工核对入口。数据库迁移采用可兼容的增量脚本并带备份、版本及恢复证据。

## 九、P4接线结果（2026-11-02）

已实现默认关闭的`navigation_enabled`，显式启用后统一品牌栏和`/learning-prep`都有“AI学习／黑客松”；原活动/实践和哈希链接保持原意。身份保护、功能写入和入口展示是独立控制，不通过隐藏按钮代替授权。运行时0.2.3保留67项操作，增加可选历史报告读取能力；P0冻结契约和既有迁移checksum未改。

实际应用与SQLite的家庭到报告完整流程、旧比赛页面、暂停历史读取及在线备份到隔离副本已经演练。存量历史只在原权限/同意/权益内可读，公开课程目录在课程关闭时仍不可用。尚未测多节点写入、生产容量或真实家庭规模，因此没有据此决定迁移PostgreSQL。详见[P4报告](handoffs/S00-P4联调.md)和[恢复手册](p4/发布与恢复手册.md)。
