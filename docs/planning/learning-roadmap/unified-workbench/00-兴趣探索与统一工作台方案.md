# 松伴：先学会用 AI，再探索兴趣、动手创造

版本：产品方案 v1.0；日期：2026-11-04。状态：用户已授权实施，按[U期规划](README.md)分会话执行；实现进度另列，不以方案采纳冒充功能完成。

本稿整合“整个平台是 AI 工作台、不同课程由对应 Agent 引导、作品集记录孩子自己的经历”，并按最新反馈明确顺序：**先让孩子学会使用 AI 工具，再用 AI 发现兴趣、展开想象、尝试创造；教学通过动手体验展开，避免做题式流程。** 实施规则已写入项目宪法4.0.0及U期增量；既有页面测试结果不能代替新体验验收。

## 1. 产品定位与核心价值

**松伴是一个陪孩子学会 AI 工具、发现兴趣并动手创造的平台。松伴先带孩子完成一次实际使用，再陪他们把自己的好奇和想法逐渐变成故事、图片、网页、小游戏或一份探索记录。**

对孩子，可以这样说：“先和松伴试试 AI 能做什么，再用它做点你喜欢的。” 对家长，松伴提供可查看的过程：孩子尝试过哪些工具、如何表达和修改要求、最近关注什么、留下了什么，以及哪些部分得到 AI 帮助。

零基础孩子先获得基本的工具使用经验，再逐渐增加自由探索的空间。兴趣可以从第一步就作为练习素材，工具操作由松伴明确示范，避免孩子面对空白输入框无从下手。入门以后，课程继续为创作中遇到的问题提供支持，黑客松提供自愿参与的团队创作与展示机会。孩子也可以长期写故事、画设想、研究感兴趣的问题，不必最终都走向编程比赛。

产品应鼓励好奇、表达、尝试和修改。是否进入下一段探索，不由答题数量或固定问卷决定；有进展时给予具体反馈，暂时没有成果也允许保存、转向和下次继续。

首批服务对象是刚接触 AI、缺乏工具使用经验的学生。入门内容按阅读和操作经验调整：需要帮助时多给图片、示范和可修改的例子；已有经验时减少提示、增加自主空间。家长查看实际过程与成果，教师或活动组织者提供必要的现场支持。首版先验证孩子能否使用工具并开始自己的创作，再验证学校与家庭的持续使用需求。

## 2. 孩子实际经历什么

首次进入，零基础孩子默认进入“第一次用 AI”工作台。松伴带着孩子用一个小例子认识输入框、发送、查看结果、继续修改和保存；附件、代码和更复杂的工具在用到时再介绍。已有兴趣访谈改成简短、可跳过的交流，必要的账号信息保持简短，不再一题接一题地追问才能开始。有经验的孩子可以选择“我用过，直接开始”。

建议第一次体验围绕同一份小成果连续进行：

1. **说出一个要求**：孩子任选动物、机器人等主题，请 AI 写一段角色介绍；松伴示范如何说明“想要什么”，孩子亲手修改并发送。
2. **让结果更合自己的意思**：孩子读结果，再提出“名字换一个”“缩短一点”“加上我喜欢的特点”等具体修改，观察 AI 是否照做。
3. **检查并留下结果**：孩子对照自己的要求，挑出需要修正的地方，保存喜欢的版本。松伴借此说明 AI 可能理解错，涉及事实时还需要核实。

这一段先帮助孩子做到“能表达、能追问、能检查、能保存”。通过实际操作观察哪里还需要帮助，不设标准答案考试，也不要求先学完全部工具、模型原理或 API 才能探索兴趣。之后做网页时，再引入运行、预览和 Vibe Coding。

有了这次使用经验，松伴再顺着孩子的选择展开，一次提供少量不同方向。例如孩子选择了猫，可以一起想象猫的城市、观察猫的行为、编一个猫的故事，或者做个会回应的电子小猫。建议卡始终保留“我有别的想法”；孩子可以只聊、换方向、暂停或开始动手。

当孩子愿意尝试时，松伴再把大想法拆成眼前能做的一小步。制作中需要什么，就出现对应的小知识和工具。遇到困难先帮孩子看清现象，再给提示或演示；需要 AI 直接生成一部分时，说明生成了什么，并邀请孩子选择、试用和修改。

每次结束可以留下“一件今天想留住的事”：一个新问题、一句设想、一张图、一次改动或已经运行的作品。松伴据此整理记录，下次回来接着这件事继续。

### 第一课的具体体验：做一张自己的角色介绍卡

以下是交互示例，不是实际生成结果。它用同一份成果串起操作，孩子可以随时改主题。

**开场。** 中央出现松伴的简短欢迎：“今天我们一起做一张角色卡。你想介绍小动物、机器人，还是自己想的角色？”界面给三个可选灵感，同时保留自由输入。右侧是一张空白卡片预览，标注“你的角色会出现在这里”。

**第一次使用。** 孩子选择机器人后，松伴在输入框旁给出可编辑的示例：“帮我想一个喜欢植物的机器人，写三句话介绍它。”孩子可以改爱好和要求，亲手发送。服务端调用模型，返回内容后展示在对话与卡片中；保存的卡片始终对应实际返回内容。

**表达自己的偏好。** 松伴邀请孩子看结果：“哪一点想保留？有没有想改的？”孩子可以直接输入“它要胆小一点，但很喜欢帮助别人”，也可以点一个提示开始修改。更新后允许对照前后两个版本、选回自己更喜欢的版本。孩子满意时也可以直接保存。

**学会检查。** 松伴提示孩子看看“三句话”和“喜欢植物”等要求有没有体现。发现遗漏时帮孩子补充要求，再试一次；若都符合，就说明符合在哪里。这里检查的是结果是否满足孩子的意图，角色想象没有统一答案。

**留下成果。** 孩子给角色起名字、保存卡片。松伴形成简短记录草稿：“你提出了什么要求、修改了什么、最后保留了哪个版本”，由孩子查看和调整。实际操作和孩子自述分别注明，不从一次尝试推断长期能力。

**自然接续。** 保存后提供“给它编个故事”“做成会回应的网页”“换一种角色”“今天先到这里”。选择网页时由创作老师接续，在已有预览与运行环境中制作；选择故事时继续对话和编辑。没有图片服务也能完成文字卡，图片与复杂工具以后按需要加入。

第一课的体验目标是让孩子知道在哪里输入、怎样提出要求、结果不合心意时怎样继续、自己的成果在哪里。它可以分次完成，不设置倒计时、分数或答对才能继续的门槛。

## 3. 统一 AI 工作台的界面

沿用用户提供的 Harness 截图中的侧栏、对话区和底部输入框结构，采用松伴自己的品牌、配色和儿童文案。大厅、创作和作品集都在同一个界面框架内切换。

- **左侧固定导航**：新探索、AI 教学大厅、黑客松教学大厅、作品集；下方显示最近的探索与项目，底部放账号。默认“图标＋短名称”，可收起。AI 教学大厅保留现有名称，突出“先会用，再探索”的入口指引。
- **顶部轻量状态**：显示当前探索或项目的名字、松伴当前角色、保存状态。避免大片标题把实际对话推到首屏之外。
- **中央对话区**：以松伴和孩子的交流为主，穿插图片、灵感选项、可操作的小卡片。开场简短，每次围绕一个话题或动作展开；更多说明按需展开。
- **底部输入框**：持续可见，可以说想法、问问题、添加材料。提供“给我一点灵感”“换个方向”等可选帮助，孩子始终能自由输入。
- **右侧按需出现的创作区**：展示图片、故事稿、想法草图、网页预览或代码。聊想法时可以收起；小屏幕以“聊一聊／看作品”切换，不挤成三列。

登录后，有上次记录就优先给出“继续上次”；零基础新用户优先看到“和松伴第一次用 AI”，同时能进入大厅浏览。第一段操作提供简短示范和明确的动手入口，随后逐渐减少提示。切换页面不丢失当前对话和草稿。

AI 大厅继续使用每门不同图片的卡片，桌面端一排四张。卡片只保留封面、短标题、一句“可以试什么”和继续入口；点击直接进入对应松伴老师的工作台。完整知识说明放在对话中的可展开内容或参考资料中。

## 4. 七门课程：工具入门在前，兴趣与创作逐步展开

原有 AI 工具篇四门、进阶篇三门的知识范围保留，默认推荐顺序为工具入门、想象探索、小项目、插件，再进入模型与 API。各课程由对应的 Agent 老师引导，共用一个松伴身份；角色差异体现在会提供的帮助、知识和工具上。

1. **“第一次用 AI”——工具向导**：先示范工具操作，让孩子实际发送要求、查看结果、追问修改、检查并保存；随后通过网页生成与试用认识 Vibe Coding。以亲手使用为主。
2. **“这个想法还能变成什么？”——想象伙伴**：从一个兴趣展开几种可能，允许混搭、转向，再由孩子决定要不要尝试其中一个。
3. **“让我的想法动起来”——创作搭档**：陪孩子做一个能看到、能操作的小项目，观察效果，改成自己的样子。
4. **“给作品加一种新本领”——工具拓展向导**：围绕孩子想增加的功能认识插件，理解插件能做什么、需要什么权限，并试用允许的能力。
5. **“同一个问题，AI 为什么回答不同？”——模型探索伙伴**：让孩子比较不同模型的实际回答，观察差别和错误，了解模型与工具的关系。
6. **“让我的作品向 AI 请教”——连接向导**：通过可操作的小实验认识请求和回应，再体验由服务端提供的 API；模拟回应与真实模型回应明确区分。
7. **“让作品有自己的说话方式”——智能创作搭档**：尝试更换模型或调整指令，比较作品的回应与行为，选择符合自己想法的方式。

七个角色使用统一模型服务与工作流配置，不需要部署七套独立模型。每个角色配置自己的知识依据、允许工具、提示方式和适用场景。孩子可独立进入任一探索；涉及前置知识时，松伴现场补一个小例子。

课程结束可以继续在同一项目上探索。角色切换时告诉孩子“接下来松伴陪你试试网页”，带上孩子选定的角色卡或项目及必要摘要；不要求重新填写一遍想法。课程素材作为老师的依据和可调用示例，不整页堆在孩子面前。

教学内容仍需真实、有来源。游戏化用于情境与互动，技术概念、模型能力和实验结果如实呈现。老师可以纠正事实错误、邀请孩子检查作品；避免把自由想象判成标准答案，也不把一次成功操作写成“已经掌握”。教学依据审核与儿童实际试用分别验证。

## 5. 引导方式：给选择、给线索、留空间

工具入门时，松伴明确示范、陪孩子操作，帮助他们理解自己可以怎样使用工具。进入探索后，再增加开放选择：先听孩子在意什么，提供有差异的可能性。孩子喜欢某个方向时跟进，不急着把每句话都变成学习任务。自由发散和集中制作都可以发生，孩子决定何时从“想一想”走向“试一试”。

例如，孩子说“我想造一座会飞的学校”。松伴可以接：“学校飞起来后，你最想带它去哪儿？我们也可以先画画它的样子，或者想想里面会发生什么故事。”孩子选择画画，就围绕画面继续；选择做网页，再进入相关工具引导。

需要知识时用简短解释、演示和实际尝试提供帮助。孩子卡住时可以看例子、减少一步难度或请松伴演示一部分。反馈应具体，例如“你刚才把门改到了侧面，还解释了这样方便上下船”，让孩子知道自己的想法被看见。

兴趣记录只表达“最近想探索什么”，允许孩子纠正、隐藏或更改。一次聊天不足以断定孩子的长期兴趣、性格、天赋或职业方向。松伴也应偶尔提供不同领域的选择，避免一直重复推荐同一种主题。

## 6. 作品集：孩子独有的探索与创作记录

作品集采用大图片、无明显边框的展示方式。每张卡对应一次有主题的探索或一个持续发展的项目。卡片可以保存比赛作品、工具作品，也可以保存尚未做成软件的想法与探索，明确标注“探索中”“制作中”或具体成果状态。

点开后先看封面、孩子起的名字、自己的介绍和已有成果，再按需展开经历：

- 最初好奇什么，为什么想试。
- 和松伴讨论过哪些关键想法，孩子选择了哪条路。
- 孩子亲自做了什么、AI 帮了什么，各自对应哪些材料或版本。
- 遇到了什么变化或困难，怎样尝试调整；未解决的也如实保留。
- 现在留下了什么，以及下次还想探索什么。

独特性来自孩子的具体表达、选择和尝试。松伴根据本次探索的交流、保存版本及可验证操作生成记录草稿；不能把孩子说“我做了”直接当成系统已验证的事实，也不能凭对话编造作品、能力结论或表扬。

草稿可在孩子点击“今天先到这里”、保存重要版本或主动要求整理时生成。孩子可以改标题、补充自己的话、删去不想保留的摘要，再确认存入作品集。后续探索更新同一份记录，保留版本，重新生成时保护孩子已经修改的文字。纯探索记录可以在之后关联到真实项目，不为每一句聊天都新建作品卡。

封面可使用实际作品截图、孩子自己的图，或由松伴按主题调用豆包生成并保存。生成封面标注来源，不能冒充已完成软件的运行画面；未配置图片服务时允许先使用已有图片，生成不成功也不影响保存记录。

**虚构示例：“会飞的学校，第一版”。** 小禾最初想让整所学校飞起来；聊过校园故事和飞行路线后，选择先画一间有翅膀的教室，又把画做成可点击的小网页。记录写明“小禾选择路线和按钮文字，松伴协助生成网页代码；预览中点击按钮后路线发生变化”，同时留下他自己的话：“下次我想让它停在海边。”若只有画和设想，记录就展示这两项，不写成已经运行的网页。

记录默认保存在孩子自己的空间。家长查看可见范围内的成果与摘要，公开分享由用户主动选择；私人交流不自动完整公开。家长成长报告引用已确认的记录，描述具体经历、可观察变化和下一步支持建议。

## 7. 黑客松与现有功能如何融合

黑客松大厅保留“认识黑客松”和“跟松伴开始一次实践”两张带图入口。先了解合作创作是什么、可以怎样参与，再自愿选择活动。进入真实比赛后，松伴协助理解规则、组织想法、分工和复盘。

现有团队、连接器、资料库、确认进度、排名投票、任务领取、交付及报告继续使用原业务数据与规则，在工作台中提供清晰的操作卡。成员确认、投票、队长确认等动作仍由对应的人完成；聊天不能替人执行这些决定。团队内容与个人探索分别管理，只有授权内容进入共享空间。

仓库已有七门课程及封面、学习记录、创作编辑与预览、版本保存、作品集和管理员配置基础。本方案新增工作的重点是统一界面、课程角色对话、可恢复探索上下文，以及有材料依据的作品记录。已有内容与历史链接需要逐步接入，避免重建一套平行数据。

模型与图片 API 由服务端统一配置；孩子无需填写密钥。管理员管理课程角色、知识来源、工具范围、用量及内容审核。沿用既有 Harness 适配与运行隔离方案，保留源码版权和第三方许可。真实模型、图片生成和执行环境是否可用，须分别实测，配置存在不代表联调通过。

对话、实际作品与成长记录需要分别保存并关联：对话提供上下文，作品保存具体内容与版本，成长记录保存经过确认的摘要和依据。学习状态至少表达正在尝试什么、保存了什么、下次从哪里继续。模型超时或生成失败时保留孩子已写的内容，允许重试或继续编辑；重复重试不能重复新增作品或覆盖已保存版本。

## 8. 建议实施顺序与验收

**第一期：跑通工具入门，再接上兴趣探索。** 先做统一工作台与“第一次用 AI”，验证孩子能在帮助下发送要求、修改、检查、保存。随后从孩子选择的主题展开联想，并支持继续制作一份小成果、生成可编辑的个人记录。后续网页体验复用“第一个小项目”。重点检验基础操作是否清楚，以及从示范到自由探索是否自然。

首版最小交付是一个完整的工具入门老师、一份能修改并保存的成果、一条可编辑的个人记录，以及关闭后恢复继续的能力。第一期不依赖七位老师全部改造、真实图片生成或外部 Agent 安装；已有课程入口保留，新对话能力按实际可用状态标识。

**第二期：接入七个课程角色与大厅。** 按实际任务提供不同工具面板，支持回到上次、换课和继续自己的项目。跨课程只传递孩子选择关联的项目及必要摘要，各自的聊天与记录保持清楚。

**第三期：接入黑客松与家长查看。** 将原比赛操作接入统一工作台，作品记录与成果互相链接，家长报告引用可追溯的过程。全平台继续只有一个统一演示入口。

**第四期：小范围试用并调整。** 先观察孩子能否用自己的话提出要求、在结果不满意时继续修改、检查并保存，再观察是否愿意主动提出问题、改变 AI 建议和探索新的方向。结合孩子和教师反馈调整提示密度；不把聊天时长、答题量或生成作品数量当成兴趣增长的证明。

工程验收覆盖：课程进入正确角色；自由输入、换方向和暂停可用；草稿与项目能保存恢复；实际模型不可用时如实反馈；记录能追溯材料、能纠正；个人与团队数据不串；原比赛流程可继续。教学验收另外检查内容准确性与实际儿童体验。

首版按一个完整故事验收：新用户进入工具入门，提出自己的要求，收到实际模型回应，修改并选择一个版本，保存成果与记录，退出后再进入能继续；切换主题不会把旧成果弄丢。模型故障时能找回输入，记录里不存在并未发生的操作。模拟服务只能证明界面与流程，真实供应商调用另记结果。

儿童试用观察放在真实操作中进行：哪里需要成人解释，哪里让孩子反复卡住，是否知道怎样修改，以及是否能用自己的话说出刚才做了什么。记录需要多少帮助，并据此调整提示；不额外给孩子发一套验收试卷，也不据此宣称已证明教育效果。首版试用结果决定后续课程扩展的优先级。

用户已授权按工期拆分宪法增量、UI细则、数据契约和独立会话任务。协作使用用户可见的独立会话，由主会话集成，具体进度见[执行记录](04-未完成项与执行记录.md)。
