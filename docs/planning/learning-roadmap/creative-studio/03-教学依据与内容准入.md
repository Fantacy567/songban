# 教学依据与内容准入

## 证据如何使用

教学有两个核验层面：所教知识是否准确、教学活动是否有合理依据。前者通过规范、官方技术文档与可复现实验核对；后者参考教育研究并在实际课程试点观察。通用教育研究不能直接证明松伴、AI 教师或某套游戏关卡有效。

IES 的学习组织实践指南支持把示例与自主解题交替安排、间隔复习和解释性提问；指南对不同建议给出不同证据强度，应保留这种差异。这里据此设计“看一个例子、自己改一次、隔一段再尝试”的活动，不声称某个固定分钟数或关卡数有普遍最优效果。[IES / WWC 实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)

EEF 的元认知与自我调节指导强调把计划、检查和反思嵌入具体学科内容，通过示范和支持逐步走向独立练习。松伴采用的“预测、运行、观察、解释、改进”是据此作出的产品教学设计，仍需本地验证；不把综合研究的平均收益作为本平台宣传承诺。[EEF 指导报告](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/metacognition)

## 知识与编程任务

首包的工程教学草稿为三个相互衔接的小任务，机器可读内容见仓库 `curriculum/creative-studio/first-web-v1.json`。状态为 `draft`，尚无人工教研签署，不能冒充已发布的正式课程。

三个任务已补充可运行示例与独立浏览器核验：`curriculum/creative-studio/examples/`、`node scripts/validate_creative_curriculum.cjs`。检查覆盖实际交互及迁移表达式变体，结果绑定源文件哈希；其性质是技术自动检查，不替代技术人员签署、教研复核或儿童试点。

1. **让按钮有反应**：目标是分辨页面外观和事件行为。孩子预测点击结果、运行、描述哪个操作触发了什么，再改变按钮行为。依据浏览器事件机制与 `addEventListener`，不是“AI 猜到人的意图”。[MDN 事件入门](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Events)
2. **让程序记住次数**：目标是观察变量初始化和更新。先说明初值，连续点三次，比较结果；再把一次增加 1 改成增加 2，预测并复测。刷新是否重置取决于具体代码是否持久化，不能把所有网页说成都会永久记住。[MDN 变量](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Variables)
3. **让作品按规则回应**：目标是理解条件控制不同路径。给出明确阈值，检查阈值以下、等于和以上三种情况，改阈值后重新验证。完成路径与变量、事件结合，不通过把 UI 文案改成“通关”伪造条件正确。[MDN 条件语句](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Conditionals)

这些技术来源用于核对语言和浏览器行为，不证明该教学顺序适用于所有年龄。孩子可选择计数游戏、报名小页面或自己的类似想法，知识目标和检验方法保持可辨认。更小年龄与有基础学生调整阅读、操作和帮助，不按年龄给能力结论。

## 课程发布必备记录

每个版本登记作者、更新日期、适用前提、目标、关键事实、来源及查阅日期、已知局限、示例代码、实际预期、误解提示、练习与迁移、核验办法。至少分开保存技术核验和教研复核人员及日期。状态链为草稿 → 技术核验 → 教研复核 → 小范围试点 → 发布；任一知识错误可撤回并标记受影响版本。

模型可以建议课程草稿、解释或提示，不能编造来源和复核者。引用失效或知识不确定时显示待核实，不能自信补造。课程审核者确认来源确实支持相应主张，不能只检查“有一个链接”。

## 怎样判断孩子学到了什么

每个目标至少有孩子的可观察行为，记录帮助程度。例如“在提示下修改点击处理函数”“能先预测改成加 2 后的结果”“能解释刚才错误与改动的关系”。独立迁移另用新的小情境核对，不能把照抄示例当独立完成。无充分证据时报告写“还需要观察”，不填虚构分数。

自动检查可验证文件、语法和特定运行行为；孩子陈述记录为自述，人工观察注明观察人。以作品版本关联证据，改代码后旧检查不自动沿用。试点观察是否理解、是否需要帮助及一段时间后的再尝试，而不只统计留存、时长和作品数量。
