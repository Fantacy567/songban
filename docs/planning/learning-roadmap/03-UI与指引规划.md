# UI 排版与儿童指引规划

版本：learning-ui 1.1.0；日期：2026-11-02；状态：新的入口与儿童工作台目标已确认，待E0原型/契约核对及E1–E4实现。具体排版和交互见[儿童工作台UI](experience/02-儿童工作台UI.md)。末尾P3/P4实施对照为历史事实，不表示本版新工作台已经上线。

## 1. 核心体验

每页帮助孩子回答“我要做什么、怎么开始、做完去哪”。孩子在一个创作工作台里完成对话、操作、看预览和修改；步骤提示提供位置感，松伴按当前任务帮助。保留首页动效、米白底、紫色主行动、小松树和现有品牌字标。对话与作品并排体现创作过程，不照搬开发者终端、文件树或多角色配置。

## 2. 页面与内容顺序

### L01 首页与学习首页

品牌首页保留主视觉，提供两个明确入口：“AI学习——跟松伴做一个小作品”和“黑客松——和队友参加比赛”。一级导航对应“AI学习／黑客松”，比赛内保留原活动和实践。入口要说明用途，不能只替换图标或名字。按E1–E3完成接线和验证后启用，不把已有P4导航开关当作体验改造已完成。

首次学习在访谈确认和必要准备完成后直接进入首作工作台，不先展示课程列表。回访优先“继续我的作品”，其他作品和后续课程保持次级入口。三关以工作台步骤提示出现，不要求先看地图动画。无记录、未具备学习条件、有草稿、待老师检查及服务故障各有真实出口。

### L02 让松伴认识你

访谈以5～6个核心问题为目标、总上限8题，提供提前结束和本人确认总结；已有答案经确认复用。必要时只补年龄段、使用经历、兴趣或帮助偏好中的缺项，不再次强制填写完整问卷。小尝试嵌入首作任务；未观察内容保持未知，不阻止提供保守帮助。写明选填和用途，不收精确生日，不显示年龄对应能力排名。

模型问答不可用时可保存选择并提供保守起点建议/人工帮助，不捏造完成模型评估。已有档案仅补缺失项，不强迫已参赛用户重新入门。

### L03 任务工作区

宽屏工作台采用三个区域：左侧“我的作品／三个步骤”，中间“和松伴聊”，右侧“看我的作品”。约18%／40%／42%作为原型起点，按可读性调整；工作台允许比普通详情卡更宽，保留最小可用区域，不能硬塞进原1060px表单。平台导航在工作台压缩，避免全局侧栏、课程侧栏和角色面板并列。顶部显示作品名、真实保存状态和返回入口。

中间首屏给出一句任务与一个可开始的动作，消息中嵌入选择、可编辑提示、当前工具卡和检查反馈。孩子默认只与松伴交流；提示等级、完整来源与帮助历史按需展开。右侧区分示例、候选、本人已保存版本和未保存修改，保存版本与检查结论对应。生成完成不自动保存、过关或跳步。长回复先呈现当前行动，保留展开全文。

平板按实际宽度折叠步骤、在对话与预览之间适配双区或切换；手机用“和松伴聊／看我的作品”页签及紧凑步骤条。切换保留输入、位置和草稿，保存和检查不会因换页签自动触发。帮助有明确关闭出口；返回后焦点回到触发控件，键盘出现时输入和主操作不被底栏挡住。

### L04 作品与完成回顾

先看作品，再看检查结果和一次具体修改。例如“你补上了活动时间，让同学知道什么时候来”。只有真实记录支持才能出现该文字。再给“看看我的作品”“继续下一课”。未通过显示可执行的补练，而非红色失败评价。待人工复核写明预计处理时间与联系出口。

作品列表区分草稿、已保存、待检查、已通过及版本，不用点赞数、对话量或外观评能力。

### L05 课程大厅（E4后续）

每张课程卡用真实支持的作品示例封面，配通俗名称、一句能做出的作品、准备条件及学习状态。封面标明示例并有替代文字、加载与缺图回退。主行动区分开始、继续、查看作品、尚未开放及需要成人准备；不虚构课程数量、时长或学习成果。首次学习不必经过大厅，完成首作后再推荐下一课。图片比例、卡片响应布局及授权要求见[详细UI](experience/02-儿童工作台UI.md)。

### F01 家长端

依次展示活动与权益、本人孩子当前学习、作品、关键过程摘要、已发布报告、下一步建议。家长可协助报名和授权；进入孩子模式与返回管理需符合真实会话权限。报告审核中不假装已发布，不默认展示全队聊天。

### A01 管理端

后台优先处理待办：关系/授权、求助、作品复核、报告审核、订单核验。内容配置次之、统计最后。每个动作显示目标孩子/家庭、依据、当前版本及结果；界面不向孩子开放运营功能。

## 3. 组件规范

复用品牌栏、导航、白底卡片、紫色按钮、输入、弹窗和状态提示；学习新增任务卡、关卡节点、工具卡、分级帮助、作品预览、检查反馈、过程回顾。组件样式仅作用于学习根节点。

复用 `--sb-*` 语义 tokens，卡片圆角约17px、控件约13px。任务正文建议16–18px、行高约1.7，按钮触控区至少44px；任务页标题桌面建议28–32px、手机24–28px，不把品牌首页大字复制到每个内页。以390/768/1440px及200%缩放验证再定稿。

一个任务区一个主行动；保存、看例子和返回为次级操作。不同区若有其他主按钮，必须避免同一视窗内不明优先级。选中、等待、错误和通过同时有文字，不只靠颜色。

## 4. 一个松伴与四个内部职责

对孩子默认使用同一个松伴名称与小松树形象，由任务工作流选择主向导、工具向导、创作教练或检查复盘教练的内部职责。界面说明“松伴正在帮你检查时间和地点”等当前行动，不要求先选Agent。真实角色、提示词版本和帮助等级保留在过程记录；不以换头像伪装成多位真人或独立专家。

三个显式帮助入口：“我不知道怎么开始”“给我一点提示”“帮我检查”。优先引导孩子作选择，再给操作方法，最后才展示示例。自动记录已提供的帮助等级；未观察到的线下成人帮助允许本人补充，不声称系统知道全部帮助。

## 5. 教学工具卡

卡片顺序：适合当前哪一步、三步操作、可编辑提示词、怎样检查、注意事项、不会时怎么办。首屏只露出当前需要的部分。明确示例和本人填写，示例不得自动成为孩子真实作品或报告证据。

## 6. 文案规则

按钮使用具体动词：“试着生成”“保存这张作品”“检查我的结果”“改好后再试一次”。错误解释当前事实与恢复动作；只有收到保存回执才能写“已经保存”，仍在本机时明确说明并给出保留/复制入口。帮助推荐使用“带着我做／让我先试试／我想挑战一下”，不使用低能力/高能力标签。

展示未知模型、费用待核对、内容待复核时用儿童可理解的主文案，技术详情折叠到成人支持区。孩子需要知道结果是否可靠，不需要阅读接口错误栈。

## 7. 状态清单

每页交付默认、加载、空态、编辑未保存、已保存、网络失败、模型失败、结果未知、预算不足、版本冲突、身份失效与恢复。特有状态包括待监护授权、内容复核中、等待老师、作品修改后需重查、报告草稿/待审核/已发布/撤销、订单待核验/已开通/退款。

不得只画成功页面。未知运行不得提供无条件自动重试；检查“保存了什么、还能做什么”先于错误原因长篇说明。离开未保存任务要有清楚提示；无保存失败时的假成功动画。

## 8. 设计验收

E0基于P0既有组件核对新版桌面/手机关键页面、组件状态、路由去向、真实/模拟标记与反馈文案。可使用独立交互原型，不接真实账号、支付或模型。不得把原型接为主站业务。

实现阶段验证键盘顺序、焦点恢复、长中文、长链接、触屏、滚动/输入法、减少动效和三个视口。邀请真实孩子观察后再判断是否通俗，研发主观满意不等于儿童可用性通过。问题按“看不懂任务／不会操作／服务故障”分开处理。

## 9. P3实施对照（2026-11-02）

当前任务和作品操作仍在前，四角色帮助放在任务下方，选择角色/提示等级后明确请求；静态提示、模拟生成、真实模型分别显示，不自动替孩子保存作品或推进关卡。报告在完成检查/复盘后出现，孩子核对事实再送审。家长页将已发布报告放在授权设置之前，避免成果被长授权表单埋住；草稿不对家长展示。

人工复核与用量核对进入独立受权限保护的 `#/learning-admin`，只列本人获分配工作。编辑离开、身份切换、unknown、失败、撤权保留相应保护；费用未知有明确文字。主站未新增导航入口，学习仍使用显式启用的 `/learning-prep`。真实页面390/768/1440无横向溢出，报告fixture另覆盖200%缩放；真实儿童理解度、真实手机输入法与屏幕阅读器留P4，不能由自动化结果代替。证据见[P3联调](handoffs/S00-P3联调.md)。

## 10. P4实施对照（2026-11-02）

统一壳和学习页新增可关闭的“AI学习／黑客松”一级切换，`navigation_enabled`默认关闭，仅在显式配置的测试服务开启验证。原活动/实践保留为比赛子导航，原哈希链接继续有效，独立演示保持原入口。新样式限定在`[data-stage-nav]`，未重写原全局布局；手机顶部切换、键盘焦点和44px控件已有页面证据。

关闭新学习/模型/报告生成后，家长仍能发现受权的历史报告，不再把“能否生成”当作“能否看历史”的条件。原作品历史和unknown核对出口也继续鉴权可读，不能通过暂停恢复新操作。

本期真实应用页面验证三种宽度及报告200%缩放、键盘提交、弹窗焦点循环/Escape/返回、未保存退出保护、减少动效的实际样式。旧比赛完整页面回归通过。真实儿童理解、真实手机输入法和屏幕阅读器仍未验收，不能把自动化结果当成这些事项通过。完整结果见[P4联调](handoffs/S00-P4联调.md)。
