## 发现并修复的问题

- **授权内容加载失败，阻断家庭准备。** 后端存储后的用途对象键序改变，前端沿返回键序计算哈希。现在两端按约定字段顺序计算，不因 JSON 对象键序变化误判；原文被篡改时仍拒绝。
- **家庭页重新加载或迟到响应可能覆盖当前状态。** 修复读取世代与组件存活标记，刷新和配置更新可继续加载；旧读取不能覆盖新读取。
- **旧密码登录正常轮换自己的令牌时被提交检查拒绝。** 只在被明确列出的凭据签发端点、同一已锁定事务内接受自身轮换；其他失效凭据和跨身份请求仍拒绝。最新隔离服务的旧密码登录已复验成功。
- **关闭新配置可能移除已生效的身份保护。** 已迁移库拒绝不带学习配置启动；显式暂停保留边界。
- **旧 HTML 书签缺少身份检查。** canonical页面与直接静态 HTML 入口统一注入边界；检查完成前隐藏旧页面，避免旧内容闪现。
- **首次没有回答却提示“调整”。** 首次主按钮改为开始回答；已选择开始方式的摘要改为学习起点。去除孩子页面上的 P1 等工程术语。
- **一个家庭的旧任务误阻挡其他家庭。** 按服务端确认的账号、浏览器和团队归属判断，并保存请求/任务原始成员范围；A有pending/unknown时无关B可继续。成员移除、增加和重启不会丢失原范围。无归属、失效owner、孤儿团队继续保守拒绝，不能凭超时伪造外部任务完成。
- **全套测试环境误拦了合成配置文件。** 第一轮420项中1项失败，原因是隔离启动器同时禁止了测试刻意放在临时目录的配置。已只拦真实项目配置，允许测试临时配置，重跑421项全部通过。没有修改业务逻辑来回避该测试。
- **新增宿主测试误把兼容页锁定当失败。** 中间一轮429项出现7个子案例失败，均因测试在core-only模式要求旧兼容页返回200。修正为分别测试兼容模式的边界注入和core-only模式保持423；没有放开原站锁定策略。
