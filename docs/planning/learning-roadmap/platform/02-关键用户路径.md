# 三入口平台关键用户路径

版本：platform-journeys 1.0.0；日期：2026-11-02；规划会话：H01。状态：实施与验收输入，尚非新三入口的运行验收报告。页面层级按[UI层级与页面规范](01-UI层级与页面规范.md)，身份、证据和模型约束沿用[项目宪法](../01-项目宪法.md)。

每条路径都说明用户要做什么、松伴怎样陪伴、哪些动作写入记录、遇到缺项怎样继续。普通浏览不生成作品，不消耗生成额度，也不替本人完成确认。

## 一 第一次来学 AI

**目的**：孩子能从自己的兴趣出发，开始一件真实可做的小作品。

1. 从首页选择AI教学大厅或首次学习推荐。记录这次内部去向，完成所需认证与家庭准备后回到该位置。
2. 简短访谈了解兴趣、经历和想做的事；已有本人资料可确认后复用。通常5–6题、上限8题，随时可结束并查看总结。旧第17题等记录直接收口，不删除已有回答。
3. 本人核对总结。访谈与学习者不是同一主体时，先由有权限的管理者明确关联，再由孩子采用或暂不采用；同浏览器和家长账号不作为自动关联依据。
4. 身份、授权和课程条件满足后，主要动作是“开始我的第一个作品”。优先进入当前真实可用的首课，不强迫先浏览整个大厅或填写第二套问卷。
5. 在工作台看到当前小任务、同一位松伴和作品预览。松伴给出一个能执行的小动作；孩子选择要求、动手制作并核对结果。
6. 孩子明确保存后，作品留在本人记录中。接着亲手改一处、自查、小迁移和复盘；检查、老师反馈与报告按各自实际状态显示。

**关键回执**：访谈总结确认、摘要关联及孩子决定、课程/课次ID、作品版本、检查和报告来源。课程封面或示例不进入本人作品证据。

**缺项出口**：家庭准备未完成就说明缺什么、找谁、完成后回哪里；没有资格时保留推荐去向，不伪造授权。没有更多课程时继续已有可用首课，不制造可点击假课程。模型未配置时保留明确标识的静态提示或获准模拟能力。

**验收观察**：确认后能找到第一步；没有第二套强制问卷；浏览和进入工作台没有自动生成；刷新后能找回已保存的同一版本。真人是否看懂，另由观察记录证明。

## 二 回到 AI 教学大厅选课或继续

**目的**：不重复介绍自己，能找到正在做的作品或下一门可用课程。

1. 点击AI教学大厅。已有本人课次时，顶部显示“继续上次的作品”；阶段分区与课程卡仍可浏览。
2. 继续时恢复服务端可访问的准确课次和作品版本，不重新生成、不重复建课次。显式作品深链接优先于一般推荐。
3. 选另一门课程时，先看目标、实际支持的作品和准备条件；有资格才提供开始动作。多课程/多课次策略须依据中央冻结的选择契约，不能沿用“取第一个授权”的隐含排序。
4. 等待老师或结果未知时，恢复该状态，展示可继续做的事及支持去向，不把重新进入页面当作重试生成。

**验收观察**：目录暂不可用不阻断合法旧作品；课程卡不显示他人进度；重复点击不产生重复课次；切换到另一孩子不会继承前一个孩子的作品地址。

## 三 第一次认识黑客松

**目的**：孩子先知道会发生什么，再决定怎样开始实践。

1. 点击黑客松教学大厅，首屏只出现两张主要图卡：“认识黑客松”“跟松伴开始一次实践”。第一次突出第一张的阅读顺序。
2. 点击“先了解黑客松”，用一个明确标注为示例的小队故事，认识活动、作品、合作与展示。按内容逐段展开，解释术语时松伴仍是原来那一位。
3. 看到本场比赛需要自己核对的规则。认识课程不把通用示例当具体主办方要求；不同赛事的实际资格、时间、地点和提交事项单独核对。
4. 末尾选择“我想试一试”，转向第二张卡对应的实践准备；需要再看例子时留在认识内容，不丢位置。

**关键回执**：可记录查看或本人选择继续，但这些不等于理解通过或获得参赛资格。不得仅凭翻页把“已经学会”写入报告。

**暂定项**：新用户能否在未完成认识内容时直接开始新实践，尚未获明确决定。实施前默认突出先认识的推荐路径，不增加强制考试或伪造解锁结论；老比赛的明确深链接仍须可恢复。

## 四 跟松伴开始一次黑客松实践

**目的**：把认识内容转成一条可执行的比赛路径，并继续使用现有团队业务。

1. 从第二张图卡开始，或在其中继续已存在的比赛。先核对活动时间、地点、赛道、评分、提交要求和来源，未知部分保留未知。
2. 创建或加入队伍，填写当前成员的能力、意愿和可用时间。松伴解释下一步，不替队长确认成员意愿。
3. 在选题讨论时，成员可使用自己的 Agent 工具与松伴连接器。安装、配置、共享选中回合是不同动作；只有本人明确共享的消息与模型可见回复进入团队资料。
4. 队长口头核对上传是否齐全，每位队员分别点击确认。显示真实“已确认人数/总人数”，例如3/5；有新的共享或成员资料变化时，按现有规则重新核对。
5. 全员确认后，团队 Agent 对全部选题给出多维建议，每个方向均说明优势、可能问题与待验证项。模拟评估与真实模型建议明确区分。
6. 全员各投一票。全员完成后由队长确认最高票方向；平票只对并列最高项重投。松伴可解释依据，不替人投票或确认主方向。
7. 沿用既有任务草案、发布或分工确认规则，成员领取任务。建议负责人不自动等于已领取。
8. 成员制作并同步本人进展，提供成果依据；同伴按检查方法确认或要求补充。本人报告完成不直接记为同伴验收通过。
9. 查看交付清单，准备展示或路演；记录实际提交状态。最后由本人复盘，报告依据、预览、复核、发布或分享按对应报告业务分别处理。

**关键边界**：大厅是入口和教学组织，不新建第二套队伍、讨论轮、票数、任务或提交事实。团队 Agent 仅取得已授权来源。图片生成或作品好看不代替投票、任务验收或主办方回执。

**失败出口**：排名未知保留原请求核对；成员未确认就显示缺项；无老师或支持接收时说明真实状态；主办方结果未公布就标明尚未知。各步骤可回到对应记录继续，不从头重建一场比赛。

## 五 有经验用户继续原比赛

**目的**：新教学大厅不妨碍正在进行的比赛。

1. 从原比赛书签进入，或点击黑客松大厅第二张卡中的“继续上次的实践”。恢复当前有权限的队伍和阶段。
2. 新导航和松伴说明当前位置；赛事、组队、连接器、选题、分工、任务和复盘仍使用原记录。
3. 孩子受限学习会话如果没有执行旧比赛操作的权限，先按原边界完成相应身份准备。不得因为顶栏有黑客松按钮就交换管理凭证或绕过限制。
4. 明确想补学认识内容时，可以主动回第一张卡；不能把看完新介绍强加成旧任务恢复的条件。

**验收观察**：旧书签不被大厅推荐夺走；队伍、投票、任务和连接器绑定不重置；原比赛参与者与学习者身份分别核对。

## 六 把课程作品留在作品集

**目的**：孩子能看见自己留下了什么，也能继续修改。

1. 在课程中确认保存作品，等待服务端版本回执。候选和未保存编辑仍留在工作区，不伪装成已保存成果。
2. 作品集展示这件作品及已选封面，图片下说明名称和简短内容。进入详情可看实际成果、课程来源、本人说明与修改历史。
3. 继续修改时回到同一课次或作品编辑上下文，另存新版本。列表中仍是一件作品，历史版本与旧检查保留关联。
4. 检查或报告等待处理时，作品仍按原授权可查看；已保存与已通过分别展示。

**验收观察**：一件作品不会因每次修改铺成多个相同卡片；封面切换不覆盖作品本体；历史版本不能继承最新检查，最新版本也不能借用旧检查的通过结论。

## 七 把比赛或外部工具成果加入作品集

**目的**：不仅保存课程产出，也能呈现真实参与的比赛或独立创作。

1. 比赛成果选择对应队伍和作品，记录孩子本人负责的部分。能引用现有成果时保留其来源，不复制整队私人资料。
2. 外部工具成果先添加名称、本人说明、作品链接或获准文件，并添加封面。填写“我做了什么”时区分孩子操作、AI辅助和团队协作。
3. 保存前看清归属与可见范围。链接未验证或暂不可访问时如实显示，不把填入网址当作作品已经检查通过。
4. 保存后在本人作品集中出现一件作品；后续补充截图、说明或版本保持关联。作品集默认私有，公开展示另行决定。

**验收观察**：团队作品不宣称由孩子独立完成；外部链接不被页面当脚本执行；添加封面不自动公开、提交比赛或生成报告；跨孩子、跨家庭读取仍被后端拒绝。

## 八 让松伴生成并自动保存图片

**目的**：在需要图片的位置完成创作和归档，图片不会生成后找不到。

1. 当前上下文明确时，孩子可在同一个松伴里请求作品封面或插图；课程编辑人员在有权限的课程上下文请求课程封面。目标不明确时先选择目标。
2. 显示本次用途及正在生成的任务；模式与可用额度依据服务配置，不因打开大厅或收起气泡自动调用。
3. 生成成功后自动归档到该目标的素材区；显示保存回执、来源和可继续使用的位置。
4. 选择作为封面或插入作品时，显示受影响的位置。保留其他已保存图片和作品版本；更换展示图不覆盖原始成果。
5. 页面刷新或离开后，从同一生成任务恢复。生成结束但归档失败时显示“图片已生成，尚未确认保存”，先核对或继续保存，不重新调用生成。

**验收观察**：图片归属于正确课程或孩子作品；没有权限就不能写课程封面；任务未知时不重复外发；只有保存回执成立才显示已保存；示例和模拟不冒充真实生成；公开范围不随自动归档扩大。

## 九 全程松伴与跨页上下文

**目的**：同一个伙伴知道当前任务，页面切换不会产生一组互不认识的机器人。

1. 大厅中展开松伴，获取对当前内容的解释和一个下一步建议；不要求孩子先选内部角色或模型。
2. 进入工作台，同一当前作品的对话与进度继续，浮层聊天收起，主对话区接替。待发文字和滚动位置在允许范围内保留。
3. 切换到作品集，松伴以当前所选作品为对象帮助整理说明或图片。切换到另一课程或比赛时，明确显示上下文变化；没有选择作品时只帮助浏览，不猜测要改哪件作品。
4. 个人资料被带入团队前仍需明确选择共享范围。学习访谈原文、其他作品私聊和另一孩子的记录不会因“全程陪伴”变成团队资料。
5. 身份变化、授权撤回或资源删除后，清理失效内容并重新核对；新身份不继承上一位孩子的私人会话。

**验收观察**：全平台只有一个可见聊天入口；同一作品可继续；切换资源可辨认；进入团队没有静默同步私聊；模型建议不自动执行有业务后果的动作。

## 十 中断、身份切换与恢复

未保存时，切换一级导航或离开任务先给出继续编辑、明确保存或放弃的选择。保存失败保留输入；没有可保存接口的草稿不能显示“已保存”。导航保护不能阻断退出或把用户困在循环弹窗。

返回家长管理需按现有规则重新认证；老师只进入分配范围。切换到另一孩子后先重新读取本人课次和作品，不保留前一孩子的资源目标。原身份的延迟响应不得覆盖新页面。

授权或额度失效后，保留允许读取的历史与明确恢复出口；不能因“仍可看历史”而允许新生成或公开。报告撤回与作品公开撤回分别处理，不用同一按钮含糊表示。

## 十一 一个演示入口的走查要求

统一演示目标是一个站点同时呈现两个教学大厅、作品集、当前工作台和现有黑客松流程。真实账号服务与演示数据分别保留。旧演示整合、端口切换、备份与回退由中央按实际进程和数据库验收；写入本规划不表示冗余演示已经停止。

演示使用已明确标注的虚构家庭、成员和比赛素材。测试账号准备好不代表真实监护授权；示例封面、课程内容和模拟生成不能进入真实儿童效果结论。演示里也须能分清候选、已保存、已检查和已发布。

按以下顺序做一次完整走查并保留分步证据：

1. 唯一演示入口能看见三项一级导航，所有模块保持同源，旧演示入口明确归并。
2. 首次学习完成总结确认、进入首作、保存和修改、反馈与报告；回访恢复同一作品。
3. 在作品集中找到课程成果，添加一件明确虚构的工具作品，核对来源、版本与可见范围。
4. 进入黑客松第一张卡认识流程，再从第二张卡进入实践；完成共享、确认人数、排名投票、队长确认、任务领取、进展和同伴检查。
5. 完成提交准备、路演和复盘，核对报告实际状态；不能把演示填报当作真实赛事提交或名次。
6. 从本人作品请求一次获准模式的图片，完成自动归档、查回与选用；关闭重开仍找到同一资产。
7. 在390/768/1440视口与键盘、减少动效下切换模块，验证草稿、身份及单松伴状态。

实际测试分别记录UI替身、真实本地后端、真实供应商和真人观察；不把其中一种证据替代另外三种。出现问题后保留初次失败和复验记录。

## 十二 提交中央收口的未决项

1. **阶段解锁规则**：尚未决定课程或认识内容的强制前置；先维持清楚的推荐顺序和旧记录恢复，不以默认排版冒充业务解锁政策。
2. **新导航与兼容路由**：页面语义已确定，实际路径、别名和共享壳需由中央登记，保留当前学习及比赛深链接。
3. **图片服务与真实预算**：三类图片范围已确认；供应商、费用、次数、存储和unknown核对条件需在真实接入前成立，本路径不新增调用额度。
4. **外部工具成果与公开能力**：首版格式、文件限额、链接处理、公开入口与撤回细节由契约与权限收口，不因作品集UI存在就宣称均已实现。

本会话交付用户路径与页面规范，不修改业务代码、生成图片、调用真实模型或替真人填写观察结论。
