# H02 → H4 图片后端与豆包接线

日期：2026-11-02。实现文件为`app/platform_v1/images.py`与`doubao.py`，独立迁移`P03-images`与补充输入留痕的`P03B-image-inputs`；学习0.2.4／70操作、原角色及旧迁移checksum保持，P03B不修改P03 checksum。本轮没有豆包凭据，真实供应商调用为0。本文说明工程能力和启用条件，不宣称真实图片验收已完成。

## 官方接口与服务器配置

适配器使用火山方舟固定HTTPS图片端点，显式服务器模型ID、Bearer密钥、单图Base64结果、非流式请求和水印；不会抓取供应商返回的任意URL，也不自动重试。官方文档区分模型能力：支持组图的型号用`sequential_image_generation=disabled`请求单图；不支持该参数的型号必须在配置中关闭参数发送。模型不设猜测默认值，Endpoint ID返回实际模型名不同的情形需列入`allowed_response_models`。[火山引擎图片生成API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)

仅服务端构造`ImageSettings`，通过`PlatformSettings.image_settings`传给`create_app(..., learning_settings=已有学习设置, platform_settings=平台设置)`。`.env.example`仅给部署占位名称；当前没有把这些环境项自动转换为ImageSettings的加载器，填写`.env`本身不会启用出图。供应商密钥不进入前端、提示词、作业响应或配置repr。

主要配置项：

- `storage_dir`：持久、私有、可写目录；不能位于项目`static`。读图片仍经过授权接口，不把目录挂成公共静态资源。
- `config_version`、`live_enabled`、`api_key`、`model`、`allowed_response_models`、`size`：明确版本、开关与供应商资料；缺密钥或模型时live返回503。
- `supports_sequential_generation`：默认True，发送`disabled`；经核对不接受该字段的模型设False。不能凭前端传入模型名控制供应商请求。
- `image_limit`：当前配置全局真实图片请求计数上限，默认0；不是人民币金额或实际账单。`timeout_seconds / lease_seconds`与结果字节／像素上限有界。
- `image_consent_versions`：经过审核、确实包含图像处理用途的现有`live_model`授权文本版本白名单。为空时孩子不能发起live。不得把仅适用于旧文字练习的同意静默扩展到图像。
- `content_editors`：能制作课程封面的实际服务器账号白名单；必须处于manager/staff会话。孩子身份即使actor ID相同，也不能修改公共课程。
- `sample_enabled / sample_path / sample_limit`：独立的本地图样例开关、已有图片路径和次数上限；同时必须`PlatformSettings.demo_mode=True`。样例来源为`local_sample`、mode为`sample`，不是AI生成；不使用真实图片账户。

真实额度通过服务端`grant_budget('learner:'+learner_id, images, grant_key=唯一分配号, expires=有效截止时间, authority=明确配置来源)`分配；课程编辑账号用`actor:`主体。没有公共grant接口，也不因首次进入页面自动建额度。分配号幂等，配置指纹变更后旧额度不默默转移。真实测试需要配置和明确预算，本轮没有执行。

## HTTP与前端状态

中央按模块导出的`ROUTE_SPECS / REQUEST_SCHEMAS / RESPONSE_SCHEMAS`注册`/api/platform/v1`，共用cookie优先、CSRF、browser epoch、同事务复核和请求回执：

- `POST /image-jobs`：`request_id, mode, purpose, learner_id, target_id, target_version, expected_binding_revision, slot, prompt`，返回202。用途为`course_cover / work_cover / illustration`。本人作品ID用WorkSummary.id，版本用WorkDetail.current_version.id；封面slot为`cover`，插图使用独立有界ASCII槽名。
- `GET /image-jobs/{job_id}`：仅核对状态，不派发。响应含状态、来源、实际模型、asset_id、binding_revision、usage与can_recover；不返回原始提示、供应商响应或私有存储路径。
- `GET /learners/{learner_id}/works/{work_id}/image-jobs`：按当前作品授权恢复最新20条任务，逐条核对权限，刷新不依赖客户端保存job ID，也不触发派发。
- `POST /image-jobs/{job_id}/recover-storage`：仅在`can_recover=True`时启用。把同作业恢复到received等待存储，绝不重新生成。
- `GET /learners/{learner_id}/works/{work_id}/images`：返回当前target_version、当前版cover_asset_id和各槽最新绑定items。items含自身target_version与binding_revision；旧版本的槽记录用于下一次CAS，不得当作新版封面。无绑定时expected_binding_revision为0，有绑定时用该槽真实revision。
- `GET /courses/{course_id}/images`：相同绑定结构，只允许受控内容编辑账号。
- `GET /assets/{asset_id}`：授权后的元数据；`GET /assets/{asset_id}/content`：中央注册的图片字节入口，private／no-store、nosniff和同源资源策略。

子会话中的ImageService与中央接口均重新检查作品所属、当前授权、原课程entitlement及比赛关联；家长查看孩子图片仍需要原有效learning和parent_summary。家长可以看获准的作品图，不能代孩子发起作品生成或读取原始私聊。公开发布接口仍关闭。

## 作业、自动保存与恢复

`queued → dispatching → received → stored → archived`。HTTP写入只排队，中央lifespan定期调用`worker_once()`，或明确调用`execute(job_id)`处理一个持久任务；任何GET都不派发。

入队前冻结目标版本和slot revision，预占真实额度；派发前重新检查发起会话、epoch、当前图像用途授权、配置与额度有效期。供应商网络期间不持有数据库事务。收到图片后验证真实格式／像素／字节上限，先把结果字节持久化，再原子保存私有文件和版本绑定；用户已请求生成，不要求第二次点击保存。

输入快照保存明确的prompt_version、冻结系统提示、无密钥配置版本／请求模型／尺寸和目标版本；不把密钥或本机存储路径写入快照。首期仅文本生图，没有上传参考素材或图生图入口；因此不会伪造参考图授权和版本记录。

- `unknown`：派发后超时、失去确定回执或派发进程过期。保留额度和原请求号，不自动重发，也不把超时当成0费用。
- `storage_failed`：生成结果已持久化但文件保存失败，可恢复同图。刷新、重启或恢复不再调供应商。
- `archive_conflict`：图片已私有保存，目标版本／slot或发起身份变动导致不能绑定。保留资产，不改新版本作品，也不声称过关；重新关联功能尚未提供独立UI。
- `failed / cancelled`：确定拒绝或派发前权限失效等情况。仅确定未生成才释放预占；真实已返回图片按一次计数结算，不声称精确金额。

server-only `reconcile_unknown`只接明确供应商证据与操作者来源，可核实未生成并释放、核实已生成但图已丢失并占用额度，或用真实图片回执恢复私有存储。没有网页绕过入口；时间经过和用户猜测不能作为核对依据。该方法不发起生成。

封面与插图绑定有独立版本和历史，不修改原课程正文、作品版本、比赛方向、任务检查或成长报告。供应商返回图片不等于平台独立内容审核；当前私有资产保留／清理期、公开发布审核及管理端核对UI仍待后续明确。

`tests/test_platform_images.py`33项隔离测试，全部使用临时SQLite、合成授权与本地图／httpx.MockTransport；socket真实联网被测试fixture禁止。覆盖自动归档、sample/live额度隔离、无配置、授权与session撤回、unknown不重发、刷新恢复任务、存储失败重启恢复、版本冲突、跨家庭、课程编辑权限、图片路径保护、严格Ark参数与结果、幂等回执、未知结果人工证据核对、输入版本留痕和迁移checksum。

## 本轮交付边界

H2数据域、H4任务／适配／存取工程与同站HTTP边界已提供；页面与真实运行状态由中央统一验收。首期明确保留以下限制，不将后续扩展写成已完成：

- 没有正式豆包凭据、真实配置授权用途和新增调用预算，未验真实供应商效果、计费或时延；当前可用演示使用明确本地样例。
- `archive_conflict`保留私有资产及原目标版本，当前没有重新关联到新版本的专用UI或写接口；unknown核对仅提供服务端证据方法，没有管理端核对页。
- 作品默认私有；公开发布、独立图片内容审核、课程封面正式发布流程未开放。allowlist课程编辑账号可生成和私有回读，不等于课程发布。
- 外部作品首期登记链接；没有外部工具自动运行、文件导入、参考图上传或图生图。展示隐藏／删除等管理选项不影响原作品保存流程，本轮未新增其后端。
- 不同people账号的比赛来源关联凭据、多孩家庭、孩子直接执行旧比赛写操作沿用H0保守边界，不做自动身份映射。
- 私有目录的备份、容量与保留／清理策略由部署补齐；后台文件和DB中的已取得结果不会为了回退被自动删除或重新付费生成。
