# H02 → H0 数据接线建议

日期：2026-11-02；状态：只读代码审计与拟议契约，待中央冻结。本文不是已注册接口说明。本次只新增本文，没有修改认证、业务、数据库、迁移、配置或服务，也没有读取回显密钥、调用模型或图片供应商。

当前学习运行契约仍是0.2.4／完整启用70项操作，P0冻结0.2.1与既有迁移checksum保持。对应领域意图见[全程松伴与图片边界](../03-全程松伴与图片数据边界.md)、[作品衔接](../04-作品集与数据衔接.md)。

## 建议中央冻结的六项决定

1. 新增独立`app/platform_v1/`与`/api/platform/v1`，共用原SQLite数据库和学习认证权威，不再创建账号、登录凭据或孩子模式。新模块自有契约、迁移与请求回执；不扩写旧学习0.2.1文件或重算原迁移checksum。
2. 平台首期以`learn_learners.id`作为孩子作品、会话和图片的归属主体；`people.id`仅表示实际认证账号。比赛来源通过逐项目、明确字段的关联提议和孩子确认接入；不做全账号自动映射。
3. 学习作品直接投影现有artifact与不可变版本；比赛投影本人贡献；外部工具作品新增平台自有版本。作品封面与作品实际产物分开，默认私密，不另造学习检查或比赛通过记录。
4. 平台松伴统一外观、当前上下文引用与恢复入口；课程仍复用原help/model任务。个人、团队、家长与工作人员对话不共用历史。非课程模型调用另有显式配置与预算，未配置时只显示可辨识的步骤说明。
5. 图片使用独立作业、独立计量预算与私有资产存储；明确请求成功后自动保存，存储重试不重新出图，网络unknown不自动重发。生成或保存不等于发布、过关或已掌握。
6. 中央精确登记新平台路由对旧API隔离中间件的豁免；平台自身必须先具备同等cookie／CSRF／epoch／撤权检查。不得为了新大厅放开整个`/api`或旧bearer接口。

## 核对到的实际接线点

- `app/main.py:create_app`先注册studio、team_core、journey、materials、recap和workbench；传入`learning_settings`时才创建`LearningV2`、迁移、注册学习路由与安装`LegacyBoundary`。平台应在这一显式装配区接入，要求同一`learning_service`实例；缺少该实例时不开放私有平台接口，不退回旧token认证。
- `app/learning_v2/auth.py:password_actor`校验现有`people`账号并复用登录限流，返回的是`people.id`。`storage.py`中的`learn_sessions.actor_id`也引用people；只有孩子模式会话另有`learner_id`。
- `storage.py`中的`learn_families.owner_id`引用people，`learn_learners.family_id`目前唯一；`learn_links`记录关系及核验。不能据此支持多孩家庭，也不能将`session.actor_id`直接当成孩子的比赛成员账号。
- `service.py:session_row / learner / learning_access / effective`已分别检查浏览器epoch、会话撤销、资源所属家庭或当前孩子、有效关系与当前文本版本的授权；`scopes`供工作人员权限使用。不要用平台新布尔字段代替这些检查。
- `routes.py`在同一短事务内检查来源、CSRF、请求幂等、资源权限，再复核会话才序列化响应；cookie只在提交成功后设置。`Store.transaction`使用`BEGIN IMMEDIATE`，同库事务可复用。
- `integration.py:_Middleware.__call__`目前只豁免精确`/api/learning/v2`及其子路径，其他`/api`调用会经过`legacy_request_guard`；孩子模式会被拒绝。新增平台前缀若不显式接线，孩子无法使用；若简单放行旧接口，则破坏既有隔离。
- `course.py:owned`在返回artifact前核对孩子归属、learning授权和原课程entitlement；工作人员另需assigned_run。`entry.py`只接受已确认访谈的必要自述、管理者提议及孩子明确采用，没有提供全平台身份绑定能力。
- `team_core.py:access`依赖people bearer或受限连接器token及`squad_members`；`snapshot`包含全队成员、近期汇报、资料库和队伍代码，不能原样返回给孩子或家长。`workbench.py`已把模型上下文缩成必要团队事实、本人任务及本次明确选中的可读材料，是可参照的投影边界。
- `WorksPage.tsx`目前读取孩子的课程artifact与版本；`models.py`已有持久作业、预占、租约、unknown和用量核对，但只服务文本。`reports.py`有独立事实确认、人工审核和发布流程，不由平台素材保存触发。

## 认证与权限适配：新模块不成为第二套身份系统

建议`PlatformService`构造时注入`LearningV2`和同库Store。平台认证适配器只包装既有公开方法，不复制它们的实现；平台不接收客户端声明的actor、mode、family、verified、scope或remaining_budget作为授权依据。

私有请求的固定顺序：

1. `transport(request)`校验TLS或已登记的本机来源；JSON写入限制体积、严格解析、拒绝未登记字段及重复查询参数。
2. 同库短事务内执行`browser`与`session_row`；写入再执行`write_guard`。获得服务器派生的`actor_id / mode / learner_id / browser_id / epoch`。
3. 按操作执行`role`、`learner`、`learning_access`、课程`owned`或比赛来源关联检查；读取与重放缓存前也核对当前权限，旧回执不能绕过撤权。
4. 平台写入用自己的`platform_requests`，键为`actor_id + learner_id + mode + operation + resource_scope + request_id`；指纹含真实路径、规范化正文及schema版本。相同号不同内容返回409，不产生第二次业务写入。
5. 资源写入、事件、幂等回执和必要审计同事务提交；响应前再次核对会话及当前资源授权。私有响应`Cache-Control: no-store`；平台不返回任何bearer或供应商凭据。

只允许已发布大厅目录和不含身份、预算的能力配置匿名读取。管理者可读自己孩子获准作品及已发布报告；不能因此读孩子原始松伴私聊。孩子只能读当前`session.learner_id`；staff仍依既有scope／assigned_run处理原案件，不自动获得全作品库、全对话或课程编辑权限。首期不增加“平台管理员看一切”的角色。

跨标签或切换身份后，前端清空旧私有缓存并重新取session；后台作业保存不可变启动身份与epoch，派发前及关联资源前重新检查。不能把“当前页面没变”当成权限仍有效。

## people 与 learner：先做逐项目来源关联

现有模型允许一个成年人账号管理一个孩子；旧比赛记录按people成员存储。直接写`learner.person_id = session.actor_id`会把家长经历与孩子经历混在一起。建议首期只实现有界的`CompetitionSourceLink`，不引入永久账号等号：

- 管理者重新认证后，在其家庭下对某孩子提出一个比赛项目来源提议。服务器只允许选择实际认证账号在`squad_members`中的项目，`source_actor_id`固定由认证账号推导，客户端不能任填其他people ID。
- 提议时选择具体本人成果引用、本人任务／汇报引用和孩子贡献说明；服务器读取必要字段并冻结来源版本、摘要、材料引用及指纹。不能自动复制全队聊天、成员画像、队伍代码、草稿报告或私密附件。
- 孩子看到明确预览后接受或拒绝；保存`guardian_statement + learner_confirmed`的来源性质。接受只表示采用该项目贡献描述，不能描述成身份证明、学校认证或独立核验。
- 状态为`offered → accepted / declined`，接受后可`revoked`；任何实质内容变动创建新revision并重新确认。读取时同时检查当前家庭授权、关联状态与来源成员资格；关系、授权或成员资格失效立即停止派生展示和模型引用。
- 如果孩子真实使用的比赛账号属于另一个people，首期返回`source_account_mismatch`并保留未关联状态；不能用昵称、手机号相似、同设备或管理员直接指定来猜测。下一步可单独设计由真实来源账号重新认证产生的一次性关联凭据；该功能未实现前不得假装已接通。

这条方案能在不改旧角色与身份表的情况下安全接入确有授权的资料，但**不能让孩子模式自动执行旧比赛投票、领取任务或队长确认**。大厅先复用教学与原流程入口；若需孩子身份直接参赛，必须另行冻结真实参赛主体及旧业务写入授权适配，不能复用上述展示关联代替。

建议字段：`id, learner_id, source_kind='competition', source_project_id, source_actor_id, source_version, revision, state, selected_refs, contribution_text, redacted_snapshot, snapshot_hash, offered_by, confirmed_session_id, created_at, updated_at`。数据库为learner、source actor建立真实外键；同孩子／项目／来源账号最多一个当前关联。客户端提交`expected_revision`，其他主体及快照字段服务器派生。

## 三类作品的最小资源

平台`WorkSummary`统一包含：`id, learner_id, origin, title, summary, revision, source_ref, current_version, actual_outputs, cover_asset_id, contribution, provenance, visibility='private', updated_at, available_actions`。`source_ref`含领域、真实ID与不可变版本；`available_actions`服务器派生。opaque ID不作权限凭证，版本ID不能跨作品互换。

- **学习作品**：稳定身份指向原`artifact_id`，版本指向原version。列表与详情均经`course.owned`及原版本读取授权；保存、readback、检查仍由原接口处理。平台只增加封面和展示偏好，不复制正文来绕过entitlement、暂停或撤权。
- **比赛作品**：稳定身份用`source_project_id + accepted_link_id`；保留团队项目、当前方向／plan版本、所选真实产物链接和本人贡献。不能把团队完成状态直接写成孩子掌握或本人独立完成。源项目更新仅提示可刷新，不能静默覆盖孩子已确认的快照。
- **外部工具作品**：平台自有`work_id + immutable_version_id`，孩子明确提供标题、工具名、作品链接或允许文件、贡献与AI参与说明。封面不是实际产物。URL只保存并作为外部链接显示，不由服务器抓任意地址；首期至少支持链接，文件支持需有大小／类型／扫描规则后启用。

作品集是三类来源的投影，不是新一套任务系统。隐藏卡片不删除原课程／比赛记录。公开展示本期关闭，未来发布单列权限与审核；不能把`visibility='public'`作为任意PATCH字段。成长报告仍通过原报告事实和发布接口生成，卡片或图片不会自动成为已审核能力证据。

建议新增`platform_works`仅存外部作品主记录，`platform_work_versions`存不可变版本；`platform_work_presentations`存三类来源的封面／显示设置；学习正文和团队项目不进入这两张内容表。对关联撤销与删除保留最小审计，但不给前端返回已失权快照。

## 同一个松伴：会话引用统一，数据和执行分域

建议`ContextRef`固定为`domain='hall'|'learning'|'competition'|'portfolio', resource_id, resource_version, learner_id, selected_source_refs`。客户端提上下文，服务器生成`ContextSnapshot`，记录必要事实、当前可做动作、来源版本／指纹和授权摘要；系统提示、供应商凭据与其他成员资料不能进入客户端快照。

`CompanionSession`按`owner_actor_id + learner_id + mode + domain + resource_id`隔离；同一作品跨大厅、展开面板和工作台恢复同一引用，切到其他作品恢复其自己的会话。不同身份不得靠同一session ID合并历史。对话事件包含`id, seq, session_id, snapshot_id, kind, role, content, provenance, model_job_ref, created_at`；`kind`区分用户文本、真实模型回复、静态指引、操作建议与业务回执。

- 学习内部角色仍为`guide / tool_guide / creation_coach / review_coach`。课程对话继续走原help和model作业，平台存可授权读取的原事件引用，不另发一次模型请求、不另扣预算、不把AI候选自动保存成孩子作品。
- 比赛内部角色仍为`materials / direction / next_step`。旧workbench会话属于people；可向当前有权的本人账号投影，不能把管理者旧私聊直接变成孩子的聊天。孩子场景仅使用已接受的项目资料和获准来源建立新受限上下文。
- 大厅与作品集的新真实文本对话须有明确provider profile、提示版本、输入上限、独立预算归属和持久作业。可以复用文本作业机制，不能直接调用旧不受学习预算约束的workbench来绕过限制。未配置时返回`companion_live_unavailable`并显示静态下一步提示，明确不是实时模型回复。
- 会话GET不会触发总结、出图或续费；POST请求只执行明示动作。AI给建议不会自动投票、定方向、送审或发布。家长无权读取原始对话，报告以原审核后的摘要为准。

## 图片：存储、权限、预算与unknown

图片首期用途固定`course_cover / work_cover / work_illustration`。目标引用必须带类型、ID、版本及插图槽位；`course_cover`只有未来明确登记的内容编辑权限可写，普通孩子请求不能修改公共课程。首期没有该权限时仅读取已配置课程图，不新增虚构管理员授权。

建议新增`platform_image_jobs`、`platform_assets`、`platform_asset_bindings`、`platform_image_accounts/grants/ledger`。作业含`id, learner_id/actor_id, session_id, browser_epoch, target_ref, target_revision, slot, input_hash, prompt_version, provider_config_hash, reservation_id, reserved_units, state, provider_request_id, lease/fence, result_asset_id, timestamps`。供应商密钥仅在服务器配置，配置对象屏蔽repr；不写提示、前端、DB结果或日志。

状态必须能解释恢复方式：

1. `queued`：同事务记录幂等请求、冻结输入／素材授权与版本、预算预占。缺provider配置、允许模型、预算或用途权限时直接拒绝，不进入待调用队列。
2. `dispatching`：worker取得持久租约／fence，复核启动身份、授权与目标，再记录已开始派发。先提交派发标记，后做网络；数据库事务内不等待供应商。
3. `unknown`：派发后超时、连接中断或进程崩溃，不能证明供应商未执行。保留预占和provider请求号；刷新只查询，禁止以新request ID自动重发。仅供应商可验证回执或真实用量核对能结算／取消保留；不能因超时直接退款后再请求。
4. `received → stored → archived`：校验供应商结果为允许的图片字节、真实MIME／尺寸／大小和内容结果，先保存私有资产，再按目标版本CAS关联并结算。孩子已请求生成，成功后自动归档，无第二个“保存图片”阻断。
5. `storage_failed`：已生成但持久化失败，保留可验证结果引用与状态；使用原作业恢复下载／存储，不再发起生成。供应商结果已过期无法恢复时明确告知，不伪造已保存。
6. `archive_conflict`：图片已私有存储，但目标版本变化或授权撤回；不把图片挂到新版本或其他作品。保持原作业可核对、在仍有权限时允许明确选择新目标；不能重新收费生成来解决CAS冲突。
7. `failed/cancelled`：只有能证明未派发，或供应商提供确定失败与用量结果时进入可结算终态。终态必须保留实际计量性质；未知费用不写0。

图像额度计量与文本token账户分开，必须明确每个请求最大费用／计量单位、配置版本、有效期与授权授予来源。后续用户已选豆包，尚无图片凭据及新增真实测试预算；已有3＋6次文本真实测试额度已用完，不调用新真实服务。缺配置时UI可使用明确标注的本地样例，不记为生成成功；注入无费用测试adapter时也必须保留`test_fixture`来源，不冒充真实供应商。

最小存储可实现可配置本机私有目录，根目录严格解析并验证范围，资产ID映射服务器生成相对键，临时文件原子落盘并存SHA256；资源绑定不保存任意客户端路径。不能挂到`StaticFiles`公开目录。资产读取经平台GET代理重新校验当前身份、关联和来源权限；不发永久公开URL。未来换对象存储只替换适配器，保留资产ID、内容hash及授权；短期签名URL还需明确撤销窗口。

对供应商结果URL不做任意网络抓取：只信预配置provider白名单／SDK，拒绝重定向到内网与本机、超限字节和非图片；优先供应商返回字节。上传素材保存来源、授权用途与版本；撤回素材授权会阻止新派发和新绑定。已有生成物保留／清理期限及监护人可见范围尚待产品明确，不默认为无限保留。

## 拟议路由与实施拆分

以下只供H0登记，不代表已经存在；所有请求／响应须有独立schema与明确错误，不把随意JSON直接透传旧snapshot。

- H1：`GET /config`与`GET /halls`；公开部分只读发布内容，私有继续学／继续实践引用另经授权投影。
- H2：`GET /learners/{lid}/works`、`GET /learners/{lid}/works/{wid}`；外部作品`POST .../external-works`、`POST .../external-works/{wid}/versions`；比赛关联`POST .../competition-source-links`与`POST .../{id}/decision`，决定必须由当前孩子提交。
- H3：`POST /companion-sessions`解析合法上下文，`GET /companion-sessions/{sid}`恢复；平台新消息`POST .../{sid}/messages`只在其域功能配置成立时启用。课程session返回原run/task/help引用，继续原学习API，不创建镜像模型任务。
- H4：`POST /image-jobs`、`GET /image-jobs/{jid}`、`POST /image-jobs/{jid}/recover-storage`和`GET /assets/{aid}/content`。恢复操作复用原作业；任何新预算grant不提供孩子可调用路由。

新写请求统一有`request_id`、资源更新有`expected_revision`；只读响应有`revision/source_ref`。拟议错误至少区分`resource_not_found`（含越权）、`child_mode_restricted`、`source_account_mismatch`、`source_confirmation_required`、`source_changed`、`revision_conflict`、`idempotency_conflict`、`companion_live_unavailable`、`image_unavailable`、`image_budget_required`、`job_result_unknown`与`storage_unavailable`，均提供可核对原请求的恢复提示。

## 进入实施前的可检验结果与剩余条件

H0可先冻结以上字段和降级行为，允许隔离测试先跑。最低验收包括：两家庭互不可读；manager与learner切换后缓存与在途作业不可泄露；来源关联接受／拒绝／撤回和成员离队；学习entitlement失效；同号冲突不重写；模型unknown不重扣／重发；图已生成而存储失败可恢复；目标版本冲突不误挂；静态课程图、样例图与真实生成图可区分；家长看不到原始松伴私聊；作品／图片保存不改变原关卡、比赛和报告状态。
