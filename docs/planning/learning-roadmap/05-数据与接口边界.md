# 数据、接口与 Agent 边界

本文保留contract-intent 1.1.0的底座业务语义和原设计意图；P0冻结0.2.1不变，2026-11-02当前运行时为0.2.4／70项操作。最新新增边界见[全程松伴与图片](platform/03-全程松伴与图片数据边界.md)、[作品集衔接](platform/04-作品集与数据衔接.md)；H0冻结必要增量后才实施，本次文档没有注册新接口。下文简化列表及历史版本不能替换实际代码契约。

## 1. API 与认证分界

现有学习底座采用`/api/learning/v2`。原`/api/learning/v1/events`和sessions是样例/历史体验，不能直接升级成家庭授权。新接口独立注册，旧接口保留其限制和标记；不允许用旧演示session_id调用新学习资源。认证复用people等账号主体，但家庭、孩子学习、教师、运营的会话范围分别在后端校验。访谈确认只提供有归属和版本的必要起点摘要，不自动授予学习身份或替孩子同意。

孩子会话只允许访问本人有效学习者、已授权课程和尝试；家长只能管理有效关联的学习者；教师按分配班期/案件复核；核款、内容发布和后台角色不能从客户端字段获得。学习与管理会话切换需要服务端撤销旧管理授权，清私有缓存并丢弃迟到响应。

生产使用安全会话与 CSRF 防护；本机开发例外必须显式且不能继承到公网。家长关系记录声明/核验方式和授权范围，不把简单选择角色称为身份认证。起点先使用年龄段，年龄段最终由教研冻结，不假定此前举例已经批准。

## 2. 数据分组

- 家庭与访问：family、guardian_link、learner_profile、consent_version、scoped_session。访问凭证与业务内容分离。
- 内容：course_version、lesson_version、task_card、tool_card、role_prompt_version、review_rubric。已发布内容不可原地改写历史学习事实。
- 学习过程：enrollment、learning_run、attempt、learning_event、help_event、artifact_version、check、reflection。
- 模型执行：model_run、context_sources、budget_reservation、usage_entry、reconciliation_case。模型日志需保留用途、必要脱敏及保留范围，不无限期记录所有输入。
- 家长反馈：report_snapshot、report_review、publication、revocation。输出引用确切作品/检查/帮助版本。
- 运营：cohort、offer_version、order、entitlement、human_case、audit_event。MVP 手工核款不等于支付网关。

新增资源使用独立学习 ID 与归属键，不能用某个 squad_id 假扮家庭。个人学习不为绕过团队权限创建虚构队伍。不同表可按 P0 简化，但职责、来源和事务不能遗漏。

## 3. 核心状态语义

课程发布：draft → published → archived；旧学习保持绑定版本。单关：locked、available、in_progress、pending_review、needs_practice、passed。资格以服务端 enrollment/consent/检查结果决定，前端不能写 passed。

作品：保存产生不可变版本，另有当前草稿。检查绑定 learner、run、lesson、artifact_version 和 rubric_version；规则检查、AI 建议与人工结论分别标注。修改作品使旧检查不再支持新版本过关；下游解锁影响由服务端明确计算，不能无提示撤销已有成果。

模型运行：pending、running、succeeded、failed、unknown。供应商可能已接收的超时进入 unknown；保留预占，不直接退款并重发。核对案件有截止时间和责任人，最终按证据确认用量或有审计的调整，不编造精确成本。

报告：draft、pending_review、published、failed、revoked。生成完成不等于家长可见；已发布快照不可静默随学习变化。撤销使后续访问失效，但不能承诺抹掉已经下载的副本。

订单：pending、verified、closed、refunded；只有核验到款或明确试点授权才发放权益。权益到期/退款后的编辑、历史只读、报告保留规则由报价版本决定，具体期限在 P5 前冻结。

## 4. 写入、版本与恢复

所有有副作用请求带 request_id；同 ID 同正文返回原资源，不重复运行/扣款/发权益；同 ID 异正文 409。已有已知失败需要新尝试时由用户明确创建新 request_id，unknown 不自动重放。更新带 expected_revision，过期返回冲突与可恢复动作。

模型运行入库、预算预占、结果落盘和用量结算采用明确事务及唯一约束；上游调用不在数据库长事务中。进程中断后持久租约恢复，不能启动第二个仍有效执行。上游无幂等保证时不承诺严格只执行一次。

输入与草稿先保存后运行；报告生成不重跑作品；预算不足不丢输入。页面刷新与重启读取服务端事实，本地缓存仅辅助编辑恢复。内容版本变化后继续旧课或显式迁移，不能在半途偷偷替换验收规则。

## 5. 四角色统一调用

学习专属role_id为guide、tool_guide、creation_coach、review_coach，沿用现有冻结定义。现有比赛工作台roles枚举不直接改成这四个。新版儿童工作台默认呈现一个松伴，由工作流按当前任务选择内部职责；学习会话记录真实使用角色和提示词版本，共用模型不声称独立专家互证。

输入仅含当前学习者、课次、已授权来源、最近必要对话、作品版本、帮助历史与预算事实。输出为可见文本、有限建议动作、引用及必要的检查建议。建议动作使用白名单，例如打开当前工具卡、保存候选、请求人工帮助；不能通过模型文本指定任意 URL、执行终端、改变订单/权限/过关结果。

教学卡按关卡/主题/基础标签检索，结果带版本和来源；不检索到其他孩子私有材料。运行输出只作内容，不执行其中脚本和隐藏指令。首课工具为受控文本输入输出与固定预览，不接开放代码执行。

## 6. 报告与原流程适配

复用 parent_report/recap_reports 的来源引用与输出校验思想，新建学习来源适配。不能把团队任务分配当孩子已完成，也不能把仅有 AI 对话当独立创作。当前比赛报告接口和用户记录继续保留。

学习报告的观察必须指向真实 source_ids，区分孩子自述、系统保存、AI 建议和人工核对；没有证据可写尚不了解。家长报告不包含队友原话和完整私聊；老师复核有明确分配及审计。
