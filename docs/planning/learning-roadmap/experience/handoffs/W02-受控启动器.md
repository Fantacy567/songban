## 交付与参数

新增 `scripts/run_learning.py`、`config/learning.example.json`、`tests/test_learning_launcher.py`，未修改中央 main、已有启动器、默认 Settings 或原数据库。原 `app.main` 行为保持。

以依赖已安装的 Python 执行以下命令，路径需换为实际批准的目标。数据库必须是绝对路径，其父目录须已存在；备份目录必须已存在且位于当前仓库外。

```powershell
python scripts/run_learning.py --config config/learning.example.json --database "D:\approved\application.sqlite3" --origin "http://127.0.0.1:8901" --check
python scripts/run_learning.py --config "D:\approved\learning.json" --database "D:\approved\application.sqlite3" --origin "http://127.0.0.1:8901" --backup-directory "D:\approved-backups"
```

`--check` 只读取指定 JSON 和其中显式命名的可选模型凭据环境变量；不加载 `.env`、不打开数据库、不导入 `app.main`、不 bind 端口、不解析 DNS、不访问供应商。输出明确标为 `business_readiness=not_verified`。示例配置是暂停状态，工作台/导航可见不等于已开放学习写入。

运行时不提供默认数据库、域名或端口。host 默认为 `127.0.0.1`，也可显式 `--host ::1`；origin 必须是相匹配的 HTTP loopback origin，并包含 >=1024 的端口。端口不永久禁止任何既有编号，但若已占用则在数据库、备份和 app.main 导入之前拒绝。成功绑定的 socket 一直保留并传给 uvicorn，避免先检查后被其他进程抢占；退出时关闭。没有自动停掉其他服务的操作。

HTTPS 公网 origin 允许配置检查，直接运行会拒绝；公网域名、反向代理、TLS、cookie、访问控制与供应商 DNS 等仍按发布手册另行部署和验收。

## 配置边界

顶层仅接受 `schema_version: 1` 和 `settings`，拒绝额外键、重复 JSON 键、非有限数字、超过 64 KiB 的文件，以及 bool/int 混用。Settings 开关只能为 JSON boolean，时长为正整数；Settings 自身继续核对 TTL、origin、catalog/studio 等约束。`allowed_origins` 和 `loopback_http` 从显式 origin 推导，不接受 JSON 偷换。

可选队列为 `relationship_queue`、`learning_queue`、`support_queue`、`report_queue`，值为 null 或完整 ReviewQueue：`reviewer_id`、`display_name`、`due_seconds`、`support_contact_label`。只构造配置，不创建负责人账号、不发放 staff scope、不分配虚构授权。

`model_settings` 默认为 null。需启用时显式设置 `models_enabled: true` 并填写以下结构；此处所有值均为格式示例，不是已批准供应商、模型、价格或预算：

```json
{
  "config_version": "replace-with-approved-model-config-version",
  "base_url": "https://approved-provider.example/v1",
  "api_key_env": "SONGBAN_LEARNING_PROVIDER_KEY",
  "requested_model": "replace-with-approved-model-name",
  "allowed_models": ["replace-with-approved-model-name"],
  "pricing_version": "replace-with-approved-accounting-version",
  "input_unit_rate": 1,
  "output_unit_rate": 1,
  "max_input_tokens": 1000,
  "max_output_tokens": 200,
  "reservation_units": 1200,
  "timeout_seconds": 30,
  "lease_seconds": 90,
  "reconciliation_queue": {
    "reviewer_id": "replace-with-existing-approved-reviewer",
    "display_name": "核对负责人",
    "due_seconds": 3600,
    "support_contact_label": "替换为已确认的支持渠道",
    "escalation_actor_id": "replace-with-existing-approved-escalation-owner"
  }
}
```

只从 `api_key_env` 对应环境变量取值，不接受 JSON `api_key` 或 `transport`，不输出密钥、完整配置或库异常详情。模型 endpoint 必须是 HTTPS，拒绝 localhost、.local、已知非公网 IP 字面值、URL 身份信息等。检查阶段不做 DNS/供应商请求，因此“通过配置检查”不能证明域名实际解析到公网、供应商可用、真实模型准入或已经获得调用预算。预算单位仍按既有 ModelSettings 账本语义，不是货币。

实际启动会清除本启动进程中隐式旧供应商环境键，防止旧 `.env` 或通用模型配置悄悄启用其它模型路径；显式学习凭据已构造在 ModelSettings 中。不会修改父 shell 或私密文件。需要旧短信/邮箱/比赛服务的正式部署应单独复核配置，不能将该本机学习入口自动替代全部既有服务。

## 备份、迁移与业务资格

目标 DB 已存在时，必须先使用现有 `scripts/learning_backup.py: snapshot` 在线备份到新仓库外文件；备份包含已提交 WAL 内容，检查 integrity 和外键，不覆盖已有备份或原文件。备份失败则停止，不导入应用工厂。新库无需伪造备份，只在显式现存父目录下由实际工厂初始化。

由于 main 保留模块级默认 app，启动器在 TemporaryDirectory 中将这一次默认初始化指向临时 SQLite，禁用 load_env；工厂关闭初始化连接后释放目录，再用显式数据库与 Settings 调用实际 `create_app`。不动态改写 main、不执行 AST、不连接默认仓库 data 文件。真正业务数据库只运行原迁移和身份保护，不 seed 人员、家庭、监护关系、同意、课程、课程资格或模型预算。

负责人 scope、授权文本审批、监护关系、学习/真实模型同意、课程发布和权益、模型预算、unknown 核对负责人都仍必须通过现有受控流程完成。启动器不会把 JSON 中负责人名称视为已授权，也不会因为开关开启就批准模型请求。启用既有 worker 时，既有持久任务仍遵循服务端会话、授权、预算和租约规则。
