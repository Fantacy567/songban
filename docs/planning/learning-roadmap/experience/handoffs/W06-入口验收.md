# W06 新入口独立验收

日期：2026-11-02。范围：E1前端入口与旧访谈跳转的隔离验证。W06仅新增`frontend/learning/tests/entry-flow.cjs`及本报告，不修改业务或旧验收断言。

## 被测对象与方法

被测对象为`FirstWorkPage.tsx`、`EntrySummary.tsx`中的`EntryTransfer`、学习应用`index.tsx`的身份切换返回，以及`static/songban.js`和`static/songban-journey.js`的旧路由、流程门槛和访谈确认。

浏览器部分加载真实组件及学习应用代码，所有HTTP请求由Playwright拦截为虚构身份、课程、权益和摘要。管理模式切入学习使用真实`LearningApi`、会话更新及UI确认逻辑。旧站部分用VM执行从实际源文件读取的函数，验证入口意图、原流程门槛和确认目的地。未启动服务、未读取真实数据库/配置、未发送短信邮件、未调用真实模型。

## 发现与修复复验

1. **已有作品被目录故障拦住**：最初`FirstWorkPage`将home、courses、entry放在同一`Promise.all`，即使home已指向本人作品，目录暂停也会整体失败。反馈W00后，已有run路径不再依赖课程目录请求；独立“目录暂停仍恢复已授权作品”用例通过。
2. **旧访谈书签受残留学习意图影响**：最初无query的`#/interview`仍保留会话存储中的学习意图，明确打开旧比赛访谈会走学习。反馈W00后，无学习参数的旧访谈/起点清理残留意图，学习路径用明确`entry=learn`恢复；学习确认、比赛确认、比赛入口及旧书签四组检查通过。

以上修复由中央实施，本会话保留独立断言进行复验。

## 最终结果

命令：`node frontend/learning/tests/entry-flow.cjs`。最终13组通过，0失败，0浏览器pageerror：

- 已有作品直达，只读导航，无写请求。
- 首次有效课程快速双击仅创建一次；刷新后继续作品，不再创建。
- 无课程权益提供家长准备入口，不请求完整起点问卷。
- 已提供摘要须本人明确采用，写入来源记录的当前revision，不创建课次或自动过关。
- 本人可明确拒绝摘要，同样不写问卷/授权或自动过关。
- 管理方需勾选带入字段并确认访谈确属该孩子，发送精确source_version和字段范围；结果仍待孩子确认。
- 管理转学习保持`#/learn/first`目的地。
- 管理转学习保持指定run的深链接。
- 课程目录暂停不阻断已有作品恢复。
- 原访谈的明确学习入口确认后去`/learning-prep#/learn/first`。
- 原比赛访谈确认后仍去contest。
- 明确比赛入口在旧流程门槛执行前清理学习意图。
- 明确旧访谈书签不被残留学习意图接管。

证据：`E:\松伴\outputs\learning-experience\entry-flow\results.json`及`entry-final.png`。

首轮出现5项超时，原因是fixture使用相同path/query且只改变hash，浏览器未重新加载，导致后一场景继续使用前一场景已挂载组件。测试在每次场景打开时增加唯一fixture查询号后重跑通过；没有放宽断言或修改业务。首轮记录保留于同目录`first-run.json`。
