# E0 方案与契约收口

状态：工程完成：入口/身份/摘要契约已收口；工作台虚构交互及三种宽度已验证。见[实施与验收](../handoffs/W00-实施与验收.md)。实施前估算：1–2有效人日。负责人：W00集成，W01设计、W02身份衔接、W04教学提供输入。

## 交付目标

冻结“选AI学习、完成并确认简短访谈、进入第一个作品工作台”的可实施方案。复用P1–P4底座，明确原比赛入口、新学习身份和旧访谈之间的边界。

## 工作内容

1. 对照当前路由和身份保护，冻结入口意图、内部返回地址、旧书签及回访恢复优先级。
2. 明确谁的访谈可以用于哪个学习者，哪些摘要能引用、如何确认和撤回；不能根据同一浏览器或家长账号猜孩子身份。
3. 保留邀请卡为首作工程默认，列清必须由孩子完成的选择、保存、修改、自查、迁移和解释。
4. 形成宽屏/手机原型，展示一个松伴对话入口及三步/预览；原型只用虚构内容。
5. 核对已有help与model_run能否支持连续对话、来源及恢复；列新增字段/事件、权限、幂等、版本和出错恢复，不先制造第二套聊天后端。
6. 明确新入口及工作台的分环境开关、测试配置和增量迁移范围。

## 完成条件 GE0

- 首次、回访、老访谈、无课程、授权未完成、身份切换和旧比赛都有明确去向。
- 设计与实现者能指出每个按钮调用哪个已有操作、哪些需要新增契约；没有把普通导航当作发权益。
- W00登记共享文件所有权与兼容差异，真实模型预算保持未增加。
- 当前短访谈修复保留，不因规划修改已有回答或服务数据库。

## 交接与回退

交接给E1/E2：路由与身份决定、组件接口、内容版本、状态原型和验收输入。此阶段只冻结规格；不重启真实服务、不公开入口。若身份对应或契约仍不清晰，相关部分留待收口，其他独立UI原型可继续。
