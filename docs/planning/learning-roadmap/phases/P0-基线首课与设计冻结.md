## 目标与依赖

将用户决策变成可开发规格，核对现有代码，不改生产业务。输入为新宪法、总体框架、UI 规划、数据边界及当前未提交代码。首课先用受控文本“班级活动邀请卡”验证，不增加图像生成或任意执行依赖。

## 三个会话的交付

- S01：`p0/首课教学规格.md`。三关目标、孩子任务、虚构材料、作品、独立迁移、帮助、规则与人工检查、不同起点、待决事项及试用观察。
- S02：`p0/UI页面与状态规格.md`。三张样板及年龄引导、家长、后台的内容层级与状态；可补 `prototypes/` 独立静态原型，明确不接真实业务。
- S03：`p0/接口与迁移规格.md`。代码事实、资源与状态、身份/授权矩阵、完整请求响应、错误、事务、开关和旧系统迁移。
- S00 集成：核对三份规格的任务、动作、权限与状态一致，更新决策记录和交接；不替未评审内容盖章。

## 验收门槛 G0

三关各有可操作任务、可核对产出、检查和补练；四角色读取/写入边界明确；UI 每个主操作有对应接口；无团队可以完成课程；v1 不变为新授权；旧比赛入口和工作台 roles 保留；新账号/受限会话方案没有高权限残留。所有未决项列责任人和阻塞阶段。

UI 原型不算儿童可用性或真实模型验证；P0 可进入 P1 的条件是工程契约可执行且阻塞 P1 的事项已收口。未做真实孩子试用时须保留教研效果待验证标记。

## 不包含、风险与回退

不改 app/static/frontend 的生产实现，不发真实短信/邮件、不调用真实付费模型、不改用户 DB/插件配置、不部署。只新增规划和独立原型，可直接撤销文档改动；已有未提交工作不能 reset。发现旧代码缺陷只记入 S03，不混进新功能。

## 交接

每会话在 `handoffs/S0X.md` 写输入基线、实际文件、完成内容、验证、假设、未决与下一期入口。完成规格后停止，不自行开始 P1；集成会话按 G0 决定下一期能否启动。
