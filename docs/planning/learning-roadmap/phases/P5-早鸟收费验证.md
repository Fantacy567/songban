# P5：早鸟报名、权益与首批交付

依赖：可诚实展示的样板可用于早期意向/限量预售；实际交付必须G4通过。预售前交付范围、时间、人员和退款约定明确。建议一轮1–2周观察，名额/课次长度按真实人手确定，不预设已验证价格。

## 服务包与订单

首包只卖一个主题三关、明确次数/时段的人工支持、作品反馈及一份审核后报告。家长支付，不让孩子会话购买。价格、币种、有效期、支持量、真实调用预算、到期/退款后资料规则绑定offer_version，前端不能提交任意金额。

首轮可人工核验收款：pending订单、证明/凭据最小化收集、获准运营核对实际到账、verified后原子发放权益。上传截图、跳转返回和点“已付款”都不算到账。重复核验不重复赋权。退款先按明确流程实际办理，再登记并撤销对应权益；不能声称后台登记已经完成支付渠道退款。

本轮不自行选择收款账户、发布招生文案、向家长发消息或执行支付。需具体运营任务与责任人后实施。

## 运营闭环

报名→确认授权与基础设备→约定体验→完成三关→老师处理卡点→发布报告→访谈反馈→下一期意向。运营界面能看到待处理案件、超时、未完成/退款；不能只统计注册量。

## 指标与G5

在招生前定义统计口径与决策阈值，当前阈值未定不得补造：报名/到课/完成/报告阅读/下一期实际付款、主要卡点、每孩子人工分钟、实际模型与履约成本、退款及原因。区分口头满意、意向和真实付款，不把购买当能力进步。

G5至少具备一轮真实可追溯履约、清楚的问题清单、成本与真人支持记录、家长反馈及“继续/缩小/暂停某服务”的产品判断。样本小不推导全市场需求。数据展示采用汇总/别名，不公开儿童原始记录。

## 扩展与回退

只有可交付、成本可解释且有继续需求时扩课程和自动支付；否则先改内容/支持方案。不为增加收入无限开名额。暂停招生仍需完成现有履约、退款和资料保留约定；不能通过下线页面逃避已开通权益。
