# 报名与履约 UI 规划

更新：2026-11-02。本文件与[原型](prototype/index.html)仅表达拟议交互，不注册真实路由或接口。

## 与现有页面融合

继续使用现有米白、紫色、品牌字标、卡片与控件。孩子端仍是“当前学习／我的作品”，不添加商店、价格或充值弹窗。没有课程权益时保留起点和“请家长查看课程开启方式”，返回家长管理须重新认证，不能以点击家长标签代替。

家长页在孩子资料与已发布报告之后、长授权记录之前增加“课程与服务”区域。关系/同意未满足时优先说明下一步，不能先收款再告诉家长无法学习。已有课程时优先“继续安排／查看服务进度”，仅无活动订单时突出报名。旧比赛、连接器、资料库均不增加收费步骤。

工作人员在已有受权后台增加“报名与履约”，按真实scope和分配过滤。核款者只读订单必要信息，不获得作品、私聊或家长报告权限；教师也不因有案件得到核款权限。P5-A原型的视角选择只是演示器，不是正式登录方案。

## 家长的主路径

1. 看首包：学什么、留下什么、人工支持、时间与价格，服务/退款/保留文本可展开阅读。
2. 确认本人孩子及已批准条款，创建待核验订单；订单编号、报价版本、金额、截止时间和下一步清楚可见。
3. 支付方式只在正式收款主体与渠道配置批准后出现。当前原型没有收款码、账户、链接或付款表单。
4. “我已完成付款，提交核对”只记录本人声明，仍显示“待到账核验”，不发权益。收到实际渠道核验结果才显示“课程服务已开通”。
5. 开通后呈现约定场次、人工支持剩余次数、本人学习进度和报告状态；阅读/起点/课程流程沿用现有模块，不自动替孩子答题、建作品或送审。

## 工作人员的主路径

查看待核验、待安排、待反馈、待核对退款等队列。核款详情先对报价快照、金额币种、渠道凭据、归属和到款时间，再明确确认；凭据引用由受控导入产生，家长截图不进入“已核实”列表。

核验与发权益应一次提交且原子完成；网络结果未知先读取原操作，不换编号重复确认。金额不一致、超出保留时间、名额已满或证据重复时给出具体处置出口，不自动补差价、超售或退款。

退款申请、渠道办理、渠道结果核对、权益变更各有回执。结果未知时显示“正在核对退款结果”，保留原订单和已用额度；未核实前不展示“已退款”。

## 状态和文案

未批准：服务方案准备中。名额已满：本期名额已满，不能创建订单。暂停招生：暂不接受新报名，已有订单继续处理。待核验：尚未确认到账。已开通：显示服务期限，避免称“已学会”。待反馈：显示负责岗位、约定期限和联系出口；缺负责人时不能假装有人在线。

过期未付：订单已关闭，可查看原条款，若疑似已付款进入异常核对。课程到期：新练习暂停，受权历史按订单规则保留。退款未知：结果待核对；已退款：仅在确认实际结果后，说明被撤销的权益和仍可读资料。

## 布局与验收

桌面最多两列：主状态/下一步占主要区域，服务摘要为辅助；手机单列，不使用横向订单表。主操作在状态文字之后，技术凭据折叠在工作人员详情里。保留44px触控高度、可见键盘焦点、状态文本、减少动效和200%缩放。

实现时覆盖加载/失败、重复请求、版本冲突、断线刷新、过期/取消、未核实到款、核验成功、退款未知与历史只读；原型只能验证文案和转换，不证明服务器权限、交易原子性或真实到账。
