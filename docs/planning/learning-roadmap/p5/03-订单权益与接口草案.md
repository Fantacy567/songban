# S11：P5 订单、权益与接口草案

版本 `p5-commerce-design 0.1.0-draft`；日期2026-11-02。**仅P5-A可审阅规格，已交接冻结；下文全部P5资源、端点、权限、事务、规则与指标能力均为拟议、未实现、未验收。** 现有能力会明确标“现有”。本稿不改变运行时0.2.3契约，也不批准报价、人员、条款或收费。具体代码问题优先见[04兼容风险](04-兼容风险与验收用例.md)。

## 1. 当前阻塞与最小范围

1. 现有grant/enrollment没有付款来源、订单或凭据唯一性；不能作为已付款。
2. 现有课程与模型授权helper各自提交，不能直接串联核款。到期/撤销会阻断作品历史，报告却没有对应保留截止规则。
3. 现有模型预算按learner汇总，没有订单消耗归属；退款不能直接减总额度或释放unknown预占。
4. 没有名额保留、退款资金核对或招生专用开关。真实报价、核款人、退款/保留/交付规则未批准，开售条件不成立。

首版建议一个订单对应一个学习者、一个报价版本、一个班期名额；仅获准成人manager下单。课程、人工支持、报告和模型预算分别列交付项；课程支付不建立监护关系、不授予模型用途同意、不产生学习通过。仅登记人工核实的实际收退款，不提供自动支付网关、自动转账、分期、优惠券、代购、多人合单或跨孩子转让。续购/试点转购及部分退款按第9节待决，不隐含支持。

服务包建议与真实待定项归S00：[01服务包与决策单](01-服务包与决策单.md)、[offer.draft.json](offer.draft.json)。原型金额、建议人数、时长、次数和期限都不能转成默认生产配置。

## 2. 拟议资源、唯一性与状态（未实现）

所有新ID不含儿童姓名/联系方式；UTC时间用于存储，页面以家长时区显示；金额为币种对应的最小货币单位整数，预算为独立整数unit。修改产生revision及审计，证据与已接受快照不可原地覆盖。

1. **OfferVersion**：不可变服务条款快照，含course_version_id、price_minor/currency、服务开始/结束算法、人工支持范围/量、已受理交付截止算法、模型预算配置/units/到期算法、退款与历史保留policy版本、家长接受文本hash、审批引用。approval=draft/approved/withdrawn；是否可售由班期和招生开关共同决定。未知字段为null并不可售，不能以0表示未定。停卖不改旧订单快照。
2. **Cohort与CapacityLedger**：实际班期、获准排期/岗位分配版本、capacity_total、held、committed、retired及revision；状态draft/open/paused/closed。`held+committed+retired <= capacity_total`，名额消费/释放是有来源的账，不靠页面计数。retired表示已消耗且不可再卖的名额/支持容量；退款不自动补回。容量未配置不是无限。班期人与额度约束都满足后才open。
3. **Order**：payer_actor_id、family_id、learner_id由会话推导；offer/cohort版本、金额/文本hash快照、guardian/consent版本引用、status、revision、created_at、hold_until、verified_at/closed_at/refunded_at、close_reason、entitlement_bundle_id。主体状态保持05数据边界的 `pending → verified → refunded` 或 `pending → closed`；过期是closed(reason=reservation_expired)，不是伪造未到账。禁止PATCH status。退款子状态单独返回。
4. **SeatReservation**：order_id唯一、cohort_id、held/committed/released/retired、hold_until、verification_due_at（如采用延长核验）。同learner+course_version只允许一个未关闭购买意图，首版不支持同课已有enrollment再次购买；pending重复返回原单或409 order_exists，不再占位。关闭后新意图需显式新单。
5. **PaymentDeclaration**：家长可选提交“已办理/请核对”的声明时间、渠道公开别名和脱敏参考；不支持任意外链抓取或默认上传截图，不生成到账状态、不延长hold。记录是不可信声明，不能作为凭据唯一键。
6. **ReceiptEvidence / CashReceipt**：仅受控核款人员录入收款主体别名、渠道、规范化渠道交易引用的服务端HMAC键、金额/币种、渠道发生时间、核验来源引用、登记/核查人、查证时间；可保留受限脱敏附件引用。唯一键 `(payee_account_id, channel_id, transaction_key)` 不含订单号，跨家庭也不可复用。缺可靠交易引用不得自动匹配。相同引用冲突金额/币种进入差异案。状态observed/unallocated/allocated/exception，不向家长暴露全局匹配信息。
7. **PaymentVerification**：order_id唯一、receipt_id唯一（首版一笔款全额匹配一单）、verified_by、assignment_id、order/receipt revisions、evidence_ids、verified_at。退款之后仍保留原receipt分配唯一性。受控收款事实可以先被记录；只有本资源与权益成功同事务提交才令order=verified。
8. **EntitlementBundle / Benefit**：绑定唯一order_id及各item_key，记录source_kind=verified_order/pilot/legacy、来源ID、learner/course、start_at/end_at、active/expired/suspended/revoked、撤销原因和履约/历史policy。分开记录练习、支持量、作品复核、报告交付和历史访问，不能只有一个“会员有效”布尔值。数据库约束 UNIQUE(source_kind,source_id,item_key) 防重复赋权。旧grant保留原语义，来源未知不得猜测付费。
9. **BudgetLot / ReservationAllocation / BudgetEvent**：每批预算绑定order或明确试点来源、config_version、granted/settled/held/frozen/reclaimed、expires_at、资格状态及审计调整；预占明确分配lot与units，结算沿原分配。总账可为现有account的兼容投影，但不得只更新汇总。未知归属旧余额为legacy_unattributed，由专门迁移方案处理。
10. **RefundCase / RefundAttempt / RefundConfirmation**：case含order、申请原因类别、policy、申请人、assignee、due_at、升级与联系出口、approved_amount/currency及审批依据。状态 `requested → approved → processing → confirmed`，或requested→rejected/cancelled；processing可进入unknown或failed_confirmed_no_transfer，unknown仅凭核查证据转confirmed/failed_confirmed_no_transfer。每次实际办理有稳定attempt_id及渠道引用；活跃/unknown尝试期间禁止创建第二办理。confirmed有渠道实际退款证据、发生/登记时间、唯一外部退款引用。全额确认后order=refunded；申请/批准/登记尝试都不是已退款。
11. **OperationalCase / FulfillmentEvent**：到账不匹配、迟到到账、退款差异与已有交付例外均须assignee、due_at、escalation、联系出口及状态；事件记录约课/实际到课/人工工作分钟/支持消费/报告打开等，含occurred_at与recorded_at、actor、source_ref和修订。工作人员缺位不能显示“已安排”，也不能开售制造无人处理的待办。

持久约束至少包括：资金引用唯一、verification订单/凭据双唯一、order/item授权唯一、预算来源键唯一、名额订单唯一、每订单至多一个未决退款案、每案至多一个在途/unknown办理、退款引用唯一、model_run结算唯一及分配守恒。跨表family/learner/order/benefit必须复合归属校验和外键；不能仅靠不透明ID或内存锁。拟新增版本化迁移，由S00编号注册，禁止改写现有M01–M03 checksum。

## 3. 拟议权限与证据最小化（未实现）

沿用现有HttpOnly会话、Origin/CSRF、mode epoch、事务内末尾复核和no-store；不接收旧Bearer或连接器凭据作为家庭权限。所有复用逻辑仍需P5回归。

- manager仅给本人已核验关联learner建单；必须已具备所售服务必要的用途授权，模型live用途仍单独选择，不能因为付款被强制增加。付款人只读本人订单、声明、退款状态；同意/关系撤回后，保留仅payer身份限定的脱敏资金查询/退款出口，隐藏儿童内容。把learner_id换成另一个家庭一律404。
- learner禁止所有购买、资金/凭据、核款与退款端点；仅见本人课程是否可练习、历史可读、有限支持状态和“请家长联系支持”。模型、四角色及客户端字段都不能代为确认付款。
- staff拟新增`payment_record`（受控资金证据登记）、`payment_verify`（分配订单核款）、`refund_review`、`refund_record`、`admissions_manage`、`fulfillment_manage`、`operations_metrics`，每次另查班期/订单/案件分配和scope有效期。命名待中央冻结，现有白名单不具备这些权限。核款员不因此获得作品、私聊、报告或完整模型输入；老师不因此获得金额/到账凭据。
- 同一人兼岗要有独立授予和操作留痕；禁止核自己付款的订单。是否对录证/核款、退款批准/确认实行双人复核为D06，人员未配置不启用。当前“有staff grant就登录staff”的实现不支持随意切回manager；若兼任需明确中央身份接线，不能让一个会话同时拥有孩子、管理和工作权限。
- 退款或模型未知案必须有真实负责人、期限和可见出口。退款数据不复用usage_reconcile授权；财务人只得到“已用/待核对/冻结”等预算摘要，不需要生成正文。

凭证不收集银行卡全号、身份证、儿童学校/生日、完整家庭聊天或支付登录口令；正式账户/渠道未定时只写“待配置”。截图如未来确需上传，先另定受控存储、脱敏、授权下载、文件限制及保留策略；此稿不提供公共上传入口。服务端日志/请求幂等记录不存原始附件、账号、cookie或密码；审计只存引用、hash、理由类别、操作者、前后版本及必要金额。HMAC键不能直接回传前端；变更密钥需保留查重能力。

资金证据、学习资料和统计事件分别配置保留policy；具体天数待定。学习同意撤回不自动删除依法/依约需核对的资金最小记录，但本稿不确定其法律期限或用途依据，由负责人批准。历史文件可见性与物理保留分开，不承诺删除已下载副本。

## 4. 拟议端点与协议（全部未实现）

建议沿 `/api/learning/v2` 增量，运行时版本号与最终operation_id由S00冻结。以下不是当前可调用地址。所有写入JSON需request_id；更新需expected_revision（所属聚合见各项），拒绝未声明字段；请求不能直接提交paid、价格、收款账号、owner、scope、passed或任意entitlement。

1. `GET /offers`、`GET /offers/{offer_version_id}`：仅已批准可展示服务的公开摘要，无私人信息，售卖状态与余量提示不是名额保证；家长接受的原文/hash须服务端提供。draft不公开。
2. `GET /orders`、`GET /orders/{order_id}`：manager仅本人；staff另用分配队列。返回订单快照、hold_until、payment_state、refund_state、履约摘要、明确allowed_actions及支持出口，绝不返回全局凭证键。
3. `POST /learners/{learner_id}/orders`：manager；请求 `{request_id,expected_revision,offer_version_id,cohort_id,accepted_terms_hash}`，expected_revision属于learner。金额从offer读；同事务生成pending与名额保留，learner修订递增；201 Order含parent_revision。课程尚未具备/同课不可续购在此阻断，不能拖到收钱后。
4. `POST /orders/{order_id}/payment-declarations`：manager；order revision，加渠道别名/脱敏参考，可选。201只表示声明已记录，订单仍pending。`POST /orders/{order_id}/close`：manager取消或获分配admissions人员处理未核实单；order revision+reason，200 closed；有未决到账关联时转核对案，不能称款已退。
5. `GET /payment-cases`、`GET /payment-cases/{case_id}`：仅分配payment人员，最小订单与查证投影；无分配404。队列先按权限过滤后分页。录证使用 `POST /payment-cases/{case_id}/receipt-evidence`（payment_record，case revision）；201受控证据/CashReceipt引用，不能直接赋权。查证来源必须属于获准渠道，不能信任家长声明里的金额。
6. `POST /orders/{order_id}/payment-verifications`：payment_verify+订单分配，order revision；请求另含receipt_id、receipt_revision、evidence_ids，服务端核对实际到账。201 VerificationResult含order_id、verified_revision、entitlement_bundle_id、seat_id、budget_lot_ids和ledger/audit引用；不返回新的高权限凭证。不同号重复核同一完成订单409 order_already_verified，可GET原结果；同号同文按原结果恢复。
7. `GET /learners/{learner_id}/benefits`：manager本人可见业务权益，learner只见学习投影；不会把enrollment.status改成付费状态。现有 `POST /learners/{learner_id}/enrollments` 继续只消费有效课程权利；未来通过order唯一映射提供entitlement_id，不接受付款字段。核款提交即有权益，enrollment作为后续可幂等兑换步骤，未创建enrollment不能反推未付款。
8. `POST /orders/{order_id}/refund-cases`：manager本人或被分配的refund_review代录申请；order revision+reason_category+可选脱敏说明，201 requested；一次只一案。`GET /refund-cases/{case_id}` 返回本人/分配范围的状态、金额是否已批准、负责人及出口，不暴露内部渠道凭据。
9. `POST /refund-cases/{case_id}/decisions`：refund_review+分配，case revision；decision=approved/rejected和policy/evidence引用。金额由冻结规则推导或受控例外批准，不能按模型建议计算。200 case；金额/规则不明时保持待决，不自动全退。
10. `POST /refund-cases/{case_id}/attempts`：refund_record+分配，case revision；稳定办理参考和受控批准引用，201 processing。**只登记线下已开始的办理，不执行外部转账**；办前应先获得稳定case/attempt引用，实际渠道操作另有授权任务。
11. `POST /refund-cases/{case_id}/observations`：refund_record+分配，case revision+attempt_id+outcome=unknown/confirmed_no_transfer+证据引用，200 case。unknown不能用时间推成失败；confirmed_no_transfer须可核查证据，才允许之后新办理尝试。
12. `POST /refund-cases/{case_id}/confirmations`：refund_record+分配，case revision+attempt_id+受控退款证据、渠道引用/发生时间；201 RefundConfirmation，事务内登记真实全额退款、order=refunded和对应权益撤回/额度冻结。没有证据返回422；不能接受“已点击退款”。不同正文冲突和已退款订单不能再次撤权。另拟 `POST /refund-cases/{case_id}/exceptions`：相同权限/版本，登记已核实的部分退款或矛盾迟到结果，201受限差异事件（含实际金额、币种、外部唯一引用、证据），并派差异案；不改为全额refunded，不再次办理付款，保持消费冻结直至受控处理。已知部分退款金额在资金账单列，不混成unknown或0。
13. `POST /cohorts/{cohort_id}/admissions-state`：admissions_manage+班期分配，cohort revision+paused/open+reason；200。恢复open仍需重新满足审批/人员/容量；不能通过“恢复”绕过正式批准。是否支持修改容量由独立受控配置版本决定，不能降到低于承诺容量。
14. `POST /orders/{order_id}/fulfillment-events`：fulfillment_manage+分配，order revision；事件类别、实际时间/分钟、源引用，201。资金人员无此权限；手工更正追加反向/修订事件，不篡改旧记录。
15. `POST /reports/{report_id}/open-events`：manager+当前published且可读，request_id+publication_id；201只确认本次明确显示事件，唯一(publication_id,actor_id,event_kind)记录首次打开。GET/预取不产生此事件，也不等于理解。`GET /cohorts/{cohort_id}/metrics`：operations_metrics+分配，仅汇总/别名及缺测状态。

通用响应采用现有error结构。拟新增业务错误：409 offer_changed/order_exists/capacity_exhausted/order_expired/order_already_verified/receipt_already_allocated/payment_mismatch/refund_unsettled/purchase_requires_review；423 admissions_paused；503 admissions_unconfigured/support_unavailable；403缺scope/孩子限制；404跨归属/未分配；422非法字段/证据；401失效会话。精确code与恢复枚举待中央契约核对，不能先在前端硬编码。已撤回报告沿用410。钱已到但不符合核款条件时，业务错误不能删除CashReceipt，应明确资金待处理案。

幂等沿现有 `(actor_id,effective_scope_id,operation,request_id)` 与规范化正文/路径指纹；同号异文409；先当前身份/资源权限，再查幂等，再校验revision和状态。scope绑定稳定父资源，跨actor仍靠业务唯一键防重。原始成功结果和当前状态分开：重试可返回原事务结果，但客户端随后GET当前order，避免退款后把旧核款回执展示成现有有效权益。网络未知先GET或原号重试，不提示再付一次。

## 5. 拟议关键事务与名额恢复（未实现）

**T0 创建与保留。** 同一短写事务内：核验manager/本人关系/必要consent、报价已批准且文本hash匹配、招生open、实际值班容量、learner修订及同课限制；条件扣减可售容量/增加held；写pending订单+不可变快照+SeatReservation、已分配payment case（核款人、核验期限、升级与联系出口）、learner revision、审计、幂等。并发以DB唯一键和条件更新保证，不能先读余量再无条件插入。保留期限服务端计算；值未冻结时503，不用建议时长补齐。闭单仍保留原payment case的迟到款登记路径；无法对应已有订单的受控到账由获准核款人员在班期分配范围建未匹配款案，拟议 `POST /cohorts/{cohort_id}/unmatched-payment-cases`（payment_record，cohort revision，201），不自动生成孩子或权益。

**T1 到期、取消和暂停。** 服务端时钟到期任务幂等地将未承诺hold释放并关单；原子条件为pending、相同revision、未分配款/没有有效受控核验延长。家长付款声明不无限占位。是否允许有受控到账依据的待核单延长到verification_due_at是D02；无决定不可售。暂停招生只阻断新T0，仍允许期限内原单核验。过期已关单后发现真实款，保存未分配到账及有负责人差异案；不复活原单、不抢别人的名额、不静默退钱。重新安排名额需明确新单/新接受与原receipt的唯一分配事务。

**T2 真实到账核验并赋权。** 先以受控记录保留真实到账观察/证据，这一步不授课。核款事务内重验staff scope/分配、订单归属与revision、报价快照、有效保留及可履约条件、关系/同意当前性、金额/币种/收款主体、receipt唯一性/版本；写PaymentVerification和receipt allocation、order=verified、唯一课程/支持/报告权益、预算lot及总账兼容更新、held→committed、audit+幂等，一次提交。后续enroll仅兑换课程权益。任何写失败整笔T2回滚；预先登记的未分配真实到账继续可核对。若失败因关系撤回、金额不匹配或保留过期，建立异常处理案，不能把已到款改为“没付款”。

数据库事务内不得查外部支付平台/模型；不得调用当前会另开事务的grant helpers。内层函数接同一个con，相关唯一约束入数据库。若未来不是同库，必须另审持久outbox/补偿与“待开通”状态，不可继续宣称原子verified；本稿推荐首版同库。

**T3 退款状态登记。** 申请/批准不等于实际退款。case/attempt有稳定ID，先落盘再线下办理，返回未知就挂在原attempt；不自动重复渠道动作。若线下已发生退款而前序登记缺失，由受控异常补录关联原事实，不引导再办理一次。实际确认事务重验退款scope/分配、case/order revision、批准金额、退款证据来源/渠道唯一引用、实际到账累计约束；写confirmation、order=refunded（首版全退）、撤销该order的未履行权益、冻结其未用预算、容量转released或retired、审计+幂等，同次提交。证据冲突进入差异案，不能覆盖旧confirmation。

**T4 资金事实与模型核对分别结案。** 已确认全额退款可以登记refunded，即使模型unknown未结；同时明示budget_reconciliation_pending。不得因预算待核对阻止保存真实退款事实，也不能因此把成本记零。已发调用无权重发，迟到输出不复活练习/报告；原有usage案件与资金退款案各有负责人和权限。

**T5 暂停与保留。** admissions=false不影响既有有效权益和履约，不能使用learning enabled/course_enabled代替。紧急全停允许资金登记/核对、退款、隐私撤回和受限历史读；无法继续教学时如实进入运营安排。回退先停新单/新派发，保留资金、权益、未知账、访问控制和受限核对代码；不能删除新表或回滚到不理解新权限的旧版本。

## 6. 拟议课程与模型预算分离（未实现）

课程权利负责能否练习/编辑，预算负责特定配置下是否可生成；模型还需live同意、配置、值班和派发开关。人工支持量、模型units、服务售价和退款金额四者不可互相推导。付费不意味着预算无限；额度已用尽仍保留草稿与已保存结果，给出支持出口。

每个预算lot满足 `granted + authorized_adjustments = available + held + settled + frozen + reclaimed`，各余额非负；调整是有来源的独立事件。active且未到期的available才可预占，按批准的确定顺序（建议本run对应权益来源优先，再按有效期；不得跨订单隐式借用）分配。订单退款/到期只将剩余available转frozen/reclaimed，不回写settled、不动其他lot。unknown的held沿原分配保留；结算后剩余释放量若lot已关闭进入frozen/reclaimed，不能回到可用余额。

现有account/ledger迁移必须保持账实一致；grant_key改作稳定order+item+配置来源键，不能每重试随机生成。无明确分配的旧job/余额保留legacy归属；若无法安全分摊，应阻止混用并转人工迁移，不捏造订单历史。新批次不能借当前MAX(expires)延长旧批次。用量成本未知继续null；行政预算调整不是渠道退款，也不是供应商确认免费。

退款unknown期间推荐只冻结该订单新增消耗，保留历史与已受理支持出口；是否暂停课程编辑由D04批准，界面不得写成“已退款”。为了不重复退款，确认未执行须有受控证据；unknown超时只升级不自动释放。模型已dispatch的held和费用核对始终保留，不受退款状态推定。

## 7. 拟议历史访问与已受理交付（未实现）

分别返回 `practice_access`、`fulfillment_access`、`history_access` 及原因/截止，不把到期渲染为所有资料消失。建议服务到期禁止新练习/生成，仍在已批准保留期内读取本人作品版本、检查和已发布报告；这些规则必须绑定order接受的policy。家长仅已发布快照，草稿仍拒绝。孩子历史会话和返回管理继续守既有模式切换，不能用订单恢复高权限。

作品/报告保留各自起算事件、read_until、物理处置/导出安排与受权人员必须冻结，不能含糊写“永久保留”。退款不得删除作品/学习通过/审计；是否保留已发布报告与多久由policy决定。关系、用途撤回或报告撤回优先于商业保留权；重新支付不恢复撤回数据。

已受理的作品复核/报告需单独fulfillment_due_at，可在practice结束后完成该案的审阅与发布，仍需scope/分配、证据版本、报告批准、当前关系/同意。它不授予新练习额度。若到期前未送审怎么办、补练后复核次数和超期出口由S00决定；未明确不可对外承诺“含报告”。资料保留期间支持财务异议的最小渠道，与读取儿童资料分别授权。

## 8. 拟议运营事件与指标（未实现）

按[05运营指标](05-试点运营与指标.md)落实事件来源，S11只定义接线，不设转化阈值。每个汇总带window_start/end、as_of、cohort/offer版本、分子分母、排除条件、source_ref与coverage；无分母显示不适用、无来源显示未测，不填0。

1. 订单数按order_id去重，pending/closed/verified/refunded分列；独立家庭数不能当订单数。
2. 实际核款金额来源PaymentVerification，按币种；到账未匹配款单列。退款确认按渠道实际发生时间与登记时间分别可追溯，unknown单列；净款项不是利润。
3. 到课由获分配人员有依据记录，登录不算到课；完成从对应run人工通过及版本事实读取，支付/AI生成不算学习成效。
4. 报告区分生成/审核/发布/撤回/明确打开；新增open-event仅代表打开，不代表理解或满意；报告重版按publication_id计算，不混淆同一家庭多版本。
5. 人工工时按工作事件实际分钟汇总，未知不填0，案件排队时差不当工时；模型成本按受控供应商账单来源，unit不可换成人民币，未知成本阻止精确利润展示。
6. 下一期意向、再次报名、再次实际付款分别记录；当前首版续购若未支持，应显示未观察，不能把意向代填付款。卡点、退款原因、未按期交付和未知核对案件需可追踪的别名统计。

指标仅限获准班期汇总，不导出儿童全文、证据截图或未经授权的团队来源。退款后旧完成/工时事件保留，防止通过删除订单美化效果。G5必须另有真实履约证据，本稿没有该数据。

## 9. 待决规则与接线顺序（未实现）

下列均待S00汇总给产品/实际责任人决定；推荐只是设计假设，不代表用户批准。未知项阻断对应上线配置，P5-A审阅可继续。

- **D01 报价与交付**：按S00服务包填价格、币种、实际时间、支持/补练/报告范围、开始和结束算法；可选按约定开始或按核款开始，推荐约定开始并让家长接受明确日期，不能因运营核款延迟偷偷缩短服务。责任：产品/教研/运营。
- **D02 名额保留与核款期限**：可选短固定保留或“固定保留+已有受控到账证据时一次核验保留”；推荐后者但必须有最大核验期限/负责人；时长、到期前款已到而核款稍晚如何处理待定。禁止家长声明无限续占。责任：运营/核款。
- **D03 同课续购/试点转购**：首版禁止并前置提示，或正式设计绑定迁移；推荐先禁止。若当前首批家庭均已有试点enrollment，必须先明确该决策，不能用新建孩子/新课程伪装购买。责任：S00/产品。
- **D04 退款规则**：首版仅全退登记或同时支持部分退；推荐首版全退、部分实际退款进入异常真实登记并不误标全退。开课前/已部分交付/平台无法交付/报告已发布的金额算法、时间与unknown期间消费限制均待批。已实际发生款项不得因系统不支持被抹去。责任：产品/运营/资金负责人。
- **D05 预算归属**：采用按来源批次，或仅在明确隔离的新试点人群禁混用；推荐批次方案，legacy预算仍需迁移审阅。正式模型配置、unit、额度、有效期、用完处理和unknown负责人未定；本轮不会调用模型。责任：S00/模型用量负责人。
- **D06 岗位与核查**：录证/核款、批准/确认采用双人，或允许获准兼岗；推荐具备人员时双人，任一方案均不允许自核本人订单。需真实主责、替补、期限、联系出口、收款主体/渠道；本稿不命名任何人。责任：运营/资金负责人。
- **D07 历史与已受理交付**：保留期/起算、报告是否与作品同期限、退款后访问、导出/删除及未完成报告期限；推荐商业权利结束后仍保留有限受权历史，期限由负责人批准。法律保留依据另行确认，不由研发设天数。责任：产品/数据负责人。
- **D08 暂停与复售**：推荐独立招生开关；容量退回或retired、暂停后已有pending是否继续核验及紧急故障出口需冻结。责任：运营/S00。
- **D09 兼岗会话与指标**：决定staff购买自己孩子服务的显式manager模式路径；核款本人永远禁止。指定事件录入者、统计窗口和继续/缩小/暂停阈值，缺项保持未测。责任：S00/产品。

建议接线顺序：先冻结D01–D09及正式试点前提 → S00批准新增契约/scope/默认关闭开关及迁移 → 内部同事务grant写入、预算批次、历史授权拆分 → 订单/名额/收退款与受限运营投影 → 家长和工作人员页面 → [04的A01–A20](04-兼容风险与验收用例.md)隔离并发/故障/恢复与旧回归 → 单独申请真实收退款及真实家庭履约验收。现有代码和中央文件本期全部只读；不自动进入P5-B，更不启动P6。
