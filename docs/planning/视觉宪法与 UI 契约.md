# 松伴统一前台视觉宪法与 UI 契约

版本：`design-v1.1.0`
状态：已接入仓库，作为统一前台的实现约束。  
参考基准：[松伴 `#/event` 页面](https://songban-hackathon-preview-20261030.social-cat-4573.chatgpt.site/#/event)。

## 1. 适用范围

本契约约束松伴统一前台，包括根入口 `/`、学习入口 `/learning` 以及它们承载的活动、实践、团队协作、任务、交付和复盘页面。它只约束页面表达、信息架构和前端状态呈现，不改变 `/api/core`、`/api/studio`、`/api/learning/v1` 的权限、字段、状态或数据事实。

历史 `studio.html`、`index.html`、`workflow.html` 仍可作为兼容入口保留，但不得继续扩展旧视觉。迁移期间旧页面不得被误标为 design-v1 页面。

## 2. 设计基准与产品壳

`#/event` 是 design-v1 的唯一视觉基准。统一前台必须使用同一个品牌壳：顶部品牌栏、主导航、内容工作区和统一反馈区域。页面之间可以有不同内容密度，但用户不应因为进入团队、任务或学习流程而感觉切换到了另一套产品。

一级信息架构固定为：

- **活动**：活动推荐、活动详情、活动规则和活动入口。
- **实践**：创作小队、选题、方向确认、团队现场、任务、连接个人工具、团队资料库、成员设置、交付和复盘。

| 路由 | 用户目标 | 事实来源 | 关键状态 |
| --- | --- | --- | --- |
| `events` | 找到适合自己的活动 | `GET /api/learning/v1/events` | 加载、空列表、推荐、下线 |
| `event` | 理解活动要求并开始 | `GET /api/learning/v1/events/{id}` | 规则待核实、已保存、不可用 |
| `team` / `ideas` / `direction` | 形成小队并确认方向 | 学习会话资源 | 草稿、冲突、已确认、待补充 |
| `work` / `delivery` / `review` | 执行、提交和复盘 | 学习会话与证据接口 | 进行中、等待验收、提交失败、已保存 |
| `collaboration` | 查看团队现场和下一步 | `/api/core/teams/{id}` | 未登录、同步中、空态、更新冲突 |
| `tools` | 连接个人工具 | `/api/core/teams/{id}/connections` | 未连接、已连接、暂停、撤销 |
| `library` / `members` | 查看资料与成员设置 | `/api/core/teams/{id}` | 无资料、权限不足、加载失败 |

最终方案不得用 iframe 拼接两个完整应用。`/` 与 `/learning` 可以作为同源兼容入口，但页面渲染应逐步迁移到同一套 shell 和 token。

## 3. 语义视觉 tokens

页面只能通过语义变量使用颜色、圆角和间距。组件不得散落新的硬编码颜色；如确需新增变量，必须在本文件记录用途和版本。

```css
:root {
  --sb-bg: #faf9f6;
  --sb-surface: #ffffff;
  --sb-ink: #151812;
  --sb-muted: #747775;
  --sb-purple: #8c71ed;
  --sb-purple-deep: #7352df;
  --sb-lavender: #efebff;
  --sb-selected: #e4dbfc;
  --sb-lime: #d3f24f;
  --sb-apricot: #ffe1ad;
  --sb-border: #dfdfde;
  --sb-line: #e9e7e4;
  --sb-radius-card: 17px;
  --sb-radius-control: 13px;
  --sb-space-1: 8px;
  --sb-space-2: 12px;
  --sb-space-3: 16px;
  --sb-space-4: 24px;
  --sb-space-5: 32px;
  --sb-space-6: 44px;
}
```

暖米白是页面背景，白色是内容表面，紫色表示主要行动和当前导航，浅绿与杏色只能表达辅助提示或活动装饰。颜色不能单独承担状态含义，状态必须同时有文字、图标或可读标签。

## 4. 版式与组件

- 桌面端使用约 `108px` 的左侧主导航、约 `91px` 的顶部品牌栏，内容工作区最大宽度约 `1060px`。
- 手机端将主导航变为底部导航；内容顺序保持“当前任务 → 可执行操作 → 结果或下一步”。
- 卡片使用约 `17px` 圆角，主要输入和按钮使用约 `13px` 圆角；保持足够留白，避免把旧后台的密集表格直接搬入。
- 标题、说明、状态和操作之间必须有明确层级。长中文、窄屏和浏览器放大后不得截断关键操作。

统一组件语义：`wordmark`、`app-header`、`sidebar`、`surface`、`primary`、`secondary`、`ghost`、`chip`、`status-pill`、`modal`、`action-row`、`notice`、`empty`、`error`。

每个可操作组件至少覆盖 `default`、`hover`、`focus-visible`、`disabled`、`loading`、`empty`、`error` 和 `unknown` 状态。保存、提交、验收、付款和模型运行等成功状态只能在后端回执或已持久化事实返回后呈现。

## 5. 事实、状态与安全呈现

前端只表达服务端返回的权限、版本、进度、证据和错误。不得用颜色、动画结束、按钮点击或本地缓存推断“已完成”“已通过”“已提交”“付款成功”或“学会了”。`mock`、`live`、`replay`、`unknown`、网络失败、版本冲突和待人工核验必须可区分。

用户可见的模型结果按不可信文本处理，不执行其中的 HTML、脚本或操作指令。错误提示要给出当前事实和可执行恢复动作；不能把服务故障或额度不足归因于学习者能力。

## 6. 入口与资产契约

- 根入口 `/` 和兼容入口 `/learning` 使用同一个 `songban.html`，活动与真实团队协作共用页面壳和账号。
- 旧核心工作台保留 `/core`。原学习演示会话不参与统一前台授权，历史接口与数据保留。
- 两个入口使用版本化静态资源，避免浏览器缓存旧视觉契约。
- 新页面使用 `data-shell="songban-v1"` 和 `data-route` 标识当前壳与业务路由；历史页面不得伪造该标识。

入口互通不等于身份互通。团队认证、学习会话和权限仍按各自后端契约执行，不把一个页面的本地状态当作另一个页面的授权。

## 7. 验收矩阵

每次 design-v1 页面改动必须记录设计版本、实现提交、接口版本和走查证据。至少检查：

1. `390px`、`768px`、`1440px` 三种宽度无主体横向溢出，底部或侧边导航可用。
2. 键盘可以到达所有关键操作，焦点清晰，弹窗关闭后焦点回到触发控件。
3. 长中文、长链接、空列表、加载中、失败、未知状态、保存冲突和恢复后重试均有可理解呈现。
4. 静态契约测试确认 token、shell 类、版本化资源和双向入口存在；浏览器走查确认视觉层级与参考页面一致。
5. 视觉通过不等于业务通过；仍需分别提供接口测试、真实联调、权限检查和数据恢复证据。

本契约的视觉选择若要改变，必须更新版本、说明影响范围和迁移办法；普通文案微调不改变契约版本。

## 8. design-v1.1.0 实施补充

2026-10-30：按用户确认统一黑客松体验与现有团队协作。首页参考 `#/login` 的大标题、小松树和扇形创作卡片，应用内继续参考 `#/event`。主导航只有活动与实践，团队页面通过实践内的二级导航访问；登录弹窗同时提供密码／验证码两种方式。

辅助文字 token 从 `#8b8c8e` 调整为 `#747775`，提高米白和白底上的可读性。增加 `--sb-danger`／`--sb-danger-bg`（错误）、`--sb-success`／`--sb-success-bg`（有检查记录）、`--sb-deck-*`（首页创作方向卡片）、`--sb-shadow`／`--sb-overlay`（弹窗与通知）语义变量，具体值集中于 `songban.css` 的 `:root`。这些卡片明确是创作方向示意，不冒充真实作品。

版本化资产为 `20261030-design-v1.1`。迁移无需更改数据库；回退界面可使用 `/core`。入口与接口验证、响应式证据和外部服务限制见 `docs/core-collaboration/统一前台接入说明.md`。
