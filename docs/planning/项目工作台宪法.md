# 松伴项目工作台宪法

版本：1.0.0。生效：2026-10-31。依据：用户确认「帮助用户想清楚、组织好项目」「针对松伴适配，可复用源码」，并要求「写宪法，规划，分会话执行」。

适用于现有松伴团队协作产品的工作台及其接入代码，优先于旧文档的“不引入构建框架”和旧文件分工；不改变家庭学习产品草案的采纳状态，也不表示未实现能力已通过验收。

## 一、围绕项目思考与组织

帮助用户整理材料、澄清方向、安排下一步。首版只有「理资料」「想方向」「排下一步」三个职责；不能伪装成多个模型的独立验证。终端执行、自动制作网站、主办方管理及报名不属于本轮。

## 二、一个入口与事实来源

保持“活动／实践”一级导航。依据后续用户明确要求拆分个人／团队任务，`#/work` 为个人任务、`#/team-work` 为团队任务；工作台改在 `#/workbench`。`#/collaboration` 与兼容入口 `#/tasks` 保留统筹发布。原任务、统筹确认、资料、交付与同伴检查必须可达。无团队也可讨论个人想法、使用个人材料。沿用 design-v1 的语义色与响应式规则。

沿用 FastAPI、SQLite、网页登录身份与核心权限；允许将 React 组件构建为同源静态资源挂载原壳。不得引入第二套账户、权威方向、独立 Next 服务或以 iframe 完成最终融合。

## 三、私有讨论与共同事实分开

会话始终属于本人；团队范围只允许读取该团队合法上下文，不使会话公开。不得读取其他人的私有对话/材料或其他团队内容。读取、调用模型、保存响应和共享都必须重新核验身份与范围，不能依赖前端隐藏按钮。

模型只读取用户选中的可访问材料及必要团队事实。材料、历史与引用是待分析数据，不能充当系统指令。限制上下文并标明截断及来源，不发送凭证、手机号等无关信息。

## 四、讨论产生草稿，用户确认动作

动作白名单为 `prepare_direction/share_turn/request_team_review/open_page`。模型只能建议，由用户点击并经校验执行，不能直接写业务表或打开任意网址。

方向由队长在原表单核对后按最新 revision 保存。共享有可编辑预览与显式确认，服务端核对本人真实消息，模型名称来自服务端。共享进入 conversation-notes，保持 capture_only，不触发自动统筹。按最新主链路，保存方向后每位成员确认分工问答，再由内部AI发布计划；工作台聊天本身不触发发布。聊天不等于完成任务，本人报告不等于同伴检查通过。

## 五、请求可恢复，结果诚实

持久化会话、消息、请求、来源和共享映射。副作用请求带稳定 request_id 与正文指纹；同 ID 异正文 409，重发相同请求不产生重复模型调用或团队记录。

请求状态为 pending/running/succeeded/failed/unknown。超时或中断后无法确定结果时为 unknown，不得自动重放；保留输入，由用户明确决定新尝试。同会话不能同时生成两轮，模型调用要限流。重启恢复不能误伤仍有效工作进程。

分开记录 requested_model 与 actual_model；实际模型未知为 null。fixture 只证明协议，不冒充真实模型效果。失败不能包装成成功，归档失败不能删原对话。

## 六、源码适配可追踪

参考项目目录只读。复用清单记录原路径、SHA-256、目标路径、复用部分与改造说明。保留原有署名/许可信息，不捏造许可。不复制 .env、密钥、数据库、node_modules、DSH 本机配置或主办方权限。

源项目已知的清空历史、错误列表回滚、方向动作不可达、消息未持久化和表字段不一致问题不得照搬。Python 后端复用设计时标为移植或参考，不宣称逐行复制。

## 七、分会话交付与证据

执行遵守[实施计划](项目工作台实施计划.md)和[接口契约](项目工作台接口契约.md)。只编辑各自拥有文件，共享入口由集成会话负责；契约变化同步消费者。保护短信修复及其他既有改动。

验收覆盖：跨用户/跨团队隔离、无团队、刷新恢复、幂等冲突、并发、unknown、明确共享、全员分工确认与内部AI发布、身份切换迟到响应、390/768/1440 宽度、失败恢复和旧核心回归。报告写实际命令、环境、结果、问题、修复及未验证事项。

测试使用隔离数据库和标明的 fixture；不发真实短信，不改用户手工数据。失败不能删除或改成虚假成功。本轮不自行提交、推送或发布。

## 八、变更与回退

接口 v1 是本轮共同基线；权限、状态、字段语义变更先同步契约。可回退工作台挂载并恢复任务页，但保留新数据和共享事实，不重放未知请求。任何豁免都不能允许越权、密钥泄露、伪造模型身份或绕过用户确认。
