# 松伴前后端接口规范

版本：`1.0.0-draft`。日期：2026-10-30。关联：[宪法](../../.specify/memory/constitution.md)、[前端开发与交付](前端开发与交付.md)、[后端开发与交付](后端开发与交付.md)。

> 本文是拟新增学习域的契约设计，尚未实现，也不是当前线上 OpenAPI。代码审阅基线为 `9b92738`。强制规则已直接写入宪法；本文负责具体字段、路由、状态和联调例子。接口冻结时将本文转换为版本化 OpenAPI，并消除两者差异。下列请求均为设计样例，本次没有向供应商或业务服务实际发送请求。

## 1. 适用边界与接口负责人

新增接口前缀统一为 `/api/learning/v1`，本文下文路径均相对此前缀。旧稿的 `/api/learn` 是未实施示意，由此版统一替代。现行 `/api/core`、`/api/studio` 的认证、错误结构和工作流保持自身契约，不能把下面的草案当成已存在接口直接调用。

后端维护 OpenAPI、字段校验、状态机、权限及幂等规则；前端核对用户任务所需字段，基于同一版本创建类型和 fixture；产品/教研决定课程、报告、权益的含义；美术引用业务状态和用户动作，不另造服务端枚举。接口不能决定页面数量、布局、颜色或组件实现。

首轮范围：家庭与学习身份、年龄和起点、课程、尝试与保存、模拟/真实/回放实验、候选作品、检查与提交、家长报告、试点订单及受限运营。P0 真实执行只支持受控文本模型；上传任意文件、任意 URL、真实个人密钥、终端执行、支付网关回调和公开作品分享不在本版。

## 2. HTTP 与数据基本约定

- 使用 HTTPS 和 UTF-8 JSON。请求体 `Content-Type: application/json`；读取不得改变业务状态。
- 字段使用 `snake_case`。ID 是服务端生成的 1–128 字符不透明字符串，前端不得从 ID 推断所属家庭或权限。
- 时间是 UTC ISO 8601，例如 `2026-10-30T08:00:00Z`；展示时可转本地时间。日期 `YYYY-MM-DD` 不带时区。所有过期与限额判断以服务端时间为准。
- `revision`、课程/材料/规则/输入/作品版本为正整数。金额是 `amount_minor` 整数加 `currency`，不能用浮点金额。本文不预设价格。
- 缺少可选字段与显式 `null` 的含义必须分别定义。读取到未知模型、用量或耗时时用 `null`，不能用 `0`、空串或猜测补齐。
- 新增写接口拒绝未声明字段，返回 `422 unknown_field`；前端兼容忽略响应中新增加的可选字段。枚举扩展需同步客户端兼容处理，未知状态不得显示成功。
- 列表使用游标：`?cursor=...&limit=20`，`limit` 范围 1–100；服务端返回 `items` 和可空 `next_cursor`。游标不授予权限。报告默认按 `created_at`、ID 倒序稳定分页。
- 课程发布配置声明文本、步骤、参数和输出限额，响应包含相应 `limits`。超限明确 `422 input_too_large`，不得像旧网关一样静默截断输入；服务端请求体总上限和网关限制须在部署契约中保持一致。
- 成功、失败响应均附 `X-Request-ID`，正文 `meta.request_id` 与其一致。客户端可记录它帮助定位，不能因此得到敏感日志。

### 2.1 成功与失败包装

成功示例：

```json
{
  "data": {"attempt_id": "att_demo", "revision": 3},
  "meta": {"request_id": "req_demo"}
}
```

失败示例：

```json
{
  "error": {
    "code": "revision_conflict",
    "message": "这份记录已有更新，请读取最新版本后再保存。",
    "retryable": false,
    "details": {"current_revision": 4, "fields": []}
  },
  "meta": {"request_id": "req_demo"}
}
```

`details` 始终为对象，可为空。字段错误 `fields` 是 `{path, code, message}` 数组，`path` 为 JSON Pointer，例如 `/draft/prompt`。不把原始密码、输入私密全文、供应商响应堆栈放进错误。`retryable=true` 仅表示错误可能短暂，仍须服从幂等与状态规则；不授权客户端换键重发。

### 2.2 状态码与客户端处理

- `200`：读取或更新成功；`201`：创建资源；`202`：持久化接受异步任务。异步创建提供 `Location` 和资源 ID，不能仅返回“已提交”。
- `400 malformed_request`：JSON/请求格式不合法，修改请求后再发。
- `401 authentication_required|session_expired`：重新认证；保留安全范围内的未保存输入，不能切换到另一个人后恢复旧人的内容。
- `403 forbidden|csrf_failed|parent_authorization_required`：无动作权限、请求防护不通过或缺家长授权；刷新身份/回家长操作，不能无限重试。
- `404 resource_not_found`：不存在或对当前主体不可见；跨家庭资源统一此响应，避免泄露存在性。
- `409 revision_conflict|idempotency_conflict|invalid_transition|snapshot_mismatch|attempt_already_active`：读取当前记录并按具体原因恢复；不能盲目覆盖或创建第二次运行。
- `422 validation_error|unknown_field|input_too_large|model_not_allowed|parameter_not_allowed|course_not_available`：修正输入或改用允许配置。字段错误写入 `details.fields`。
- `429 rate_limited`：请求频率限制，返回秒数 `Retry-After`。`429 quota_exhausted`：真实额度不足，返回自己的额度摘要与可用模拟动作；不能仅等待几秒反复重试。
- `503 service_unavailable`：暂时无法接受操作；若不能确认运行是否创建，仍按原键查询/恢复，不生成新键。
- `500 internal_error`：未预期内部错误，只展示安全文案与请求号。服务端不能把内部异常改写成孩子学习失败。

`GET /runs/{id}` 返回 HTTP 200 且 `data.status=failed` 是合法的：查询成功而实验失败。前端必须读资源状态，不能只判断 HTTP 200。

## 3. 会话、身份及请求权限

### 3.1 会话方案

同源 Web 使用服务端会话 Cookie，至少设置 `HttpOnly`、`Secure`、`SameSite=Lax`，路径覆盖新学习域；正式部署不允许 HTTP。开发本机例外必须仅在开发配置启用。会话 ID 与 CSRF token 不写入 localStorage、普通日志或报告。

`GET /session` 无登录时返回匿名状态，必要时建立受限匿名会话并提供 CSRF token。登录、注册、发短信等匿名写请求同样校验来源与 CSRF。登录后轮换会话和 token；前端以该响应重新建立当前身份上下文。

Session 的 `data`：

```json
{
  "actor": {"type": "learner", "actor_id": "learner_demo"},
  "family_id": "family_demo",
  "learner_id": "learner_demo",
  "onboarding_required": false,
  "allowed_actions": ["attempt.read", "attempt.write", "run.create"],
  "csrf_token": "example_only_not_a_real_token",
  "expires_at": "2026-10-30T10:00:00Z"
}
```

`actor.type` 为 `anonymous|parent|learner|operator`。匿名主体的 `actor_id/family_id/learner_id` 为 null；家长没有当前学习者时 `learner_id` 为 null。`onboarding_required` 对家长为 boolean、学习者为 false、匿名及运营为 null；家长刷新后通过它恢复家庭引导。`allowed_actions` 帮助界面呈现，不替代后端校验。每个写请求携带 `X-CSRF-Token`，新会话必须使用新 token。匿名操作幂等在服务端绑定内部匿名会话标识，不能把所有匿名用户都绑定公共 null 主体。

进入孩子模式时撤销当前浏览器的家长管理会话，签发只属于指定孩子的学习会话。返回家长区重新认证，不靠“我是家长”按钮或本地切换变量升权。多标签页仍必须受服务端撤销约束；前端更新身份 epoch、清理私有缓存，丢弃旧请求的迟到响应。

运营账号独立配置与认证，拥有具体权限，例如 `course.publish`、`check.review`、`order.verify`、`run.reconcile`；普通注册接口不得传入运营角色。P0 可以由受限内部脚本调用相同服务层，不要求先做完整运营后台；没有运营身份方案时不得开放管理 HTTP 接口。

### 3.2 身份规则

- 匿名：公开样例和认证；不得创建校准、尝试、作品或模型运行。
- 家长：管理本人家庭引导、学习者资料、学习会话、自己的订单/权益和授权范围内的报告；不代替孩子提交学习结论。
- 学习者：只能访问当前学习者的课程、尝试、运行、作品及有限权益摘要；不得购买、扩大预算、读取完整家庭管理资料或访问另一孩子。
- 运营：按具体权限处理被分配的课程/核验/复核/异常，不因是“后台”就得到全库权限。
- 对任意资源 ID 做家庭归属检查。跨家庭、跨学习者请求用统一 404；有可见资源但缺动作权限用 403。

## 4. 并发、幂等和客户端恢复

### 4.1 可变记录版本

`PATCH /attempts/{id}`、资料更正、订单核验等带 `expected_revision`。服务器比较后原子更新并增加 `revision`，冲突返回当前 revision。前端保留本地草稿，读回最新状态后让用户决定合并或重新保存，不自动最后写入覆盖。

`revision` 是尝试记录并发版本；`input_version` 是运行所用输入快照版本；`input_hash` 是该输入快照摘要。输入快照冻结材料、prompt 和参数，修改其中任一项增加 `input_version`；仅修改当前步骤不一定增加输入版本。run 请求的 parameters 必须等于所引用快照的参数，不能拿旧 hash 搭配新参数；模型选择另以 model_ref 记录。比较不同参数时先分别保存输入版本，并明确记录哪些材料/提示保持相同、哪些参数改变。候选作品的 `content_hash` 是另一种摘要，不与输入摘要混用。

### 4.2 幂等操作

所有有副作用的 POST 和可重放的更新都携带 `Idempotency-Key`，取值为调用端生成的 UUID。服务端绑定“当前主体 + 操作码 + 资源 + 键”及规范化正文摘要。同键同正文返回原操作结果；同键异正文返回 `409 idempotency_conflict`。会话轮换不能让同一业务主体绕过原键约束，重放旧登录响应不得复活已撤销会话。

创建 run 与额度预占在一个事务内提交，再由持久任务队列执行。幂等映射与关联业务记录采用一致保留策略，未决运行不能先过期；策略须在上线前配置。响应可附 `Idempotency-Replayed: true` 表示复用了原操作；资源状态以随后 GET 为准。

客户端为一次用户动作生成一次键，并在请求前保存于该身份的短期操作上下文；断网但没有拿到 ID 时，用原键、原正文恢复原操作。已拿到 ID 则优先 GET 查询。用户修改输入或明确开始另一实验才生成新键。注销清除浏览器私有操作上下文；重新登录通过服务端尝试和运行列表找回事实，不依赖本地键作为唯一记录。

`GET` 可以有界重试。运行查询建议从 2 秒逐步退避到 10 秒并遵守 `Retry-After`，前台连续轮询超过 120 秒停止自动轮询，保留手动查询/稍后恢复入口。该客户端等待上限不改变服务端任务状态。任何超时均不能自行改失败、重新调用或再次扣额。

## 5. 领域对象和状态机

### 5.1 资料与课程

Profile 包含 `learner_id`、`age_band`、`self_level`、`recommendation`、`revision`。`self_level` 为 `beginner|some_experience|advanced`，只是自选起点。`age_band` 从产品配置返回的合法选项选择，不在客户端根据生日推算能力。`recommendation` 含推荐课次、理由、证据 ID 和 `source`，可以为空；更改自选值不删除旧校准证据。

CourseVersion 包含 `course_id/course_version`、`title`、`learning_objectives`、`lessons`、`materials`、`model_options`、`parameter_schema`、`limits`、`required_checks`、`transfer_tasks`、`entitlement_requirements`。课次有 `lesson_id/lesson_version`，材料有 `material_id/material_version`，规则有 `test_version`。发布版本不可变，已有尝试继续绑定原版本。

`model_options` 每项至少有 `model_ref`、展示名称、模型类别、允许模式、能力和可用性。它是服务端允许目录，不能包含真实密钥或任意供应商 URL。P0 实际能力仅 `text_generation`；更丰富类别可以作为课程知识内容，但不能画成已经接通。

### 5.2 Attempt

必备字段：`attempt_id`、`learner_id`、`course_id/course_version`、`lesson_id/lesson_version`、`status`、`access_state`、`revision`、`current_step_id`、`draft`、`input_version/input_hash`、`runs`、`artifact_versions`、`submitted_artifact`、`updated_at`。

`draft` 只接受课程声明的字段，例如 `material_ref`、`prompt`、`parameters`、`child_explanation`；允许值由 CourseVersion 的 schema 决定。`submitted_artifact` 是候选三元组或 null。

- `status`：`in_progress → submitted → passed|needs_practice|pending_review`；补练时保存新内容可重新进入 `in_progress`，旧提交与结论保留。
- `access_state`：`writable|read_only`，只反映权益/授权是否允许修改，不能把到期改成“学习未通过”。
- `submitted` 表示正在处理提交，不能无期限停留；服务异常须有可查询状态和恢复任务。
- 活动状态为 `in_progress|needs_practice|submitted|pending_review`；一个学习者同一课次版本只允许一个活动尝试。重复建另键返回 `409 attempt_already_active` 并给出本人活动 ID。仅 in_progress/needs_practice 且 access_state=writable 时可保存内容，submitted/pending_review 只读等待结果，不再创建另一个活动尝试。passed 为终态，复练必须新建并关联 `previous_attempt_id`，不改原成果。等待状态超时须由后端恢复/复核处理，不能要求孩子新建以绕过。

### 5.3 Run

必要字段与类型：

```json
{
  "run_id": "run_demo",
  "revision": 1,
  "attempt_id": "att_demo",
  "mode": "live",
  "status": "queued",
  "input_version": 2,
  "input_hash": "sha256:example_input_digest",
  "model_ref": "text_model_a",
  "requested_model_id": "provider_model_id",
  "response_model_id": null,
  "course_id": "course_demo",
  "course_version": 1,
  "lesson_id": "lesson_demo",
  "lesson_version": 1,
  "material_id": "material_demo",
  "material_version": 1,
  "model_config_version": 1,
  "quota_policy_version": 1,
  "parameters": {"temperature": 0.2},
  "output": null,
  "finish_reason": null,
  "is_truncated": false,
  "duration_ms": null,
  "usage": {"input_tokens": null, "output_tokens": null, "source": "unknown"},
  "billing": {"status": "reserved", "unit": "credit", "reserved": 10, "charged": null, "provider_cost_minor": null, "currency": null},
  "source_run_id": null,
  "review_due_at": null,
  "reconciliation": {"status": "not_required", "resolution": null},
  "created_at": "2026-10-30T08:00:00Z",
  "started_at": null,
  "finished_at": null,
  "error": null
}
```

上面额度数值只是结构样例，不是定价或收费承诺。`parameters` 必须通过本课程的 schema；未知字段拒绝。`output` 为 null 或 `{text: string}`。`finish_reason` 为 `stop|length|filtered|unknown|null`；有截断或缺失必须如实标记。`usage.source` 为 `provider|estimated|unknown|not_applicable`，不能把估算写成供应商实测。费用和 token 是不同度量。

执行状态：`queued → running → succeeded|failed|unknown`；排队前校验失败不产生可执行任务。`unknown → succeeded|failed` 只能凭可靠核对结果；无法确认可以保持 unknown 且把核对关闭。P0 不提供取消运行接口，关闭页面不代表取消上游。

`reconciliation.status` 为 `not_required|open|closed`，`resolution` 为 `confirmed_success|confirmed_failure|unresolved|null`。unknown 必须有 `review_due_at`；截止时间来自发布配置，运营队列可发现超期项。

`billing.status` 为 `not_applicable|reserved|settled|released|pending_reconciliation`。未知运行按事先披露的额度规则核对/释放；核对关闭后不得继续永久冻结。平台额度处理与供应商实际成本分别记录，供应商成本无法得知仍为 null。mock/replay 的真实调用用量不适用，不填伪造 token 和真实费用。

replay 必须引用本人可访问的 `source_run_id`，且必须同 attempt、input_version/input_hash、model_ref、parameters、课程/课次和材料版本；任一不匹配返回 `409 replay_source_mismatch`。前端改过输入不能将旧输出当作新输入结果。响应增加 `replay_source={run_id,mode,created_at,usage}` 说明原始事实；回放本身不新扣真实额度，不用于冒充新的独立实验。源运行无可展示输出时返回 `422 replay_unavailable`。mock 故障脚本必须明确是教学模拟，不外发。比较结果须基于共同材料、测试规则和明确记录的变化参数，不能由前端随意拼成排行榜。

### 5.4 Artifact、Check、Report、Order

Artifact 三元组：`artifact_id`、`artifact_version`、`content_hash`。内容包含输入快照、孩子修改/说明、选用运行和必要材料引用，由后端计算 hash。已创建版本内容不可变；新内容产生新版本。`stage=candidate|finalized`，finalized 只代表已提交，不等于课次通过。

Check 作业 `status=queued|running|completed|failed`；学习结论另为 `verdict=passed|needs_practice|pending_review|null`。检查运行错误使用 status=failed、verdict=null，不能让服务错误降低孩子结果。每项 `items` 含检查 ID/规则、来源 `deterministic|ai_assisted|human|learner_statement`、结果、证据引用和可给用户的反馈。人工复核保存人员、理由和时间，不由 AI 冒名。

Report 为 `report_id`、`report_version`、`status=pending|ready|failed`、成果三元组、`attempt_status`、证据索引、已观察事实、帮助摘要、未观察事项和下一任务。报告 ready 不等于学习通过。报告内容不默认包括全部原始私人对话；家长获得产品定义的报告范围。

Order 为 `order_id`、`offer_id/offer_version`、价格快照、`status=pending|verified|closed|refunded`、`revision`、时间和可见说明。权益单独记录来源订单、课程范围、有效期和允许动作，真实额度单独记录。订单提交、上传收款证明或浏览器回跳都不能自动授予权益。

## 6. 认证、家庭与起点接口

以下字段除注明可选/null 外均必填。所有写操作遵守第 4 节；主体、角色、归属、金额、通过结果等服务端字段不得由客户端越权传入。每条接口均继承通用错误，只额外列重点分支。

### A0 `GET /bootstrap`

允许匿名，只返回公开配置：`config_version`、`age_band_options`、`self_level_options`、当前 `terms_version/consent_version`、相应条款文本或公开地址、`auth_policy`（密码约束和手机号格式）、公开样例引用及服务说明。不得包含家庭、供应商密钥或未发布课程。前端不得硬编码另一套年龄选项和密码校验；注册/引导提交已展示的配置版本，过期且不兼容时返回 `409 policy_version_changed` 并要求重新阅读。

### A1 `GET /session`

允许匿名。无请求体，返回第 3 节 Session；未登录返回匿名 Session，而非伪造家长身份。会话无效时清除旧 Cookie。响应不缓存，`Cache-Control: no-store`。

### A2 `POST /auth/codes`

匿名认证上下文。请求 `{phone, purpose}`，`purpose=register|reset_password`，手机号按服务端约定规范化为国际格式。响应 `200 {challenge_id, expires_at, resend_after_seconds}`，不返回短信码或账号是否存在。限流 429。实际短信成本与风控单独限制，不能拿模型额度抵扣。

### A3 `POST /auth/register`

请求 `{phone, challenge_id, code, password, terms_version, config_version}`。注册不要求技能和工作画像。服务端完成校验后返回 `201 {session, onboarding_required}` 并设新 Cookie；不直接创建学习成果。密码约束由认证服务配置并向前端提供一致说明，不静默裁剪。

重复手机号不覆盖旧人画像或密码，按明确的登录/找回引导返回 `409 account_already_registered`；该信息只在已验证对应手机号控制权后提供。无效或过期挑战返回 422，短信验证限流为 429。

### A4 `POST /auth/login` 与 `POST /auth/password/reset`

登录请求 `{phone, password}`，成功 `200 {session, onboarding_required}`。失败 `401 invalid_credentials`，不区分手机号不存在与密码错误。

重置请求 `{phone, challenge_id, code, new_password}`，成功 `200 {password_reset: true}`，撤销既有登录会话，重新登录。验证码单次使用、验证失败次数和过期均由后端执行，不靠倒计时控制。旧协作账号适配不得覆盖旧画像和团队数据。

### A5 `POST /onboarding`

仅家长。请求 `{learner: {display_name, age_band, self_level}, consent_version, config_version}`。P0 一个家庭一个学习者；服务端以当前家长推导归属，响应 `201 {family_id, learner, revision}`。重复原键返回原记录，重复初始化新键返回 `409 already_onboarded` 并给出本家庭引导状态。进入学习模式另调用 A6。

### A6 `POST /sessions`、`POST /sessions/end`、`POST /family/reauth`

- 创建学习会话：家长请求 `{learner_id}`，校验家庭关系后 `201 {session}`，撤销当前管理会话并更换 Cookie。越权资源 404。
- 退出：当前主体请求 `{}`，`200 {ended: true}`，撤销当前会话并清 Cookie；重复退出可安全完成。
- 回家长管理：请求 `{phone, password}`，重新认证成功返回 `200 {session}`，撤销当前学习会话。不能把 learner_id 或 role 当作凭据；失败不升权。

### A7 `GET /profile` 与 `PUT /profile`

学习者访问自己的 Profile；家长使用 `?learner_id=...` 指定本人家庭学习者。更新体 `{expected_revision, self_level?, age_band?, display_name?}`，至少一个修改字段；学习者仅可改 `self_level`，年龄段和展示名更正由家长完成。响应 200 Profile。更正不删除校准或伪造能力提升；越权字段 403，非法选项 422。

### A8 `POST /calibrations`

仅学习者。请求 `{calibration_version, responses:[{task_id, answer, explanation, assistance_declared}]}`；任务来自发布的校准配置。返回 `201 {calibration_id, recommendation, evidence_refs, limits_of_inference}`。P0 可使用固定规则形成建议，不把 AI 文本判定当科学评分。服务失败不能给出“不擅长 AI”结论；调整推荐不重写原始作答。

### A9 `GET /calibrations/config` 与 `GET /calibrations/{calibration_id}`

仅学习者。config 返回 `calibration_version`、任务 ID/材料/说明、作答 schema、帮助选项、目标与推断局限，不把标准答案泄漏成已完成结果。提交时绑定此版本。记录读取返回本人原始作答、帮助声明、推荐及其来源，允许刷新后恢复，不重跑校准或重写历史。匿名只看公共样例，不能执行校准。

### A10 `GET /family/learners/{learner_id}/settings` 与 `PUT /family/learners/{learner_id}/settings`

仅绑定家长。GET 返回 `learner_id`、`revision`、`live_enabled`、`daily_credit_limit`、`allowed_max_daily_credits`、`window_ends_at`、`consent_version` 与允许动作。新学习者默认 live_enabled=false。

PUT 请求 `{expected_revision, live_enabled, daily_credit_limit, consent_version}`。daily_credit_limit 为非负整数且不超过服务端返回的 allowed_max_daily_credits；计费窗口以服务端 window_ends_at 为准。家长只能在已获得的权益/平台预算内设置限制，不能通过此接口增加已购额度或后台余额。启用必须对应当前已展示的真实调用说明；服务端保存授权人、说明版本和时间。成功 200 返回新设置和 revision；跨家庭404，孩子调用403，超限422。

撤销授权立即阻止新运行及尚未外发的 queued 任务；后者标记 failed、error.code=authorization_revoked 并释放预占。已确定发出的 running/unknown 保留查询与核对，不重复发送，也不把撤销当作供应商已经停止。课程到期/退款采用同一“停止新发、处理在途”的执行原则；已经产生的服务成本依发布前明确的规则处理。

### A11 `GET /family`

仅家长。返回 `{family_id, revision, learners, allowed_actions}`，learners 为本人家庭的 `{learner_id, display_name, age_band}` 摘要数组。家长重登后从此读取学习者 ID，再创建学习会话或读取 settings，不依赖浏览器保留的 ID。未完成引导时返回 family_id=null、revision=null、learners=[]，结合 Session 的 onboarding_required 引导下一步；不能把读取失败当未建立家庭。

## 7. 课程、尝试、提示与实验接口

### L1 `GET /home`

仅学习者。返回 `{profile, recommended_course, resumable_attempt, available_courses, entitlement_summary}`。课次条目包含是否可进入及 `unlock_reason`；无记录为 null/空列表，与错误分开。`resumable_attempt` 含 attempt_id、状态和更新时间，不从浏览器猜测继续位置。

### L2 `GET /courses/{course_id}?version=...`

仅有相应体验或正式权限的学习者。省略 version 读取可访问的当前发布版本，明确给出实际版本；已有尝试仍读取它绑定的版本。返回 CourseVersion、可用模式、参数 schema、限制和动作权限。不具备操作权益时只返回经定义的课程摘要或 403，不泄露未发布内容。发布后停用模型需返回可用性与原因，不能暗中换模型。

### L3 `POST /attempts`

请求 `{course_id, course_version, lesson_id, lesson_version, previous_attempt_id?}`。服务端校验发布版本、先修条件、权益和复练关系，返回 201 Attempt。课次状态和归属由服务端创建，不接受客户端 passed 或 learner_id。已有活动尝试返回 409 与本人活动 ID。

### L4 `GET /attempts/{attempt_id}`

返回完整恢复用 Attempt，包括当前 draft、各运行 ID/状态、保存版本、候选及提交引用、检查摘要和报告状态。历史较多时各集合使用游标/后续读取链接，不能只靠“最近几条”决定旧任务是否存在。到期后按已确认的数据保留规则返回只读记录。

### L5 `PATCH /attempts/{attempt_id}`

请求 `{expected_revision, current_step_id?, draft?}`。草稿按已发布课程 schema 校验；不存在的步骤、非法材料和参数返回 422。成功 `200 {attempt_id, revision, input_version, input_hash, updated_at}`。前端只有拿到成功回执才显示已保存，保存失败保留当前编辑。

### L6 `POST /attempts/{attempt_id}/hints`

请求 `{step_id, hint_level, input_version}`，`hint_level` 来自该课次允许范围。P0 返回固定课程提示 `201 {hint_id, content, source:"course", hint_level, assistance_event_id}` 并记录帮助。动态 AI 提示后续如启用必须走同一受控调用和成本规则，不能绕过额度；服务异常可回退固定提示，并如实标记来源。

### L7 `POST /runs`

请求字段：`attempt_id`、`mode`、`input_version`、`input_hash`、`model_ref`、`parameters`；replay 额外要求 `source_run_id`，mock 可有课程允许的 `scenario_id`。服务端读保存的输入，不接收另一份游离 prompt。`model_ref` 对 replay 必须与源记录匹配；mock 场景仅来自课程白名单。

校验、持久化和预占成功返回 `202 {run_id, status, mode, poll_after_seconds}` 与 Location。参数与输入不一致 409/422；live 未授权 403，额度不足 429。mock/replay 不发真实请求、不预占真实额度。原请求已经入队时重放原键只返回原 run，不再排一次执行。

### L8 `GET /runs/{run_id}`

仅本人学习者。返回 Run；queued/running 或核对尚未关闭的 unknown 可带 `Retry-After`，不存在 run.pending 枚举。Run 的 model_config_version 和 quota_policy_version 冻结本次实际配置与额度处理依据，不能因后台改配置而改写旧运行。结果文本是非可信内容，前端按安全文本/受限 Markdown 渲染，不执行模型返回的 HTML/脚本。父母在报告中看被选取的证据，不通过此接口默认读取全部实验对话。

## 8. 候选、检查、提交和家长报告接口

### E1 `POST /artifacts` 与 `GET /artifacts/{artifact_id}?version=...`

创建请求 `{attempt_id, input_version, input_hash, source_run_ids, child_explanation, contribution_notes, artifact_id?}`。`artifact_id` 只在给本人已有作品追加新版本时填写。服务端读取冻结输入、验证源运行归属/版本/可用结果，创建不可变候选，返回 `201 {artifact_id, artifact_version, content_hash, stage:"candidate", created_at}`。

`contribution_notes` 记录孩子自述，不能冒充系统已核验贡献。帮助历史由服务端关联，不能因客户端只挑选几个 run 就抹去此前提示、成人协助或失败记录。服务故障/截断运行可留作过程证据，但必须标记，不能冒充完整成品依据。GET 指定版本返回不可变内容及证据索引；省略 version 读取最新可见版本，必须返回实际版本号。

### E2 `POST /attempts/{attempt_id}/checks`

请求 `{artifact_id, artifact_version, content_hash, transfer_response?}`，`transfer_response` 含 `{task_id, task_version, answer, explanation, assistance_declared}`；必需项由该课次规定。服务端选择当前绑定版本的必需检查，不允许客户端只选容易通过的子集或提交 passed。

返回 `202 {check_id, status, artifact_id, artifact_version, content_hash}`。不匹配返回 `409 snapshot_mismatch`；缺材料/迁移提交返回 422。重复原键返回原检查。AI 辅助反馈单独标明，不能自动伪装成人工确认。

### E3 `GET /checks/{check_id}`

返回 `{check_id, revision, status, verdict, artifact_id, artifact_version, content_hash, test_version, items, feedback, review, error}`；review 无人工记录时为 null。检查的 revision 是自身复核并发版本，不是 attempt revision；每次复核更新增加该值。`items` 的证据引用必须是当前身份能访问的对象。错误与学习未通过按第 5 节分开。

### E4 `POST /artifacts/{artifact_id}/finalize`

请求 `{artifact_version, content_hash, check_ids, expected_revision}`，`expected_revision` 指所属 Attempt 的当前版本。后端在事务内核对候选、全部必需检查、孩子说明与迁移任务；检查仍在运行返回 `409 checks_not_ready`，任一必需检查 status=failed 返回 `409 checks_failed`，不得据此把孩子判为 needs_practice。确认检查服务可用后可以为同候选新建检查，保留原失败记录；原键恢复仍只返回原失败检查。候选错配返回 409，不改已有结论。

提交接收后返回 `200 {artifact_id, artifact_version, content_hash, stage:"finalized", attempt_id, attempt_status, revision, report_id, report_status}`。`attempt_status` 为 passed/needs_practice/pending_review；三者均保留本次提交事实，stage=finalized 不等于 passed。报告可先 pending，不阻止已保存成果恢复。

人工复核晚到时，仅当前 `submitted_artifact` 匹配的检查可推进当前 Attempt；旧候选的结论写入历史，不覆盖更新的提交。复核改变结论须生成新报告版本并保留来源，不静默重写旧报告。

### E5 `GET /family/reports` 与 `GET /family/reports/{report_id}?version=...`

仅绑定家长。列表接受 learner_id、游标和 limit，返回本人家庭摘要、生成状态、成果版本与下一任务，包含 pending/failed 项让家长能找到记录。详情指定 version 读取该不可变报告版本，省略则读最新并返回实际 report_version 与 available_versions；历史版本仍受相同家庭授权。详情不默认开放全部原始私人对话；数据不足显示未观察到。跨家庭 404。

### E6 `POST /family/reports/{report_id}/retry`

仅绑定家长，失败或可恢复 pending 超期时可请求 `{expected_report_version}`。服务端限制频率、复用同一成果事实，返回 `202 {report_id, report_version, status:"pending"}`；已有生成任务同键复用，不新跑实验。已 ready 返回现有报告；版本不符 409。后台重试也受相同去重规则约束。

### E7 `POST /family/reports/{report_id}/feedback`

请求 `{report_version, understood, next_learning_interest, difficulty_note?}`。`understood` 为 boolean，`next_learning_interest=continue|unsure|stop`，开放文字有限长。返回 `201 {feedback_id, created_at}`。这些是家长反馈，不更改孩子检查记录，不把“想继续”记成已经付费。

## 9. 权益和试点订单接口

### B1 `GET /entitlements`

家长获取本人家庭明细；学习者仅获取自己的学习范围和允许动作，不返回付款细节。结果含 `entitlements`、`quota`、`allowed_actions`、`restriction_reasons`。权益范围、到期时间、来源订单、课程操作权与真实额度分别保存；不能以一个 is_paid 包办所有情况。

拟议规则：未开通仅公共/指定体验范围；试用默认不开 live，除非另有家长授权及独立限额；额度用尽仍可做已授权 mock；到期或确认退款后停新正式操作，但历史作品/报告及已存草稿按声明只读保留。其他有效订单的权益不被一起撤销。上述规则须在收款前落实到购买说明和数据保留机制。

### B2 `GET /offers` 与 `POST /orders`

仅家长。offers 返回服务端发布的 `offer_id/offer_version`、内容范围、有效期、价格、币种、真实额度说明、开通/退款说明版本。

下单请求 `{offer_id, offer_version}`，不接受前端金额。响应 `201 {order_id, status:"pending", price, fulfillment_instructions, revision}`。首轮是人工核验方案；客户端不能因显示支付二维码、提交证明或跳转返回就判定到账。

### B3 `GET /orders/{order_id}`

仅订单所属家长。返回 Order、权益是否实际发放及可见核验说明；内部核验材料不全量暴露。pending 有明确等待/联系入口。关闭和退款记录仍可查，不静默删除。

## 10. 受限运营接口

全部要求独立 operator 身份、具体 action 授权及审计；写请求要求 Idempotency-Key、CSRF（Cookie 调用时），GET 不要求幂等键。下述证据引用指向内部受控材料，不允许夹带密钥或付款隐私全文。

- `GET /admin/orders` 与 `GET /admin/orders/{order_id}`，权限 `order.verify` 或 `order.refund` 且需资源范围授权。返回待处理订单、价格快照、revision、已授予权益和允许动作，分页不泄露无关家庭；供核验/退款前读取当前版本。读取请求不要求 Idempotency-Key。
- `POST /admin/courses/{course_id}/publish`，权限 `course.publish`。请求 `{draft_version, expected_revision, change_note}`；后端校验目标、材料、模型引用、提示、检查、迁移和先修环，返回 `201 {course_id, course_version, published_at}`。旧尝试不自动迁移。
- `GET /admin/reviews`，权限 `check.review`。游标返回授权范围内待复核项目及到期时间；不能默认列全体孩子隐私。
- `POST /admin/checks/{check_id}/review`，权限 `check.review`。请求 `{expected_revision, verdict, rationale, evidence_refs}`，verdict 只允许 passed/needs_practice；真实操作者从会话取得。返回检查与受影响提交/报告摘要。旧版本复核不推进新版本 Attempt。
- `POST /admin/orders/{order_id}/verify`，权限 `order.verify`。请求 `{expected_revision, receipt_ref, received_amount_minor, currency, note}`；校验收款与订单快照相符，原子标记 verified 并授予权益。返回订单和授予 ID；重复核验不重复赋权，不允许家长自行调用。
- `POST /admin/orders/{order_id}/refund`，权限 `order.refund`。P0 仅登记已人工完成并有依据的退款，请求 `{expected_revision, refund_receipt_ref, refunded_amount_minor, reason}`。本版只支持全额退款，金额不符返回 422；原子撤销对应权益并保留历史。此接口不实际代替支付渠道退款，部分退款留给后续独立规格。
- `GET /admin/runs/reconciliation`，权限 `run.reconcile`。返回 open 或超期核对项、预占和脱敏供应商线索，可分页/按到期筛选。
- `POST /admin/runs/{run_id}/resolve`，权限 `run.reconcile`。请求 `{expected_revision, resolution, evidence_refs, usage?, quota_action, reason}`。resolution 为 confirmed_success/confirmed_failure/unresolved；quota_action 为 settle/release，结算依据按配置规则校验，不允许手工随意写余额。无法查证时必须标明 unresolved，执行仍 unknown，关闭核对并按规则释放/调整额度；供应商未知成本仍 null。响应更新后的 Run 与核对审计 ID。

订单核验、退款和运行核对返回的记录包含 revision；管理列表/详情须提供同一 revision 供并发校验。上述动作不存在“后端帮忙随便改个状态”的旁路。

## 11. 可直接用于联调的一条链路

下面是样例 ID 与摘要，不能据此认定真实实现。所有写请求均带当前 CSRF、各自 Idempotency-Key 与 JSON 请求头。

1. 家长登录/引导，`POST /sessions` 进入孩子身份；GET session 确认无订单和管理权限。
2. GET home 与指定 CourseVersion；POST attempts 得到 `att_demo` 和 revision=1。
3. 保存草稿：

```json
{
  "expected_revision": 1,
  "current_step_id": "try_prompt",
  "draft": {
    "material_ref": "material_demo_v1",
    "prompt": "只根据给定资料回答，不知道时说明资料未提及。",
    "parameters": {"temperature": 0.2},
    "child_explanation": "我想先检查回答有没有编造。"
  }
}
```

4. 服务端返回 revision=2、input_version=1 和真实计算的 input_hash；运行请求必须使用这些回执值：

```json
{
  "attempt_id": "att_demo",
  "mode": "mock",
  "input_version": 1,
  "input_hash": "sha256:example_input_digest",
  "model_ref": "text_model_a",
  "parameters": {"temperature": 0.2},
  "scenario_id": "normal_answer"
}
```

5. 查询 run 至终态。mock 字样及来源持续可识别；换 live 需真实授权，不能只改前端标签。
6. POST artifacts 固化 input_version=1、选用 run、孩子解释与贡献记录；取得候选三元组。
7. POST checks 使用同一三元组，连同课次要求的新材料迁移作答；GET checks 取得实际结论。
8. GET attempt 取得最新 revision；finalize 提交候选三元组、check_ids 和该 revision，服务端返回 attempt_status 与 report_id。
9. 退出学习/家长重新认证；家长从报告列表找到该报告，阅读实际证据，提交反馈。报告 pending/failed 不会触发新实验。

这条链路可先用完整 fixture 联调，但必须另测真实服务、持久化恢复和权限；fixture 通过不能宣布已接入真实模型或已经产生学习效果。

## 12. 接口验收清单与交付文件

首轮验收至少覆盖：

1. 同一请求正常、缺字段、非法枚举、越权资源、过期会话、CSRF 失败的可预期响应。
2. 家长进入孩子模式后，旧管理 Cookie 失效；多标签页与迟到请求不能泄露或恢复旧权限。
3. 同键同正文复用原资源，同键异正文 409；并发 run 不能超过预算或重复预占。
4. 保存时两窗口冲突；旧 input_hash 运行被拒；新候选不能使用旧检查。
5. 运行已被服务端接受但客户端断网，原键恢复不二次发给上游；服务重启后仍可查。
6. mock/replay 没有真实外发；unknown 可进入核对并关闭，未知不能被强行当成功/免费。
7. 检查服务异常与孩子需补练分离；finalized、passed、report ready 各自独立。
8. 旧版本人工复核晚到不会覆盖当前提交；报告重建不重跑实验、不补造证据。
9. 人工核验订单、重复核验、全额退款、权益到期与在途运行都遵守明确规则；退款不误伤其他订单。
10. 空列表、无历史、额度不足、截断输出、未知用量、模型停用、接口新增可选字段和未知枚举均可正确呈现。

后端交付：与本规范一致的 OpenAPI、DTO/枚举和校验、迁移说明、状态机实现、脱敏样例、契约测试、真实联调记录。前端交付：消费的契约版本、fixture 状态覆盖、错误/恢复记录、身份缓存隔离、完整链路演示和未接通项。美术交付：引用同一业务状态的交互说明与素材，不复制另一套 API 定义。

P0 不确定值在功能规格阶段收口：首轮年龄选项、课程输入限额、可用供应商、真实额度单位换算、核对时限、会话有效期、价格、数据保留和运营人员。它们由配置/发布版本表达，不能让前端和后端各自写默认值。本规范的设计完整性不代表这些上线配置已确定。
