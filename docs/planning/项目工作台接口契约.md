# 项目工作台接口契约 v1

冻结：2026-10-31。前缀 `/api/workbench`，JSON 原对象（无 data 包装），Bearer 使用现有网页登录 token，连接器 token 不可访问私有会话。错误沿用 `{error:{code,message}}`。401 登录，403 范围，404 不存在，409 冲突，422 参数，429 忙，502/503/504 模型失败。

## 对象

ID 为字符串，空团队 null（GET 省略/空串）。request_id 为客户端生成的 8–100 字符稳定 ID。时间 UTC ISO。role_id 固定 materials/direction/next_step。

- Session：`{id,title,team_id,created_at,updated_at}`。
- Message：`{id,session_id,request_id,role:"user"|"assistant",text,created_at,role_id,actions:[],sources:[],requested_model,actual_model,mode}`。用户消息模型字段 null，mode 为 live/fixture。
- Request：`{id,request_id,session_id,status,error:null|{code,message},created_at,updated_at,message_id:null|string}`。id 服务端生成，request_id 幂等键。状态 pending/running/succeeded/failed/unknown。

## 上下文

`GET /context?team_id=…` → `{roles:[{id,name,description}],team:null|{id,name,is_captain,revision,plan_version},direction:null|{goal,rules,rubric,non_goals,deadline},my_tasks:[],sources:[],model:{configured,requested_model}}`。

角色名称理资料/想方向/排下一步。任务来自本人已确认任务。sources 只列本人个人资料及当前团队共享资料中成功解析的材料，最多100条：`{id,name,scope:"personal"|"team",version,nature}`。上下文仅列来源目录；模型只读本轮选中的 source_ids。可增加截断说明。

## 会话与生成

- `GET /sessions?team_id=…` → `{sessions:[Session]}`，只返回本人该范围，最近优先。
- `POST /sessions` `{request_id,title,team_id:null}` → `{session:Session}`。创建不删旧历史，不调模型。
- `GET /sessions/{id}` → `{session:Session,messages:[Message],requests:[Request]}`，消息稳定排序，重核会话团队权限。
- `POST /sessions/{id}/turns` `{request_id,text,role_id,source_ids:[]}` → `{request:Request,message:Message|null}`。text 1–8000 字符，来源去重后最多10项。同步等待模型，等待时可轮询恢复。
- `GET /requests/{id}` → `{request:Request,message:Message|null}`，只允许本人且仍有团队权限，无生成副作用。

模型调用前持久化 user 消息、请求和正文指纹。同 session+request_id 同正文返回已存状态，不再调用；异正文409。同会话有 pending/running 时新请求409 `turn_in_progress`。超时/结果不确定标 unknown，同 ID 永不重放；新 ID 表示用户确认的新尝试。

保存来源版本/上下文指纹，返回前重检身份、成员、来源授权与版本；已失效时不得把过期响应当可用成功。实际响应模型未知填 null，不能用配置名称冒充实际名称。生产 runner 复用 planner.team_model_config/check_model_base，使用工作台专用提示，不能调用统筹 SYSTEM，无配置不回 fixture。

## 显式共享

`POST /sessions/{id}/share` `{request_id,message_id,team_id,summary,selected:true}` → `{note_id,report_id,duplicate,analysis_triggered:false,notice}`。

message_id 必须是本人成功 assistant 消息，服务端寻找同轮 user 文本及实际模型名；summary 1–3500 字符为用户编辑摘要。团队会话只能共享本团队，个人会话可显式选择本人已加入团队。用核心 save_report archive=True 归档，tool 标“松伴项目工作台”，capture_only=true。稳定 event_id 保证重复请求同 note_id，异正文409；禁止自动 review、改方向或改计划。

## 动作

assistant.actions 是下列对象，未知动作/字段舍弃；模型不执行动作：

- `{type:"prepare_direction",label,fields:{goal?,rules?,rubric?,non_goals?,deadline?}}`：原表单预填并核对，不立即保存；deadline 只允许有时区 ISO。
- `{type:"share_turn",label}`：本条回复共享预览。
- `{type:"request_team_review",label}`：仅队长，引导先共享再进入原统筹区域，由原按钮发起。
- `{type:"open_page",label,page}`：page 仅 direction/materials/library/team/members/tools/delivery/review/tasks。

## 前端挂载

产物 `/static/workbench/workbench.js`（IIFE）与 `workbench.css`，全局 `window.SongbanWorkbench`：

```ts
mount(host: HTMLElement, options: {
  token:string; identityKey:string; teamId:string|null;
  onNavigate(page:string):void;
  onPrepareDirection(fields:Record<string,string>):void;
  onShared():void; onUnauthorized():void;
}): {unmount():void}
```

组件以 token 请求同源 API，不记录凭证。identityKey 使用稳定的当前用户 ID；壳的 epoch 检查与组件卸载负责丢弃旧身份回包，避免把易变 epoch 放入草稿存储键而导致刷新丢失。卸载中止前端等待，不删服务端请求。新登录/换团队由壳卸载重挂；核心5秒刷新不能销毁输入。历史/草稿按身份和会话区分，退出登录清理工作台临时缓存。纯文本渲染，禁用 dangerouslySetInnerHTML。请求恢复不得自动提交原 POST。

根会话将原 overview 保留为 `#/tasks` 的实践内次级任务页，work/collaboration 指向工作台。onPrepareDirection 根会话预填原表单，onShared 更新核心状态但不重挂聊天。

## 后端注册

后端提供 `app.workbench.register_workbench(api,db,problem,now,uid,digest,core,runner=None)`。根会话修改 main.py 的 `create_app(...,workbench_model_runner=None)` 并传入 core 端口字典：

- `person(con,authorization)` → 原本人字典。
- `access(con,sid,authorization,captain=False,connector=False)` → (actor,squad)。
- `snapshot(con,squad,actor)` → 原团队快照。
- `save_report(sid,body,authorization,archive=True)` → 核心归档结果，调用时不持有 SQLite 写事务。

允许只读查询 materials_spaces/materials_sources，严格按 owner/team/status 过滤，不复制上传流程。新表 workbench_ 前缀。runner(context) → `{text,actions:[],requested_model,actual_model,mode}`，context 仅合法 team/direction/my_tasks、选中 sources（含 segments/版本）、本人历史与 role，无凭证。测试 fixture 显式标注 mode。所有路由应进入 app.openapi()，接口测试验证实际响应。
