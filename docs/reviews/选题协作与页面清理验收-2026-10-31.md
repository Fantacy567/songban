# 选题协作与页面清理验收

日期：2026-10-31（北京时间）。分支：`feat/material-intake`。

## 交付结果

新小队在统一前台的“方向”页开启讨论窗口，成员连接个人 Agent 后共享本人发言与 AI 可见回复。页面按选题、成员展示实际收到的回合及确认人数，例如 3/5、4/5。新上传撤回作者本人的确认；队长与连接器不能代替其他成员确认。

全员确认后生成一次团队评估，逐项说明团队能力、赛道符合性、特殊优势、评分依据及实现可行性，并列出优势、问题、待验证事项与来源。排名完成后每人每轮一票，全员投完公布票数；最高票并列时只对并列项重投。队长只能确认唯一最高票方案。

确认方向后，任务生成使用获选方案的讨论和风险说明；发布的任务进入待领取列表，建议负责人不自动成为实际负责人。领取记录沿用现有任务版本、进展报告和同伴检查接口，不另建任务状态系统。

截图要求删除的“理清楚，再向前一步”、模拟整理标题、测试替身与版本标题行、变更统计卡片和“演示资料要点”区块已从资料结果页面移除。原件和历史数据库未批量删除，正常材料条目仍可核对与共享；过期结果、部分读取等实际状态仍有提示。

## 本轮发现并修复的问题

1. **新小队任务入口被模拟页面遮住。** 原任务进度页在没有正式任务时默认进入模拟模式，隐藏了真实统筹操作。现在有真实小队就默认显示真实数据，模拟模式仍可主动切换。
2. **重新开放讨论可能复用旧票据。** 重开后清空确认和本轮评估，新排名采用新的投票轮号，历史票据保留但不计入新一轮。
3. **旧模型请求可能晚到。** 每次请求绑定独立尝试编号；重新开放、开始新尝试或超过结果有效期后，旧结果不能把页面推进到投票。
4. **只用选题标题生成任务会丢掉方案细节。** 任务上下文现包含获选讨论、评估风险与来源；截断摘录明确标记。
5. **工作台和资料草稿仍指向旧方向表单。** 新小队的赛事要求和评分依据转入讨论设置，主方向仍需经过成员讨论与投票。
6. **领取后工具可能仍按 AI 建议负责人校验。** 任务快照、本人任务读取及报告授权统一读取实际领取记录；重复领取幂等，其他成员不能抢占已领取任务。

## 尚未实测的边界

- **Codex / Cursor / WorkBuddy 的真实客户端界面。** 当前交付复用 Codex 原生插件安装器，以及 Cursor、WorkBuddy 项目 MCP 安装器。原生注册与工具发现测试通过，不代表每款客户端的聊天加号都已出现插件。Cursor、WorkBuddy 页面明确显示项目 MCP 方式；没有统一承诺原生加号入口。
- **宿主自动逐回合捕获。** 当前通过显式选用插件或授权当前对话，让 Agent 调用 `songban_share_topic_turn`。没有跨工具统一消息 hook，不能保证 Agent 不调用工具时仍自动捕获；未选择的对话不会扫描上传。
- **真实模型排名质量与额度。** 流程和模型协议经过测试，未调用付费模型，也未验证真实模型的排名质量。正式环境缺少模型配置会进入可见失败状态，讨论保留；超时结果未知，不自动重复请求。
- **远程网页安装。** 网页的一键配置仅适用于用户电脑上的本机松伴服务。远程访问不能直接写访问者电脑；页面提供明确说明和通用插件入口。
- **已有正式任务的旧团队。** 保留原流程兼容，不清空旧任务强行重开选题；新小队及已开启选题轮的团队使用新流程。
