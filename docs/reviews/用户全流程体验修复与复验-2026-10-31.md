## 后续：Windows CI 命令启动兼容修复

推送后，[GitHub Windows 测试任务](https://github.com/Fantacy567/songban/actions/runs/41175503862/job/124462094496)报告 248 项中的一项错误：真实插件注册完成后，独立宿主加载检查抛出 FileNotFoundError / WinError 2。

原因是 Windows runner 通过 npm 安装 codex.cmd，而宿主检查直接将裸命令 codex 交给 CreateProcess；该方式不会按 PATHEXT 查找 .cmd。安装流程已经使用完整路径，故注册能成功。本机已有 codex.exe，之前的本地全量没有覆盖这个环境差异。

修复：宿主检查先通过 shutil.which 解析命令，再以参数数组启动；明确传入的路径仍然可用。未关闭检查或跳过原有真实插件加载测试。

新增 Windows 回归测试隔离 PATH，只提供位于含空格目录中的 codex.cmd，启动真实子进程并完成协议握手；这里的宿主回复是明确的测试替身。该用例修复前稳定复现同样错误，修复后通过。插件专项 6/6、本机 Windows 全量 249/249 通过。[修复后全量日志](evidence-user-journey-fixes-2026-10-31/windows-ci-fix-local-tests.txt)。新增用例仅适用于 Windows，原有真实插件加载测试继续在两个 CI 系统运行。云端最终状态以 PR #9 最新提交检查为准。
