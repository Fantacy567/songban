# INTERVIEW-03 · 注册后进入动态访谈网页 · 待 Codex 验收

**真实浏览器实点没有做，这一项保留待验证。** 本机原生浏览器（native pipe 和 browser host）都不可用，本次没有启动浏览器，也没有用其他 UI 控制方式绕过。下面的前端结论都来自无浏览器的逻辑检查：用 Node `vm` 加载真实的 `core.js` 和 `interview.js`，配一个很小的假 DOM 和可控的假 `fetch`。它覆盖不到排版、真实点击、焦点外观、移动端尺寸和 CSS 效果。

## 操作方式（用户视角）

1. **注册**：仍然填写手机号、密码、再输入一次密码、短信验证码和名字。不再要求填写“你想承担什么工作”和“目前做得到的事”，改为一行说明“不用现在填写画像。注册后可以通过一段对话访谈整理，也可以先跳过。”前端会在请求里加上 `onboarding:true`。
2. **访谈介绍**：新注册成功后直接进入介绍页。
   - 页面上写着：“围绕你想做的事聊聊，最多30问，可提前结束；不是性格或天赋测验；完整对话默认仅本人可见。”
   - 年龄段（不透露、13岁以下、13–18岁、19–25岁、26岁及以上）和目前阶段（不透露、小学、中学、大学、就业探索、在职、其他）都默认“不透露”，并说明它们只用来调整说法和例子，不用来判断能力。
   - 只有点“开始访谈”才会调用 `start`；注册成功的那一刻不会调用模型。
   - 也可以点“先跳过，去团队”，进入原来的团队流程。
3. **个人入口**：左侧导航新增“个人访谈”。老用户、没有团队的用户都能从这里开始、继续或查看。
4. **访谈页**：
   - 显示已有对话和当前问题，以及“第 n / 30 问”，并提示“不确定可以写‘不知道’或‘跳过’”。
   - 提交期间按钮和输入框都不可用，不会重复提交。
   - “提前结束，生成画像草稿”要点两次，第二次是“确定结束”。如果输入框里还有没提交的内容，会提示它不会被发送。
   - 随时可以“回到团队”。
5. **草稿页**（`pending_confirmation`）：
   - 用中文字段名显示：兴趣、想做成的事、已有经历、可能的长处、可以尝试的角色、需要的帮助、可投入时间、下一步可以练习。
   - 每条标注“本人自述”或“模型推测，待你核对”，并写明“依据：你的第 k 个回答「…」”。
   - 还会列出前后说法不一致的地方、还不了解的方面，以及“这次没有聊到”的字段。
   - 页面上写着“仅供本次协作参考，尚未证明实际能力”，可以展开查看完整对话。
   - 只有点“确认这份画像”才会发出 `confirm`。点“暂不确认，保留草稿”会回到团队页，草稿不清空，下次从“个人访谈”进入还能看到。
6. **已确认页**：显示“已确认的个人画像”和确认时间，只有“回到团队”按钮，不会再调用模型。本项没有做修改草稿或重新访谈，页面上也不提供这样的入口。

### 一次回答的前端规则

- **请求编号**：`request_id` 由当前版本、当前问题 ID 和去掉首尾空白后的回答文字共同决定。三者都没变就沿用同一个编号重试；改了回答、或者换到新问题，就生成新编号（`iv-` 加 24 位随机十六进制）。
- **模型失败（502、503、504）**：保留输入框内容，不改变页面上的访谈状态。错误提示后面会加一句“再点一次会重发同一次请求，不会重复计数”。
- **409 冲突**（例如 `version_conflict`、`stale_question`、`interview_closed`）：自动重新读取一次状态，并提示“你的回答没有提交给新问题，仍留在输入框，确认后再提交”。不会自动重发；用户再点提交时，会用新问题的 ID 和新的请求编号。
- **409 `interview_busy`**：只提示稍后再试，不重新读取，请求编号保持不变。
- **输入检查**：回答为空或超过 1000 字，在前端直接显示提示，不发请求；字数按字符计算，与后端一致。
- **过期响应**：每个请求都记下发出时的登录令牌、页面代次，以及当时是否在访谈页。退出登录、换账号、离开访谈页、重新进入访谈页之后，旧请求的响应一律丢弃，不会画到新账号或其他页面上。
- **团队 5 秒刷新**：刷新逻辑只会重画团队现场和资料库两页，所以不会重画访谈页、不会切走页面、不会移动焦点。切换团队会让访谈页重画，但输入框里的内容保留在内存里，重画后还在。

## 修订 R1：访谈的旧响应覆盖“创建团队”页面

**问题（监理复现）**：用户在访谈页提交回答，回答还没返回时，在顶部团队选择里选“＋ 创建或加入团队”。原有代码只把内容区换成创建团队页，`state.page` 仍然是 `interview`，`iv.gen` 也没有变。旧回答返回后，原来的判断仍然认为它有效，于是 `ivDraw()` 把创建团队页又覆盖成了访谈页。

**修复**：只改了 `static/interview.js`（缓存版本 `-2`），`core.js` 和团队流程都没动。

- `ivDraw()` 把整个访谈视图包在 `<div id="iv-view">` 里。
- 判断拆成两层：
  - `ivMine(gen, token)`：代次、所属账号、当前令牌都一致，才算这个人这次访谈的响应。
  - `ivLive(gen, token)`：在 `ivMine` 的基础上，还要求当前页是访谈页，并且 `#iv-view` 确实还显示在页面上。
- 回答、提前结束、确认的请求：
  - 成功时，只要 `ivMine` 成立，就把服务端返回的新状态记在内存里（已被接受的回答也会从输入框清掉）；只有 `ivLive` 成立时才重画页面、显示提示。
  - 失败时，`ivLive` 不成立就只结束“提交中”状态，不显示错误，也不在后台重新读取。
  - 打开访谈页时的读取，只有 `ivLive` 成立才会采用。
- 没有改动 `state.page` 的值。原因是：如果离开时把页面改成 `overview`，团队 5 秒刷新就会把团队现场画到创建团队页上面，等于引入新的覆盖问题。

**效果**：

- 停在创建团队页时，晚到的成功、409、读取都不会重画页面，也不会再发请求。
- 已保存的进度留在内存里，还没提交的回答留在输入框里。
- 回到“个人访谈”时，会重新读取服务端最新状态并显示。

**验证**：

- 监理的复现脚本 `interview_nav_repro.cjs` 以原样复制到本仓库运行（运行后已删除），结果从 `create_team_after:false` 变为 `{"create_team_before":true,"create_team_after":true,"page":"interview","bug_old_reply_overwrites_new_team_page":false}`。
- `scripts/interview_ui_check.cjs` 新增场景组 `team_new_page`，用可控的假请求驱动真实代码：
  - 回答提交中切到创建团队页：晚到的成功不覆盖页面，也不再发请求；内存里记下了版本 2，输入框已清空。回到访谈页时重新读取，显示第 2 问，输入框是空的。
  - 再次提交后切走：晚到的 409 不覆盖页面，不重新读取，也不重发；还没提交的“想做闯关”保留在内存里。
  - 进入访谈页后立刻切走：晚到的读取不覆盖创建团队页。
  - 回到访谈页：显示最新的第 3 问，未提交的文字还在输入框里，没有任何回答被自动发给新问题。
- 全部 14 组场景通过，退出码 0；CORE-02 渲染与过期响应检查 `executable_tasks_render_check.cjs` 仍然通过。
- 反向改坏：
  - 新增 3 处，全部被抓到：去掉 `#iv-view` 检查、成功时改回只认 `ivLive`（进度不再保存）、失败时去掉 `ivLive` 判断（会在后台重新读取）。
  - 重跑原来 `interview.js` 里的反向改坏，共 10 处，抓到 9 处。没抓到的是“去掉 `state.page==='interview'` 判断”：它现在完全被更严格的 `#iv-view` 检查覆盖，因为每条改变页面的路径都会同时替换内容区。保留它只是作为第二道防线，并没有单独的测试能证明它有用。

## 限制

- 本项不提供修改草稿、重新访谈、删除或重置；确认之后也不会写入 `people.profile` 和 `skills`，也不会发布到团队。
- 微信扫码注册的分支没有改，仍然要求填写画像。
- 页面状态只在内存里：用户刷新或重新登录后，从服务端读取进度和草稿；输入框里还没提交的文字会丢失，这是不写本地存储的代价。
- 请求编号只记得最近一次操作：用户在两个回答之间来回切换，每次都会生成新编号。这种情况下后端靠版本检查拒绝重复写入，不会多计数。
- 回答字数按字符计算。JavaScript 的 `trim()` 和 Python 的 `strip()` 对少数特殊空白字符的处理不同，所以极少数输入在前后端被算作不同的长度，最终以后端结果为准。
