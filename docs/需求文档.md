# 赛内协作助手 · 首版需求

版本：0.2；日期：2026-10-26；状态：按此范围实现与验收。产品名称暂定。

## 1. 要解决的问题

缺少参赛经验的小队，在有限时间内容易不清楚项目先做什么、谁负责、交付到什么程度。首版把赛事资料、已确认共识、任务与验收放在同一个工作区，减少重复整理与同步。

目标用户是 2—8 人的黑客松小队。队长确认目标与任务，成员执行，另一位成员验收成果。成员能力与工时是本人填写的信息；系统不声称能客观评价人员能力或保证最优分工。

## 2. 首版业务范围

1. 创建项目，填写赛事截止时间、成员角色、能力与可用工时。
2. 粘贴赛事规则和经授权的讨论记录，保留原文及来源类型。
3. 生成待确认方案：目标、共识、待确认问题、风险和带原文引用的任务建议。
4. 队长可修改方案，确认后一次性生成正式任务。估时必须在成员工时预算内，任务依赖不可成环，引用必须来自本项目原文。
5. 成员开始或阻塞自己的任务；依赖任务未通过验收时不可开始。
6. 成员提交成果说明，由其他成员通过或退回。提交不等于完成；队长也不能验收自己的成果。
7. 共享任务与操作记录；刷新可看到其他成员的最新更改；旧版本提交返回 409，防止覆盖。
8. 查看提交核对清单与基于真实任务、退回、阻塞记录的复盘，导出 Markdown。

## 3. 模型边界

- `local_rules` 是本地规则演练：根据显式“目标：”“决定：”“待确认：”等行和角色模板提出建议，非大模型理解，不对外发送资料。页面和接口始终说明来源。
- `model` 才调用所选服务的 OpenAI 兼容 Chat Completions 接口。内置密钥从服务端环境读取；队长自带密钥在密码框填写后仅交给服务端暂存。密钥不回显、不写入浏览器存储或 Git。用户选择前提示本项目资料将发送给所选模型服务。
- 模型只生成建议。服务端校验结构、成员、引用、依赖与工时；不执行模型输出的代码，不接受模型返回的数据库操作。
- 模型配置缺失、超时、拒绝或格式错误时返回清楚的错误，保留已录入资料；不会静默替换成规则结果并标成 AI。
- 2026-10-26 实测：当前运行环境提供 DeepSeek 凭据，官方模型列表成功返回 DeepSeek-V4-Pro / deepseek-v4-pro；生成被上游以 HTTP 402（余额不足）拒绝。已实现清楚的余额不足提示，不自动重试。真实草案生成与建议质量尚未通过，不能将协议模拟成功写成真实模型成功。

### 3.1 用户新增要求：默认模型与自带密钥

默认预设 DeepSeek-V4-Pro，完整调用 ID 为 `deepseek-v4-pro`，地址 `https://api.deepseek.com`。服务端配置 `DEEPSEEK_API_KEY` 后可用；没有密钥不能宣称已内置可调用额度。

队长可输入自己所选服务的 API 根地址和 key，服务端请求该服务的 `/models` 列表，返回展示名称与完整 ID，由队长选择。一个 key 可对应多个模型，无法由密钥字符串本身准确判断名称。未返回展示名称时使用完整 ID，不自行猜测。列表成功并不保证模型支持 JSON 模式或实际生成成功。

自带密钥仅暂存服务进程内存；不回显、不写入数据库、浏览器本地存储或 Git。服务重启后要重新连接；切回内置会清除该项目暂存配置。读取列表的票据有效 10 分钟、绑定项目与队长权限。外部地址只允许显式可信的 HTTPS 服务，禁止任意内网请求或重定向转发密钥。

每份模型草案记录请求的完整模型 ID、展示名称，以及上游在响应中提供的模型 ID（如果有）。这些都是服务商声明的标识，不等于能独立核验底层权重版本。

## 4. 身份与协作

创建后每名成员获得独立随机访问口令，数据库只保存哈希。口令相当于该成员的工作区钥匙；无真实账号体系。所有项目数据接口都校验口令归属，队长权限由后端判定，不接受前端提交职位冒充。

队长可重发普通成员入口，旧入口立即失效。禁止通过接口读取其他人的原始口令。默认仅监听本机；邀请链接的本机地址不能供队友跨设备访问。两浏览器验证同一服务的协作，跨设备需要队友可达的服务地址与显式 CORS 配置。

## 5. 状态与约束

项目阶段：`preparing`（资料或方案）→ `executing`（方案已确认）→ `ready`（所有必须任务通过验收，仍允许完成可选任务）。

任务状态：`todo` → `in_progress` → `review` → `accepted`；`in_progress` 可变 `blocked`，解除阻塞后回 `in_progress`；`review` 退回后回 `in_progress`。`accepted` 首版不支持撤销。所有状态变更都有操作记录。

正式方案首版仅确认一次。确认前可补充资料、重新生成并修改草案；补充资料会使旧草案失效。确认后原始资料冻结，新增范围和整套重排留待下一版；执行中可记录阻塞并通过退回修正交付。界面必须明确此限制。

时间统一存为 UTC，输入必须带时区；页面按浏览器时区展示。项目截止时间需晚于创建时间。任务截止不得晚于赛事截止；不因过期而抹掉已有记录。

## 6. 可验收标准

- F01：空白姓名、重复成员名、无时区时间、过期赛事、非正工时、超长正文被拒绝；同名项目可存在，以 UUID 区分。
- F02：规则和讨论至少各一份才能生成方案；缺失配置的真实模型请求返回 503，资料仍在。
- F03：草案可修改、保留来源；伪造引用、跨项目成员、未知依赖、依赖成环被拒绝。
- F04：仅队长确认；超工时、草案过期、重复确认被拒绝。正式任务不能重复生成。
- F05：仅负责人改变执行状态；依赖未验收不能开始，阻塞需原因；提供两独立会话观察共享数据。
- F06：成果需非空说明；负责人不能自验，其他成员能退回（需原因）和通过；验收记录不丢失。
- F07：旧版本写入返回 409；另一项目口令不能读写本项目；无凭据返回 401。
- F08：必须任务全部通过后显示可交付；提交核对与复盘使用真实任务统计；Markdown 可导出。
- F09：重启后项目、方案、任务、审计仍在；模型失败、非法 JSON、异常响应不泄露密钥或内部异常。
- F10：完整浏览器流程与本流程图一致；运行中无未处理 JavaScript 错误，窄屏关键控件可操作。
- F11：默认完整显示 DeepSeek-V4-Pro / deepseek-v4-pro 与配置状态；自带密钥读取模型列表并选择完整 ID，未知名称、过期票据、越权和不可信 URL 被拒绝；密钥不落盘、不回显；重启后自带配置清除而项目数据保留。协议测试用模拟服务，真实连接需有效 key。

## 7. 本轮不包含

找比赛、找队友、实时录音、文件上传、代码托管、GitHub 自动验收、主办方系统、云端账号、WebSocket 实时同步、自动改代码、已验证的节时百分比。技术栈为 Python/FastAPI、SQLite、原生 HTML/CSS/JavaScript；附操作页面用于联调和验收，胡可通过同一接口另做正式前端。

## 8. 验证方法

先做真实数据库与 HTTP 请求测试，再使用浏览器按流程从创建走到复盘，使用第二会话完成跨成员验收，同时验证拒绝、自验、过期草案、并发冲突与重启持久化。模拟模型只用于协议测试，真实模型的输出质量、延迟与费用需配置后另测。每项结果在 `docs/验收报告.md` 中记录，不把未执行项写成通过。
