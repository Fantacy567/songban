# 松伴新版：功能清单与使用链路检查

检查日期：2026-10-28。只包含当前新版松伴首页与 `/api/studio`。

## 一、先说结论

当前已具备一套以手动录入、手动确认、手动推进为主的团队协作原型：可以保存成员与赛事、组队、聊天、记录职责、维护任务树、填进度、共享文字成果。

**从“大家讨论”到“分工变成任务”，再到“成果验收、赛后复盘”，还没有完整接上。** 智能分工、自动验收、完整培训计划、赛后文章、真实代码托管，目前不能作为已完成能力宣传。

优先处理：运行服务加载不完整、任务子分支隐藏、赛事缺时间时出错、文档内容不对应项目、赛后入口过深与成长记录不一致。

## 四、已确认的缺陷清单

P1：优先修，会让核心流程失败、内容错配或重要记录不可见。P2：随后修，恢复成本、提示或判断容易误导。

### B01 · P1 · 当前页面与运行后端没对齐

**复现：**当前 8886 的接口定义缺少三个新版路径，也缺少任务删除方法。使用不存在的测试 ID、无登录口令探测，不修改真实数据。

| 新页面动作 | 当前 8886 实际响应 |
| --- | --- |
| 同步赛事截止时间 `POST .../contests/{id}/sync` | 404 |
| 邀请好友 `POST .../squads/{id}/invite-friend` | 404 |
| 刷新团队综述 `POST .../squads/{id}/overview` | 404 |
| 删除任务分支 `DELETE .../squads/{id}/tasks/{id}` | 405 |

同一磁盘源码的隔离服务已注册这些路径。当前正式进程没有自动重载。

**影响：**页面有按钮，点击却找不到对应功能；用户容易误以为资料、权限或操作方式有错。

**建议：**先妥善结束当前处理中的请求，再重启这个项目的后端加载当前代码；启动后核对接口版本和关键路径。在开发页显示构建标识，让前后端版本可核对。

证据：`audit-2026-10-28/running-route-mismatch.json`。

### B02 · P1 · 父任务换负责人，子分支从团队图消失

**步骤：**队长名下创建“实现失物登记 API” → 其下创建“校验登记信息并返回错误提示” → 到队长规划，把父任务改给前端 → 回任务图。

**实际：**子分支不再显示在任何成员下面，但“个人进度”里仍能看到它，并未删除。

**原因：**任务图先按负责人过滤，再递归画父子任务；父子归属不同后，子任务既不是根，也不能挂到另一人的父任务下。

**建议：**明确跨成员父子任务的显示规则；改负责人时可询问是否连子分支一起移动，或把跨成员子任务显示为带父任务引用的节点。

证据：`06_child_hidden_after_reassign.jpg`、`07_hidden_child_still_in_progress.jpg`；位置：`static/studio.js` 的 `viewBoard`，`app/studio.py` 的 `adjust_task`。

### B03 · P1 · 资料未抽出截止时间，后续无法补救

**受控复现：**只模拟资料提取层返回“没有找到截止时间”，后续请求仍执行真实业务逻辑，不调用外部模型。

**实际：**确认赛事返回 200，并允许建队；提交选题返回 500。即使创建任务时提供有效日期，也因对比空赛事时间返回 422 `invalid_due_date`。赛事卡页面没有手工补录或纠正时间的表单。

**建议：**赛事卡保存前标出缺少的关键字段，允许补录并说明来源；时间未确认时给明确业务提示，禁止进入会报 500 的计算。显式任务日期应有一致的校验规则。

证据：`missing-deadline-results.json`。位置：`confirm_contest`、`add_idea`、`publish_task`。

### B04 · P1 · 生成文档没有对应本队项目

**步骤：**把题目确认为“校园失物招领” → 点击“需求文档简版” → 打开成果架。

**实际：**得到的主路径是“选比赛、组队、选题、安装同一技能、发布任务”，没有失物登记、查询或匹配。

**原因：**`static/studio.js` 的 `BRIEFS` 是固定字符串，没有读取本队题目、职责或已发布任务。

**建议：**先按真实项目字段填充可编辑草稿，并展示引用依据；未实现前标为“通用参考模板”，避免以“本项目需求文档”交付。

证据：`05_generated_document_wrong_topic.jpg`。

### B05 · P1 · 成长记录会过期，结束比赛入口也过深

**界面体验：**个人空间只显示“结束一场比赛后，这里按真实完成的任务记一句”，没有直达操作。继续追查后，实际找到了“个人 → 查看全部比赛卡 → ← 我的系统 → 成长系统 → 结束这场并写入成长”的路径。功能存在，但用户要借道赛事卡的返回按钮，才会发现从未主动进入过的上级页面。

**浏览器与真实接口反例：**任务未完成也能直接结束；结束后仍能把任务改成 100%；再次结束直接返回已记录，个人成长保持“还没有把进度标到完成”，没有新完成的任务。浏览器也走通了这一反例。

**建议：**提供赛后入口；结束前列出完成、未完成、未提交事项并确认；明确结束后是冻结记录还是允许重新生成带版本的总结。成长记录不能与任务数据无提示地分开变化。

证据：`10_growth_reached_via_card_backlink.jpg`、`11_growth_stale_after_task_completed.jpg`、`api-probe-results.json`。

### B06 · P2 · 会话失效后仍停在已登录界面

**步骤：**测试账号在另一会话重新登录，使原 token 失效 → 原页面点击团队。

**实际：**显示“登录已失效”，但继续画旧成员和空团队卡，没有自动进入登录；手动整页刷新后才回登录页。

**建议：**统一处理 401，清理旧视图并转到登录；保留可恢复的草稿和返回位置。位置：`api`、`go` 与页面提交处理。

### B07 · P1 · 提交清单漏掉单独要求的视频

**输入：**明确要求演示作品、40 秒演示视频、PPT、项目说明、分工说明和仓库链接。

**实际：**清单只有 PPT、分工说明、仓库、可演示作品、项目说明；视频没有单列，也跟着漏进统一技能文件。

**原因：**关键词把“演示视频”归到“可演示作品”，并未保留两项独立交付物。

**建议：**每条提交要求保留原文、名称和限制，例如“视频，40 秒”；支持人工确认和补项，不能只按类别合并。

证据：`api-probe-results.json` 及组队、成果架页面。

### B08 · P2 · 智能体失败提示能当成资料上传

**步骤：**未接个人模型时提问 → 得到“还没填写 API 密钥” → 点击“上传到团队资料库”。

**实际：**成功保存该错误提示，随后可被计入团队资料条数。这没有生成有效回答。

**建议：**返回结构区分成功回答、待配置、失败；只有成功内容才显示上传按钮。上传前给用户预览并可编辑。

证据：`08_error_reply_saved_as_material.jpg`；位置：`askAgent`、`uploadAgent` 与 `coach`。

### B09 · P2 · 已保存的职位没有回填

**步骤：**保存“后端开发”和具体职责。

**实际：**成员展示正确，编辑表单却立即变回“产品”，职责框为空。再次修改时容易无意覆盖。

**建议：**用当前成员已保存的角色、职责初始化表单；有未保存内容时避免切页丢失。位置：`viewTeam`。

## 五、功能割裂：不等于接口报错，但离产品目标还有差距

### G01 · 讨论和任务还需要重复搬运

群里发“决定：先做登记接口，再做页面”，只保存为消息；团队资料库和任务数都不变。队长确认两人的职责，也只得到两条职责草案，任务仍为 0。随后还要去任务图逐条填写。

建议先做一条连贯路径：选中本次讨论 → 生成带依据的候选任务 → 队长修改确认 → 写入任务图。个人私聊继续保持自愿上传，不自动读取。

### G02 · 引导说下一步，但没有把人带过去

建队自动打开群聊是顺畅的；之后的职位/邀请码却要走“赛事 → 返回比赛系统 → 比赛组队”。确认分工成功后只给“回到首页”，落到消息页。选题、同一技能、需求与流程藏在赛事二级入口。个人成长的操作要先借道比赛卡返回“我的系统”。

建议团队页直接放“邀请/职责/确认”入口，顶部给下一步按钮；保留页面专属状态，不让用户为了更新名单来回切页。

### G03 · 协作数据没有主动更新，任务图不显示进度

队友已经加入并保存职责，队长当前页仍只显示一人、确认按钮仍灰；离开再进入才更新。个人把进度填为 50%，主任务图只有标题，没有百分比、截止或阻塞状态。

建议增加不打断输入的刷新提示/同步；任务节点至少显示负责人、进度、截止、是否等别人。当前百分比只是自报，不能称已验收。

### G04 · 表决收齐了，缺少采纳操作

全员同意改题目后记录为 `recorded`，题目不变；队长通过确认题目接口再改仍返回 `topic_locked`。表决不自动改项目是既定规则，问题在于没有后续的队长采纳入口。

建议让队长查看影响清单、明确采纳或搁置，保留旧决定和变更记录；不要自动推翻项目。

### G05 · 模型设置不代表接入验证成功

测试填写明确的假 key 和不存在的模型名，保存返回 200，`model_ready=true`。模型名完全由人填写；没有读取服务列表来核对。密钥留空再保存会保留旧值，没有清除密钥的操作。当前个人模型配置存在服务器数据库中，不能描述成仅本次内存有效。

建议把“配置已保存”和“连接测试通过”分开；提供模型列表、一次明确触发的短连接测试和删除配置。不要根据 key 字符串猜模型，也不要把手填名字当成已核验完整版本。

### G06 · 结果验证和赛后训练尚未形成

成果架保存的是文字/链接，任务完成由本人填百分比，没有把成果绑定到验收标准，也没有另一成员复核。赛后只是拼接角色和完成任务，没有失败原因分析、复盘文章、分级训练内容或下次检验。
